# Util Maker

Desktop-приложение для Windows 11 x64: резидентный хост в трее, глобальные
сочетания клавиш и независимо устанавливаемые микроприложения-плагины. Первая
поставка — «Скриншоты» и «Переводчик»; прототип содержит контрольный модуль,
через который проверяется вся цепочка вызова.

## Архитектура

```text
apps/desktop          нативный хост Tauri 2: трей, окна, команды, настройки
crates/core           переносимое ядро: реестр действий, IPC, шорткеи, журнал
crates/sdk            контракт плагина: манифест, JSON-RPC 2.0, цикл stdio
crates/platform       платформенные адаптеры Win32 и автозапуск
crates/packages       проверка подписанного пакета .umpkg до установки
crates/fixture-module тестовый модуль с управляемыми сбоями (не в поставке)
plugins/control       контрольный плагин: отдельный процесс, действие ping
plugins/screenshot    плагин «Скриншоты»: сведение кадра и аннотаций
plugins/translator    плагин «Переводчик»: состояния выбора текста
  providers           HTTP-адаптеры Яндекса и Google внутри плагина
docker/               Linux-окружение разработки и кросс-сборка Windows
installer/            NSIS-установщик
docs/                 ТЗ, блоки, задачи, формат пакета и проверка на Windows
```

### Границы ответственности

- **Хост** владеет треем, глобальными регистрациями, окнами настроек и
  жизненным циклом процессов. Он не содержит условий по ID штатных плагинов.
- **Переносимое ядро** не зависит от Tauri, Win32 и графической сессии. Здесь
  живут реестр модулей и действий, маршрутизация `moduleId + actionId`, запуск
  процесса, таймауты, отмена и реестр сочетаний.
- **SDK** фиксирует манифест и протокол. Плагин может быть написан на любом
  языке, если соблюдает JSON-RPC 2.0 через stdin/stdout.
- **Платформенный адаптер** скрывает Win32: `RegisterHotKey`, окна, фокус,
  автозапуск. Публичный контракт не содержит системных дескрипторов.
- **Плагин** — отдельный процесс и отдельный пакет. Он объявляет действия,
  сочетания и собственные настройки; ядро не знает его внутренностей.

### Плагин как единица поставки

Каждый плагин лежит целиком в своём каталоге:

```text
plugins/<plugin-id>/
  Cargo.toml       сборка процесса и/или переносимой логики
  manifest.json    контракт пакета (id, издатель, версия, hostApi, действия)
  src/             исходники
  assets/          иконка и ресурсы
  README.md        назначение, действия, сборка и проверка
```

`manifest.json` — тот же контракт, который попадёт в `.umpkg`
([формат пакета](docs/blocks/packages/package-format.md)). Плагин запускается по требованию,
получает вызов через `initialize`/`invoke`, при необходимости обращается к
возможностям хоста и завершается после действия. Падение или зависание
изолировано процессом.

### Экспорт и установка пакетов

Экспорт подготовленного каталога плагина в подписанный `.umpkg` выполняется
целью `make package-export` или командой `util-maker-package export`. Архив
проходит ту же проверку подписи, хешей, издателя, платформы и диапазона API,
что и устанавливаемый пакет. Импорт и установка из интерфейса пока не
реализованы: каталог плагина самодостаточен, поэтому их можно добавить без
пересборки хоста.

## Сборка и проверки

```sh
make dev-setup          # подготовить Linux-контейнер
make check              # версия, rustfmt, clippy, тесты
make example-package    # подписанный пример стороннего плагина в dist/
make package-export     # подписать подготовленный каталог (PACKAGE_* в параметрах)
make build-windows      # NSIS-установщик в dist/
make bump-version VERSION=0.4.2  # поднять версию продукта
make version            # версия и тип сборки
```

Тип сборки задаётся `BUILD_KIND`; версия продукта — semver в исходниках и
`make bump-version`. Установщик получает имя
`UtilMaker-Setup-<версия>-<тип>.exe`.

Требуется Docker Engine. Установщик собирается под
`x86_64-pc-windows-msvc` с cargo-xwin и NSIS; запускать его нужно на Windows 11
x64. Подробности — в [проверке прототипа](docs/blocks/platform/windows/prototype-verification.md).

Прототип 0.3.0: хост, контрольный плагин, трей, сочетание, автозапуск, журнал,
