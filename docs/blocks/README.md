# Функциональные блоки Util Maker

Первая поставка включает приложение для Windows 11 x64 и два отдельно обновляемых микроприложения. Каждый документ ниже описывает один результат, границу ответственности и способ его проверки. Общие требования и состав поставки определены в [ТЗ проекта](../ТЗ.md). Как заводить задачи по этим документам, описано в [правилах работы с задачами](../Работа%20с%20задачами.md).

| Блок | За какой результат отвечает |
| --- | --- |
| [Ядро и трей](host.md) | Действие, вызванное из трея или шорткеем, доходит до нужного процесса. Хост остаётся доступен во время операции и при сбое модуля. |
| [Windows-адаптер](windows.md) | Хост получает события и данные ОС через переносимый интерфейс. |
| [Глобальные шорткеи](hotkeys.md) | Каждое сочетание имеет одного владельца. Пользователь может передать внутреннюю привязку, системные сочетания защищены. |
| [Контракт модуля и SDK](module-sdk.md) | Разработчик может собрать пакет и подключить новые действия к существующему хосту. |
| [Установка и обновление пакетов](packages.md) | Проверенный пакет можно установить, заменить и откатить с соответствующими настройками. |
| [Интерфейс и настройки](settings.md) | Пользователь находит действие, меняет привязку и настраивает модуль с одной страницы. |
| [Скриншоты](screenshots.md) | В буфер попадает выделенная область экрана с выбранными аннотациями. |
| [Переводчик](translator.md) | Пользователь выбирает текст в другом приложении и видит перевод рядом с местом работы. |
| [Провайдеры перевода](translation-providers.md) | Активный профиль отправляет текст в Яндекс или Google и возвращает перевод либо распознаваемую ошибку. Оба адаптера поставляются внутри переводчика. |
| [Диагностика и ресурсы](diagnostics.md) | Пользователь может диагностировать сбой по локальному журналу, а разработчик — воспроизвести замеры памяти, CPU и задержки. |

## Сквозная приёмка

Номера совпадают с разделом 9 общего ТЗ. Ведущий блок задаёт ожидаемый результат. В проверке участвуют также блоки, перечисленные в правом столбце.

| № | Проверка | Ведущий блок | Участники |
| --- | --- | --- | --- |
| 01 | Чистая установка | [Пакеты](packages.md) | Ядро, интерфейс, оба штатных модуля |
| 02 | Внутренний конфликт | [Шорткеи](hotkeys.md) | Интерфейс, ядро |
| 03 | Системный и внешний конфликты | [Шорткеи](hotkeys.md) | Windows-адаптер, интерфейс |
| 04 | Глобальный вызов | [Шорткеи](hotkeys.md) | Windows-адаптер, ядро |
| 05 | Скриншоты | [Скриншоты](screenshots.md) | Windows-адаптер, ядро |
| 06 | Захват текста | [Переводчик](translator.md) | Windows-адаптер, провайдеры |
| 07 | Два реальных провайдера | [Провайдеры перевода](translation-providers.md) | Переводчик, интерфейс, хранилище секретов Windows |
| 08 | Независимость пакетов | [Пакеты](packages.md) | Ядро, SDK, шорткеи |
| 09 | Изоляция сбоя | [Ядро](host.md) | SDK, Windows-адаптер, шорткеи |
| 10 | Интерфейс и ресурсы | [Интерфейс](settings.md) | [Диагностика](diagnostics.md) отвечает за замеры |
| 11 | Контракт для нового модуля | [SDK](module-sdk.md) | Пакеты, ядро, шорткеи, интерфейс |

Первый прототип соединяет трей, регистрацию одной комбинации, запуск контрольного модуля и показ первого кадра. Уже на этом срезе измеряются простой и холодный отклик. Затем проверяются установка двух версий пакета и конфликты привязок, после них — оба штатных модуля с настройками. Для релизного кандидата проходят все 11 сценариев. Исходники, установщик, пакеты, SDK с примером и инструкцией подписи, инструкции настройки провайдеров, протокол и результаты замеров составляют общую поставку по разделу 9.
