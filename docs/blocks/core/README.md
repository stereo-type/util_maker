# Переносимое ядро

Ядро владеет реестром модулей и действий, регистрацией владельца сочетания и вызовом процесса по паре `moduleId + actionId`. Код ядра работает без Tauri, Win32 и графической сессии. Трей и окна подключаются через [desktop-хост](../desktop/README.md). Основание — разделы 2–4 и 8, приёмка 04 и 09 [общего ТЗ](../../specification.md).

## Контракт выполнения

Из меню и от [реестра шорткеев](hotkeys.md) ядро принимает одну пару `moduleId + actionId`. До открытия собственных окон оно фиксирует контекст источника через [адаптер ОС](../platform/windows/README.md). Для меню используется последнее активное внешнее окно до открытия меню. Если источник закрыт или контекст потерял актуальность, пользователь выбирает его заново.

Ядро выбирает активную версию пакета, запускает процесс, согласует API и передаёт действие по [протоколу SDK](../sdk/README.md). Обработка событий трея продолжается, пока пользователь выбирает область или провайдер отвечает на запрос. Завершение процесса, нарушение протокола или сбой запуска дают конечную ошибку конкретного вызова. При отмене зависшего вызова ядро освобождает контекст, игнорирует поздний ответ и завершает оставшийся процесс через 2 с. После завершения работы и закрытия последнего окна модуль выгружается.

Если плагин завершился из-за необработанной ошибки, ядро определяет сбой по результату IPC или завершению дочернего процесса. Оно передаёт оболочке ID модуля и действия, категорию ошибки и безопасное описание. Оболочка показывает, какой плагин завершился, и предлагает «Отключить плагин». Закрытие сообщения сохраняет текущее состояние плагина и позволяет повторить вызов. Пользователь может отключить и исправный плагин через переключатель в настройках.

## Критерии приёмки

- Одно действие из меню и с клавиатуры попадает в один handler. Вызов из меню обращается к исходному приложению. Ожидание выделения в одном модуле позволяет пользоваться треем.
- Принудительно завершить процесс во время действия, затем воспроизвести зависание и отмену. Второй модуль отвечает, первый можно вызвать повторно, после выхода дочерних процессов нет.

Правила назначения и восстановления сочетаний определены в [ТЗ по шорткеям](hotkeys.md). Состав журнала и методика проверки ресурсов описаны в [ТЗ по диагностике](diagnostics.md).
