# Диагностика, устойчивость и расход ресурсов

**Результат.** Сбой можно связать с конкретным действием по локальному журналу. Стоимость простоя и коротких действий измеряется на одной конфигурации. Основание — разделы 2, 3, 8 и 9, приёмка 09 и 10 [общего ТЗ](../../specification.md).

## Журнал и конфигурация

Структурированный журнал текущего пользователя с ротацией доступен из [общих настроек](../desktop/settings.md). Для сбоя фиксируются версия, ID модуля и действия, длительность и код ошибки. Правило распространяется также на сообщения из процессов модулей и HTTP-адаптеров. Содержимое снимков, исходный текст, переводы, буфер, ключи, заголовки авторизации и полные URL с секретами в журнал не записываются.

Хост сохраняет конфигурацию и реестр привязок с восстановлением после аварийного завершения. Для обновления пакетов согласованность версии и её настроек обеспечивает [менеджер пакетов](../packages/README.md). После перезапуска недоступность одной привязки или одного модуля не лишает пользователя остальных действий.

## Холодный отклик

Запись замера содержит `moduleId`, `actionId`, `cold` и `firstFrameMs` — время от
события вызова до первого видимого кадра. `durationMs` всего вызова, включая
облачный запрос плагина, не заменяет `firstFrameMs`. Сводка строится отдельно
по паре `moduleId + actionId` и отдельно для холодных и тёплых вызовов; для
каждой группы печатается размер выборки. Записи без первого кадра видны как
неполная выборка, а не как нулевой отклик.

## Приёмочные замеры

Это целевые бюджеты для проверки на первом прототипе. Если цель пересматривается, результат замера и новое значение фиксируются в общем ТЗ. Замеры проводить на release-сборке Windows 11 x64, машина с 4 физическими ядрами, 8 ГиБ RAM и SSD, одинаковый профиль питания. Записать модель CPU, версии Windows и WebView2, масштаб, список процессов и способ определения первого кадра. CPU и память снимать раз в секунду.

| Что измерить | Процедура и ожидаемый результат |
| --- | --- |
| Простой | Закрыть окна, выждать 60 с. Сумма Private Working Set всех процессов продукта, включая его WebView и модули, ≤ 60 МиБ. Средняя загрузка CPU за 10 мин ≤ 0,2% от суммарной мощности машины. |
| Фоновая активность | По трассировке за 10 мин проверить отсутствие периодического опроса клавиатуры, выделения и экрана, постоянного рендеринга, сетевых запросов модулей и оставшихся процессов завершённых действий. |
| Холодный отклик | На основном мониторе 1920×1080 выполнить по 50 вызовов каждого действия из остановленного процесса модуля. От события шорткея в ядре до первого видимого кадра p95 ≤ 350 мс отдельно для каждого действия. Облачный запрос измеряется отдельно. |
| Возврат ресурсов | Провести 100 циклов подтверждения или отмены и выждать 60 с. Память снова укладывается в бюджет простоя, рост относительно исходного замера ≤ 10 МиБ. После выхода хоста дочерних процессов нет. |

## Критерии приёмки

- Передать результаты по четырём строкам таблицы вместе с параметрами стенда. Для корректности захвата отдельно использовать второй монитор с отличающимся DPI.
- Провести восьмичасовую сессию с уходом в сон и пробуждением. Проверить трей и допустимые шорткеи после восстановления. После сбоя модуля доступны повторный вызов и штатный выход.
- Вызвать ошибку перевода с тестовой фразой и ключом, затем ошибку копирования скриншота. В журнале находятся соответствующие действия и причины сбоя, поиск по контрольным значениям не находит пользовательских данных или секрета.
