# Плагины-расширения микроприложений

**Результат.** Установленное микроприложение объявляет точки расширения, а
отдельные подписанные пакеты подключаются к ним как плагины. Пользователь
ставит, обновляет и удаляет такой плагин независимо от родителя, выбирает
активный плагин и настраивает его. Родитель вызывает выбранный плагин через
ядро, не получая прямого доступа к чужому процессу.

Основание — разделы 2, 4 и 8 [общего ТЗ](../../specification.md), контракт
[SDK](../sdk/README.md) и [формат пакета](../packages/package-format.md).
Первым потребителем станет [переводчик](../plugins/translator/README.md):
провайдеры Яндекса и Google поставляются отдельными плагинами-расширениями.

## Модель

| Понятие | Значение |
| --- | --- |
| Родитель | Микроприложение, которое объявляет одну или несколько точек расширения. |
| Плагин-расширение | Отдельный пакет `.umpkg`, который реализует точку расширения родителя. Может не иметь собственных действий в трее. |
| Точка расширения | Именованный контракт родителя: ID, отображаемое имя, версия контракта и правило выбора. |
| Вклад | Объявление плагина о том, какую точку какого родителя он реализует. |
| Активный плагин | Вклад, выбранный пользователем для точки с выбором одного плагина. |

В первой версии поддерживается один уровень вложенности. Пакет может быть
родителем **или** плагином-расширением, но не обоими одновременно. Плагин не
может объявлять собственные точки расширения. Циклы и цепочки глубже одного
уровня отклоняются при проверке набора пакетов.

Плагин-расширение не становится отдельным микроприложением в трее. Если он
объявляет действия, они остаются обычными действиями пакета; для провайдеров
перевода такие действия не нужны. Настройки и секреты плагина принадлежат его
собственному ID и не смешиваются с настройками родителя.

## Манифест родителя

Родитель добавляет `extensionPoints` и запрашивает возможности
`extensions.read` и `extensions.call`.

```json
{
  "id": "org.utilmaker.translator",
  "capabilities": ["selection.read", "extensions.read", "extensions.call"],
  "extensionPoints": [
    {
      "id": "translation-provider",
      "name": "Провайдер перевода",
      "contract": "util-maker.translation.provider",
      "contractVersion": "1.0.0",
      "selection": "single",
      "required": true
    }
  ]
}
```

Правила проверки:

- `manifestVersion` остаётся `1`: новые поля необязательные. Пакет с
  `extensionPoints` или `provides` требует `hostApi >=1.1.0 <2.0.0`; старый хост
  отклоняет его обновлением, а не принимает пакет, который не сможет вызвать.
- `id` — локальный идентификатор из строчных латинских букв, цифр и дефисов;
  уникален в манифесте.
- `contract` — стабильный глобальный ID контракта; `contractVersion` — точная
  semver-версия. Несовместимое изменение смысла операции требует новой major.
- `selection` в первой версии принимает только `single`: у точки один активный
  плагин. Значение `multiple` зарезервировано и отклоняется до отдельного
  расширения контракта.
- `required: true` означает, что без выбранного совместимого плагина родитель
  показывает «Нужна настройка», а вызов возвращает машинную ошибку, а не
  подставляет встроенную реализацию.
- Родитель с точками расширения обязан объявить обе возможности
  `extensions.read` и `extensions.call`.

## Манифест плагина-расширения

Плагин добавляет `provides`. Массив `actions` может быть пустым, если пакет
что-то предоставляет хотя бы одной точке.

```json
{
  "id": "org.utilmaker.translator.yandex",
  "capabilities": ["secret.read"],
  "actions": [],
  "provides": [
    {
      "moduleId": "org.utilmaker.translator",
      "pointId": "translation-provider",
      "contract": "util-maker.translation.provider",
      "interfaceVersion": ">=1.0.0 <2.0.0",
      "name": "Яндекс",
      "description": "Yandex Translate API v2"
    }
  ]
}
```

Правила проверки:

- `moduleId` и `pointId` адресуют точку расширения; `contract` обязан совпадать
  с контрактом точки, а `interfaceVersion` — допускать её `contractVersion`.
- Один пакет может предоставить не более одного вклада в одну точку. Повтор
  пары `moduleId + pointId` отклоняется.
- `name` — короткое имя для выбора; `description` необязательно.
- Пакет с `provides` не может одновременно объявлять `extensionPoints` или
  возможности `extensions.*`: вложенные вызовы и цепочки в первой версии
  запрещены.
- Точка входа и подпись проверяются так же, как у обычного пакета. Для
  extension-only пакета отсутствие действий не является ошибкой.

## Реестр и выбор

Ядро строит индекс вкладов из активных манифестов установленных пакетов.
Установленный плагин может временно не иметь родителя или совместимой точки:
его вклад остаётся неактивным, пакет не удаляется, интерфейс показывает причину
и предлагает установить нужное микроприложение.

Для точки `single` действуют правила:

1. Явный выбор пользователя хранится ядром по паре `moduleId + pointId` и
   переживает перезапуск, обновление и повторную установку плагина.
2. Если явного выбора нет и доступен ровно один включённый совместимый вклад,
   он становится активным автоматически.
3. Если доступно несколько вкладов без явного выбора, активного плагина нет:
   родитель получает `EXTENSION_NOT_SELECTED`, а интерфейс предлагает выбрать
   провайдера.
4. Если выбранный плагин отключён, удалён или стал несовместим, сохранённый ID
   не стирается. После восстановления плагина выбор снова действует; до этого
   применяются правила 2–3.
5. Отключение родителя скрывает его точки и вклады, но не удаляет дочерние
   пакеты. Удаление родителя оставляет дочерние пакеты установленными и
   показывает их как ожидающие родителя.

## Вызов расширения

Родитель не запускает чужой процесс напрямую. Во время своего активного вызова
он обращается к хосту:

```json
{"jsonrpc":"2.0","id":41,"method":"host.call",
 "params":{"callId":"call-7","capability":"extensions.read",
           "method":"extensions.list",
           "params":{"pointId":"translation-provider"}}}
```

Результат содержит активный ID и доступные вклады без запуска их процессов:

```json
{"pointId":"translation-provider",
 "selected":"org.utilmaker.translator.yandex",
 "contributions":[
   {"moduleId":"org.utilmaker.translator.yandex","name":"Яндекс","available":true},
   {"moduleId":"org.utilmaker.translator.google","name":"Google","available":true}
 ]}
```

Для вызова используется отдельная возможность `extensions.call`:

```json
{"jsonrpc":"2.0","id":42,"method":"host.call",
 "params":{"callId":"call-7","capability":"extensions.call",
           "method":"extension.invoke",
           "params":{"pointId":"translation-provider",
                     "operation":"translate",
                     "timeoutMs":10000,
                     "params":{"text":"hello","sourceLanguage":"auto","targetLanguage":"ru"}}}}
```

Ядро проверяет родителя, точку, активный вклад и совместимость, запускает
дочерний процесс со **своими** возможностями и настройками и передаёт ему
операцию контракта. Родитель не может выбрать произвольный чужой пакет в обход
выбора пользователя.

Правила выполнения:

- `operation` и схема `params` принадлежат контракту точки; ядро передаёт их
  без истолкования.
- `timeoutMs` необязателен, по умолчанию 10 000 мс. Ядро ограничивает его
  остатком времени родительского вызова и общим пределом 30 000 мс.
- Отмена родительского вызова отменяет дочерний вызов и освобождает его
  ресурсы. Поздний ответ плагина не меняет состояние нового вызова.
- Падение, таймаут или нарушение протокола плагина возвращаются родителю
  ошибкой `EXTENSION_FAILED` с ID плагина. Родитель и остальные плагины
  продолжают работать.
- Дочерний вызов получает собственный `callId`; в журнале сохраняется связь с
  родительским вызовом. Секреты и настройки родителя дочернему процессу не
  передаются.
- Плагин может пользоваться объявленными возможностями хоста, включая
  `secret.read` для собственных ссылок. Его контекст не наследует возможности
  родителя.

Новые машинные коды: `EXTENSION_NOT_FOUND` (1008),
`EXTENSION_INCOMPATIBLE` (1009), `EXTENSION_NOT_SELECTED` (1010) и
`EXTENSION_FAILED` (1011).

## Пакеты и доверие

Плагин-расширение — обычный подписанный `.umpkg`. Проверка издателя, подписи,
хешей, путей, платформы и `hostApi` не меняется. Дополнительно:

- предварительный просмотр установки показывает ID родителя, точку и контракт;
- отсутствие родителя не блокирует установку, но показывается предупреждением;
- обновление плагина не затрагивает родителя и его настройки;
- удаление плагина очищает его настройки и секреты, но не родителя;
- удаление родителя не удаляет дочерние пакеты автоматически;
- активный вызов плагина завершается по обычным правилам обновления и удаления.

## Интерфейс

На странице микроприложения-родителя появляется раздел «Плагины». Для каждой
точки видны:

- название и состояние: активный плагин, доступные варианты, «Нужна настройка»;
- выбор активного плагина для `single`;
- действия «Установить плагин», «Настроить», «Отключить» и «Удалить»;
- причина недоступности: нет родителя, несовместимая версия контракта, пакет
  отключён или отсутствует.

Форма настроек плагина строится по его собственному `settings` и использует
существующие секреты и команды формы. Установка из общего менеджера пакетов
показывает, какому микроприложению и точке принадлежит плагин.

## Критерии готовности контракта

- Манифесты родителя и плагина проходят проверку; несовместимый контракт,
  повторный вклад, цикл и `multiple` в первой версии отклоняются до запуска.
- Ядро хранит выбор, поднимает и гасит вклады при установке, обновлении,
  отключении и удалении пакетов без перезапуска хоста.
- Родитель получает список только своих точек и вызывает только активный
  совместимый вклад. Отмена, таймаут и падение плагина изолированы.
- Плагин использует собственные настройки и секреты; родитель и другие плагины
  не получают к ним доступа.
- Интерфейс позволяет установить плагин, выбрать его и открыть настройки;
  отсутствие обязательного плагина объяснено пользователю.
- Сквозной сценарий: установить переводчик, выбрать Яндекс, перевести фразу,
  установить второй плагин Google, переключиться и повторить перевод тем же
  шорткеем. Удалить один плагин — второй и переводчик продолжают работать.
