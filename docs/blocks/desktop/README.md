# Desktop-хост

Один резидентный хост обслуживает интерактивную сессию пользователя. Хост создаёт трей и окна, принимает команды и связывает переносимое ядро с адаптером ОС. Для прототипа принято решение ADR-01 о Rust и Tauri 2. Основание — разделы 2–4 и 8, приёмка 01, 04 и 10 [общего ТЗ](../../specification.md).

## Запуск и команды пользователя

- При первом запуске открыть настройки со штатными модулями. При последующих — создать трей. Повторный запуск активирует настройки существующего экземпляра. Опция автозапуска относится к текущему пользователю.
- Основной клик открывает настройки. Контекстное меню содержит доступные действия включённых модулей, паузу шорткеев и выход. Источник списка — активные манифесты из [менеджера пакетов](../packages/README.md). Для чтения списка запускать модули не требуется.
- Иконка трея зелёная в работе, жёлтая на паузе и красная при недоступном сочетании. Подсказка и пункт «Пауза сочетания» / «Возобновить сочетание» совпадают с состоянием; пауза сохраняется между запусками.
- Закрытие настроек уничтожает WebView. Хост остаётся в трее. При выходе хост прекращает приём новых вызовов, отменяет действующие, освобождает регистрации и завершает дочерние процессы.

Команды меню и события сочетаний передают в [ядро](../core/README.md) идентификаторы модуля и действия. Захват системного контекста обеспечивает [адаптер Windows](../platform/windows/README.md). Поведение экранов, редактора шорткеев и форм модулей описано в [ТЗ интерфейса и настроек](settings.md).

## Критерии приёмки

- На чистом профиле первый и повторный запуски дают один трей и один экземпляр хоста. После закрытия настроек по-прежнему можно вызвать действие.
- После сна, разблокировки и перезапуска Explorer иконка и меню доступны. Ядро инициирует повторную проверку назначений и показывает причины недоступности отдельных шорткеев.
