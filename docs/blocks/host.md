# Ядро, трей и выполнение действий

**Результат.** Один резидентный хост обслуживает интерактивную сессию пользователя. Модули запускаются по требованию. Для прототипа принято решение ADR-01 о Rust и Tauri 2. Основание — разделы 2–4 и 8, приёмка 01, 04 и 09 [общего ТЗ](../ТЗ.md).

## Запуск и команды пользователя

- При первом запуске открыть настройки со штатными модулями. При последующих — создать трей. Повторный запуск активирует настройки существующего экземпляра. Опция автозапуска относится к текущему пользователю.
- Основной клик открывает настройки. Контекстное меню содержит доступные действия включённых модулей, паузу шорткеев и выход. Источник списка — активные манифесты из [менеджера пакетов](packages.md). Для чтения списка запускать модули не требуется.
- Закрытие настроек уничтожает WebView. Хост остаётся в трее. При выходе хост прекращает приём новых вызовов, отменяет действующие, освобождает регистрации и завершает дочерние процессы.

## Контракт выполнения

Из меню и от [реестра шорткеев](hotkeys.md) ядро принимает одну пару `moduleId + actionId`. До открытия собственных окон оно фиксирует контекст источника через [адаптер ОС](windows.md). Для меню используется последнее активное внешнее окно до открытия меню. Если источник закрыт или контекст потерял актуальность, пользователь выбирает его заново.

Ядро выбирает активную версию пакета, запускает процесс, согласует API и передаёт действие по [протоколу SDK](module-sdk.md). Обработка событий трея продолжается, пока пользователь выбирает область или провайдер отвечает на запрос. Завершение процесса, нарушение протокола или сбой запуска дают конечную ошибку конкретного вызова. При отмене зависшего вызова ядро освобождает контекст, игнорирует поздний ответ и завершает оставшийся процесс через 2 с. После завершения работы и закрытия последнего окна модуль выгружается.

## Критерии приёмки

- На чистом профиле первый и повторный запуски дают один трей и один экземпляр хоста. После закрытия настроек по-прежнему можно вызвать действие.
- Одно действие из меню и с клавиатуры попадает в один handler. Вызов из меню обращается к исходному приложению. Ожидание выделения в одном модуле позволяет пользоваться треем.
- Принудительно завершить процесс во время действия, затем воспроизвести зависание и отмену. Второй модуль отвечает, первый можно вызвать повторно, после выхода дочерних процессов нет.
- После сна, разблокировки и перезапуска Explorer иконка и меню доступны. Ядро инициирует повторную проверку назначений и показывает причины недоступности отдельных шорткеев.
