# Контракт микроприложения и SDK

**Результат.** Разработчик добавляет собственный модуль с несколькими действиями, собирает и подписывает пакет, затем обновляет его без изменения исходников хоста. Основание — разделы 2 и 4, приёмка 08, 09 и 11 [общего ТЗ](../ТЗ.md).

## Контракт пакета

Спецификация фиксирует формат `.umpkg` и манифеста в UTF-8. Обязательные сведения — стабильный ID модуля, издатель, отображаемое имя, версия пакета и схемы, диапазон API хоста, точки входа по ОС и архитектуре, иконка, действия и запрошенные возможности. Действие объявляет стабильный локальный ID, название и описание, может предложить шорткеи. Для пользовательских параметров модуль объявляет схему с типами, значениями по умолчанию и секретными полями. Эти сведения доступны хосту до запуска процесса.

Пакет и API версионируются независимо. Внутри major-версии неизвестные необязательные поля игнорируются. Удаление обязательного метода или изменение смысла его параметров требует смены major. Диапазон проверяется до запуска в [менеджере пакетов](packages.md). При рукопожатии процесс подтверждает выбранную версию и возможности. Переименование отображаемого действия сохраняет его ID.

## Протокол выполнения

| Этап | Обязательство сторон |
| --- | --- |
| Обмен | Двунаправленный JSON-RPC 2.0 через stdin/stdout дочернего процесса. Один JSON-объект UTF-8 на строку, максимум 1 МиБ на сообщение. Служебный вывод идёт отдельно. |
| Инициализация | На `initialize` модуль подтверждает версию, доступные возможности и готовность за 3 с. Неуспешная инициализация прекращает запуск. |
| Действие | В `invoke` входят уникальный идентификатор вызова, локальный `actionId` и ссылка на исходный контекст. SDK направляет вызов в handler. Ожидание выбора пользователем продолжается до результата или отмены. |
| Обращение к хосту | Ядро проверяет возможность в контексте именно этого модуля и действующего вызова. Кадр передаётся ссылкой на временный буфер с размерами, форматом и шагом строки. Ссылка действует до завершения вызова. Форме настроек доступен вызов команды модуля, например проверки подключения. |
| Завершение | Каждый вызов получает один исход — успех, отмену или ошибку с машинным кодом. `cancel` и `shutdown` доступны во время операции. Правила обработки поздних ответов и остановки процесса выполняет [ядро](host.md). |

Разрешения протокола регулируют доступ через SDK. Нативный процесс работает с правами пользователя, поэтому модель доверия опирается на подпись издателя. Любой язык реализации может использовать описанный протокол.

## Критерии приёмки

- Передать спецификацию форматов, пример модуля с двумя действиями, инструкцию по сборке и подписи. По ним собрать модуль под новым ID, установить через UI, назначить и вызвать оба действия, поставить следующую версию на тот же хост.
- Автоматически проверить совместимое расширение необязательным полем, отказ для несовместимой major-версии, таймаут инициализации, отмену и поздний ответ. Неверное сообщение или превышение предела завершают конкретный вызов с ошибкой.
- Проверить отказ при обращении через SDK к незапрошенной возможности или к завершённому контексту. Передача полноразмерного кадра укладывается в предел IPC-сообщения за счёт ссылки на буфер.
