# Микроприложение «Пипетка цвета»

Пользователь указывает пиксель в любом видимом окне и одним кликом копирует цвет для вставки в макет, CSS или сообщение. В первой версии выбирается цвет зафиксированного кадра рабочего стола Windows 11 x64.

## Пакет и настройки

| Свойство | Требование первой версии |
| --- | --- |
| Манифест | Отдельный подписанный `.umpkg`, ID `org.utilmaker.color-picker`, издатель `org.utilmaker`. |
| Действие | `pick-color` — «Скопировать цвет пикселя». Вызывается из трея или сочетанием, которое пользователь назначает в общем редакторе. |
| Возможности | `screen.capture` для снимка, `clipboard.write` для записи строки, `settings.read` для формата. |
| Формат результата | Поле «Формат цвета» на странице плагина. По умолчанию HEX: `#2F80ED`, шесть цифр, буквы в верхнем регистре. Второй вариант — CSS RGB: `rgb(47, 128, 237)`, десятичные компоненты 0–255. Выбор сохраняется между запусками. |

## Выбор пикселя

1. Получить один снимок до появления overlay. Показать его и лупу у курсора. Пока пользователь двигает мышь, увеличивать окрестность без сглаживания, отмечать центральный пиксель перекрестием и показывать рядом точную строку для копирования. На краю экрана смещать лупу, удерживая выбранную точку на месте.
2. Стрелки смещают выбранную точку ровно на один физический пиксель. Левый клик или Enter копирует текущее значение. После успешной записи закрыть overlay и освободить кадр. Esc закрывает выбор с сохранением прежнего буфера. Повторный шорткей возвращает в открытый выбор.
3. Если запись в буфер отклонена, сохранить точку и показать её значение с действием «Повторить копирование». При недоступном кадре показать причину и предложить новый захват. Выбор вне площади мониторов или после смены конфигурации дисплеев не должен копировать случайный пиксель.
4. Плагин читает статический кадр в памяти только во время выбора. Лупа, рамка, текст значения и курсор исключены из выборки. После завершения процесс выгружается. История цветов, сетевые запросы и фоновое наблюдение для этого сценария не требуются.

## Цвет и координаты

Вход первой версии — снимок SDR в формате BGRA8, верхняя строка первая. Для физической точки `(x, y)` проверить попадание в монитор и кадр, вычесть `origin`, затем вычислить смещение `(y - origin.y) * stride + (x - origin.x) * 4`. Проверить границы данных. Три первых байта в точке — B, G и R. Форматы вывода используют порядок R, G, B. Альфа-канал опускается. Для HDR и цветовых профилей результат определяется 8-битным кадром платформы; подбор цвета исходного HDR-документа находится за пределами v1.

Координаты курсора, overlay и кадра свести к физическим пикселям виртуального рабочего стола с учётом масштаба конкретного монитора. Если в ответе отсутствует геометрия, нужная для однозначного выбора, показать недоступность режима. При движении мыши брать новые значения из уже доступного снимка. ## Приёмка

| Среда | Проверка | Ожидаемый результат |
| --- | --- | --- |
| Linux, контейнер | Подать кадр с отрицательным `origin.x`, отступом в конце строки и соседними пикселями разных цветов. В целевой точке задать байты `ED 80 2F FF`. | Оба формата точно совпадают с примерами выше. Смещение на пиксель вправо или вниз читает соответствующего соседа. Чёрный и белый дают `#000000` и `#FFFFFF`. |
| Linux, тестовые адаптеры | Попытаться выбрать точку вне кадра, отменить до клика, вернуть ошибку копирования, затем повторить. | Выхода за буфер нет. Только успешная команда копирования меняет буфер. Значение при повторе совпадает с показанным. |
| Windows 11, пользователь | Открыть в SDR контрольное изображение в масштабе 1:1. Вызвать из трея и шорткеем. Выбрать известный цвет на основном мониторе и мониторе слева с другим DPI, затем соседний пиксель стрелкой. | Перекрестие лупы, показанный цвет и вставленная в Блокнот строка соответствуют одной точке. Выбор работает также у края экрана. |
| Windows 11, пользователь | Задать формат RGB, перезапустить хост, задержаться на выборе дольше срока ссылки на кадр и скопировать. Повторить с Esc и с занятым буфером. | Формат сохранился. Долгий выбор остаётся рабочим. Отмена и отказ в записи сохраняют прежний буфер, повтор копирует выбранный цвет. |

Агент передаёт эталонное изображение с координатами, оба ожидаемых значения и результаты Linux-проверок. Пользователь проверяет DPI, лупу и запись в Windows-буфер на своей сборке.
