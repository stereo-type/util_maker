# Провайдеры перевода и профили подключения

**Результат.** Пользователь настраивает Яндекс и Google внутри переводчика и выбирает, куда уйдёт следующий запрос. Оба адаптера входят в один обновляемый пакет [переводчика](../README.md). Основание — разделы 6 и 7, приёмка 07 [общего ТЗ](../../../../specification.md).

## Профиль и контракт

Пользователь выбирает сервис, вводит или заменяет собственный API-ключ, указывает исходный и целевой языки. Доступно автоопределение исходного языка. Исходная настройка целевого языка — русский. На форме видны имя сервиса, состояние и «Проверить подключение». Для проверки используется короткая фиксированная фраза. Команду формы выполняет модуль через тот же адаптер провайдера.

Каждый адаптер реализует две операции — проверить подключение и перевести текст с возможностью отмены. На вход перевода поступают текст, языки и профиль, на выходе — текстовый результат либо ошибка. Запрос идёт напрямую по HTTPS к активному сервису. Учётные данные профилей хранятся раздельно в системном хранилище текущего пользователя, в настройках — только ссылки. Активация другого профиля действует со следующего вызова и сохраняет шорткей.

| Сервис | Параметры и ответ |
| --- | --- |
| Yandex Translate API v2 | API-ключ сервисного аккаунта в заголовке `Authorization: Api-Key`. Вызов `translate/v2/translate` получает `texts` и `targetLanguageCode`, явный исходный язык передаётся при выборе. Для сервисного аккаунта `folderId` опускается. Перевод берётся из `translations[].text`. |
| Google Cloud Translation Basic v2 | API-ключ проекта с включённым Cloud Translation API. Вызов `language/translate/v2` получает `q`, `target`, формат `text` и при выборе явный `source`. Ответ читается из `data.translations[].translatedText`. |

Сообщить об ошибке авторизации, исчерпании квоты, временном ограничении частоты, отсутствии сети либо истечении 10 с. Сохранять различие причин в пределах сведений провайдера. Ошибка одного профиля не запускает автоматический запрос во второй. В локальный журнал попадают только разрешённые [диагностические сведения](../../../core/diagnostics.md).

## Критерии приёмки

- С действующими тестовыми ключами проверить оба подключения. Перевести контрольную фразу через Яндекс, переключить на Google и повторить тем же шорткеем. В обоих случаях подтвердить ответ выбранного сервиса и возможность скопировать его.
- Через тестовый HTTP-адаптер проверить для каждого сервиса отправленные поля, автоопределение и явный выбор языков, разбор ответа и повтор пользователем. В запросе одного сервиса отсутствуют ключ другого профиля и посторонний текст.
- Воспроизвести неверный ключ, квоту, HTTP 429, отключённую сеть, задержку и отмену. Проверить соответствующий исход, отсутствие запроса второму провайдеру и отсутствие секретов в журнале. Передать пользователю инструкцию настройки обоих профилей.
