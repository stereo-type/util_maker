# Настройка провайдеров перевода

Оба профиля настраиваются в будущей странице переводчика; сейчас адаптеры
поставляются как `util-maker-providers` и проверяются тестами. Ключи хранятся
раздельно, активный профиль определяет, куда уйдёт следующий запрос.

## Яндекс

1. В Yandex Cloud создайте сервисный аккаунт с ролью на Translate.
2. Выпустите API-ключ сервисного аккаунта.
3. Укажите ключ в профиле Яндекса. Адаптер отправляет его в заголовке
   `Authorization: Api-Key`, вызывает
   `https://translate.api.cloud.yandex.net/translate/v2/translate` и читает
   `translations[0].text`. `folderId` для этого способа не передаётся.

## Google

1. Включите Cloud Translation API в проекте Google Cloud.
2. Создайте API-ключ проекта.
3. Укажите ключ в профиле Google. Адаптер вызывает
   `https://translation.googleapis.com/language/translate/v2?key=...` с
   `q`, `target`, `format=text` и читает
   `data.translations[0].translatedText`.

## Проверка

`check_connection` отправляет фиксированную фразу `Util Maker`. Ошибки
авторизации, квоты, HTTP 429, таймаута и отмены различаются; автоматического
повтора через второй сервис нет. В журнал не попадают ключи, заголовки
авторизации и полные URL с секретами.
