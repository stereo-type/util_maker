# Провайдер «Файловые хранилища»

Подписанный пакет `org.utilmaker.file-storage` публикует `util-maker.file-storage` версии `1.0.0`. Приложение через свой слот сохраняет файл в выбранное пользователем назначение. Сервис проверяет параметры и делегирует запись пакету реализации точки `storage-backend`. Новые реализации подключаются по манифесту. [Общая модель и примеры манифестов](../../core/typed-providers.md)

## Контракт v1

| Участник | Операция и данные |
| --- | --- |
| Потребитель → сервис | `putFile` принимает `requestId` одной логической записи, `fileName` (один сегмент), `mimeType` и `contentRef` на неизменяемые байты с размером. Хост подставляет доверенные подключение и папку из слота. Потребитель получает `objectId`, фактическое имя и отображаемое назначение после подтверждения сервера. |
| Сервис → реализация | Контракт `util-maker.file-storage.backend` v1. Операция `putFile` получает те же метаданные, ссылку для чтения и контекст конкретного подключения и папки. Реализация возвращает непрозрачный ID удалённого объекта. Ссылка для публичного доступа в v1 не создаётся. |
| Настройки → реализация | Команды подключения/повторного входа, проверки доступа и выбора папки запускаются только по действию пользователя. `checkConnection` проверяет текущий аккаунт, `resolveFolder` преобразует выбор или относительный путь в назначение этого аккаунта. Windows-путь локального режима не отправляется в облако. |

Пример метаданных запроса потребителя. Бинарное содержимое передаётся отдельно от JSON-RPC.

```json
{"slotId":"save-target","operation":"putFile","params":{"requestId":"save-7b42","fileName":"screen-7b42.png","mimeType":"image/png","contentRef":{"id":"blob-34","size":1756032}}}
```

Для привязки пользователь выбирает папку или задаёт относительные сегменты внутри корня подключения. Пустой путь означает корень, выбранный для этого подключения. У Nextcloud назначение хранится как нормализованные сегменты, у Google Диска существующая папка закрепляется по ID. Введённые подкаталоги создаются при явном сохранении. Значения с `..`, абсолютными путями, неоднозначными разделителями, управляющими символами и попыткой выйти из выбранного корня отклоняются. Пробелы и кириллица сохраняются. Имя файла проверяется отдельно от папки.

## Байты, повторы и ошибки

- Лимит существующего JSON-RPC — 1 МиБ. Хост публикует ограниченный по размеру неизменяемый источник и выдаёт непрозрачную ссылку. Читать её может только маршрут текущего вызова, последовательно или блоками. Принять PNG размером больше 1 МиБ. Предлагаемый предел v1 — 64 МиБ на файл включительно. Превышение возвращает ошибку до отправки. Временный ресурс очищается при успехе, отказе, отмене и аварийном завершении. Лимит IPC сохраняется для всех клиентов. [Существующая передача экранных данных](../../sdk/README.md#доступ-плагина-к-пикселям-кадра)
- Получатель создаёт новый объект. Коллизия с чужим файлом сохраняет существующий файл и возвращает конфликт либо допускает отдельное имя с согласия пользователя. Двойное нажатие и повтор той же записи используют один `requestId` и неизменные байты. Область ключа включает потребителя, слот и подключение. Пока идёт попытка, хост фиксирует назначение. Смена папки или аккаунта требует нового явного сохранения.
- При обрыве после отправки возможен исход «Результат неизвестен». До повтора сверить состояние по устойчивому идентификатору записи. После перезапуска процесса реализации сохраняется возможность сверки без хранения изображения и секретов в журнале операций. Если подтвердить результат нельзя, вернуть неопределённый исход и предложить проверить папку. Успех требует подтверждения конкретного объекта. Удалённая запись, уже принятая сервисом, может сохраниться после локальной отмены.
- Различать недоступное подключение, повторный вход, отсутствие прав на папку, конфликт, превышение размера или квоты, временное ограничение, потерю сети, таймаут, отмену и неопределённый исход. UI сохраняет кадр при ошибке и разрешает повтор с тем же ID. У типизированного сетевого сохранения отдельный конечный бюджет (для v1 до 120 с на попытку), отмена проходит через весь маршрут. Таймаут перевода и других старых вызовов сохраняется.

## Приёмка

Один набор контрактных проверок прогоняется на обоих адаптерах и тестовом сервере. Два потребителя пишут в разные папки одного аккаунта, затем одновременно в два аккаунта одной реализации. Скачать результаты и сравнить исходные байты. Проверить коллизию, отказ записи, разрыв до и после приёма файла, отмену и недоступность чужой ссылки. Перечисление установленных сервисов и доступных подключений работает офлайн.
