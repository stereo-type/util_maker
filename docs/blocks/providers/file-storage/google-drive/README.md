# Файловое хранилище Google Диск

Пакет `org.utilmaker.file-storage.google-drive` типа `provider` реализует `storage-backend` родителя `org.utilmaker.file-storage`. Одновременно доступны несколько именованных аккаунтов. Выбор профиля в одном приложении не переключает другие привязки. [Контракт файлового хранилища](../README.md)

## Подключение

Авторизация использует OAuth 2.0 для Desktop, системный браузер, PKCE S256, одноразовый `state` и callback на loopback. Сессию входа связывать с конкретным создаваемым подключением. После отмены, таймаута или завершения закрывать временный listener. При повторном входе сверять идентичность аккаунта перед заменой токена. Обновлять токены только своего подключения, сохраняя прежний refresh token при его отсутствии в успешном ответе. Ошибка отзыва доступа ведёт к повторному входу. [OAuth для desktop-приложений](https://developers.google.com/identity/protocols/oauth2/native-app)

Включить Drive API и зарегистрировать desktop OAuth client для поставки. Описать настройки тестового Google Cloud проекта и тестовых пользователей. Пользователю обычной поставки достаточно войти в аккаунт. Клиент Desktop считается публичным, пользовательские токены и коды авторизации в пакет не входят. Запрашивать область `drive.file`. В v1 поддержать корневую папку, созданную самим приложением в «Моём диске», и вложенные папки в ней. Для уже существующей внешней папки пользователь явно предоставляет доступ через механизм выбора Google. Интерфейс показывает только доступные назначения. [Области доступа Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

## Запись

Реализация работает с Drive API v3. Хранить ID выбранного каталога в параметрах слота. Переименование папки сохраняет назначение. У одноимённых папок разные ID, выбор по одному заголовку недопустим. Создаваемому файлу передавать конкретный `parents`, имя, MIME и бинарные данные. Для больших файлов использовать возобновляемую загрузку. Сохранить предварительно выделенный Drive ID для логической записи до первого создания файла. При повторе после потери ответа сверить объект по тому же ID. [Папки Drive](https://developers.google.com/workspace/drive/api/guides/folder) · [Загрузка и повтор с выделенным ID](https://developers.google.com/workspace/drive/api/guides/manage-uploads#use_a_pre-generated_id_to_upload_files)

**Приёмка.** На тестовых OAuth- и Drive-серверах проверить два одновременных входа, отказ consent, подмену callback, обновление/отзыв одного токена, запись в две одноимённые папки по их ID и обрыв принятой загрузки. На Windows пользователь подключает личный и рабочий аккаунты, сохраняет по PNG в каждый и сверяет файлы в веб-интерфейсе.
