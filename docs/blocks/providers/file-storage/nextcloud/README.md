# Файловое хранилище Nextcloud

Пакет `org.utilmaker.file-storage.nextcloud` типа `provider` реализует `storage-backend` родителя `org.utilmaker.file-storage`. В настройках каждого именованного подключения пользователь задаёт HTTPS-адрес установки (включая подкаталог), имя пользователя и пароль приложения. Проверить соединение можно до привязки к скриншотеру. Секрет хранится отдельно для каждого `connectionId`. Для другого сервера или аккаунта создаётся новое подключение. [Контракт файлового хранилища](../README.md)

- Использовать WebDAV под `remote.php/dav/files/{user}/`. Проверка доступа читает свойства каталога через `PROPFIND`. Путь собирать из сегментов, кодируя каждый один раз. Секрет передаётся по TLS только своему серверу. При смене origin в redirect прекратить авторизованный запрос. [Операции WebDAV Nextcloud](https://docs.nextcloud.com/server/latest/developer_manual/client_apis/WebDAV/basic.html)
- Для записи создать недостающие каталоги через `MKCOL` и загрузить байты через условный `PUT` (`If-None-Match: *`). Если каталог параллельно создан, проверить его тип. Закрепить за операцией уникальный путь загрузки или удалённый маркер и сохранить его до запроса. После обрыва сверить принадлежность объекта операции и содержимое. Если принадлежность установить нельзя, вернуть «Результат неизвестен». Чужой файл при коллизии сохраняется.
- Ошибки отозванного пароля, запрещённой папки, отсутствующей квоты и недоступного сервера различимы в форме. Отзыв одного пароля сохраняет работоспособность второго подключения. Адрес, учётные данные и содержимое снимка исключаются из диагностических сообщений.

**Приёмка.** В Linux воспроизвести обмен с тестовым WebDAV, включая сервер в подкаталоге, два подключения, кириллицу и пробелы, одновременное создание папки, конфликт и потерю ответа после загрузки. На Windows пользователь настраивает тестовый Nextcloud, сохраняет PNG из редактора и сверяет файл в веб-интерфейсе. [Очередь](../../../../tasks/blocks/providers/file-storage/nextcloud/README.md)
