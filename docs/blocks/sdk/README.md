# Контракт микроприложения и SDK

**Результат.** Разработчик добавляет собственный модуль с несколькими действиями, собирает и подписывает пакет, затем обновляет его без изменения исходников хоста. Основание — разделы 2 и 4, приёмка 08, 09 и 11 [общего ТЗ](../../specification.md).

## Контракт пакета

Спецификация фиксирует формат `.umpkg` и манифеста в UTF-8. Обязательные сведения — стабильный ID модуля, издатель, отображаемое имя, версия пакета и схемы, диапазон API хоста, точки входа по ОС и архитектуре, иконка, действия и запрошенные возможности. Действие объявляет стабильный локальный ID, название и описание, может предложить шорткеи. Для пользовательских параметров модуль объявляет схему с типами, значениями по умолчанию и секретными полями. Эти сведения доступны хосту до запуска процесса.

Пакет и API версионируются независимо. Внутри major-версии неизвестные необязательные поля игнорируются. Удаление обязательного метода или изменение смысла его параметров требует смены major. Диапазон проверяется до запуска в [менеджере пакетов](../packages/README.md). При рукопожатии процесс подтверждает выбранную версию и возможности. Переименование отображаемого действия сохраняет его ID.

## Протокол выполнения

| Этап | Обязательство сторон |
| --- | --- |
| Обмен | Двунаправленный JSON-RPC 2.0 через stdin/stdout дочернего процесса. Один JSON-объект UTF-8 на строку, максимум 1 МиБ на сообщение. Служебный вывод идёт отдельно. |
| Инициализация | На `initialize` модуль подтверждает версию, доступные возможности и готовность за 3 с. Неуспешная инициализация прекращает запуск. |
| Действие | В `invoke` входят уникальный идентификатор вызова, локальный `actionId` и ссылка на исходный контекст. SDK направляет вызов в handler. Ожидание выбора пользователем продолжается до результата или отмены. |
| Обращение к хосту | Ядро проверяет возможность в контексте именно этого модуля и действующего вызова. Кадр передаётся ссылкой на временный буфер с размерами, форматом и шагом строки. Ссылка действует до завершения вызова. Форме настроек доступен вызов команды модуля, например проверки подключения. |
| Завершение | Каждый вызов получает один исход — успех, отмену или ошибку с машинным кодом. `cancel` и `shutdown` доступны во время операции. Правила обработки поздних ответов и остановки процесса выполняет [ядро](../core/README.md). |

Разрешения протокола регулируют доступ через SDK. Нативный процесс работает с правами пользователя, поэтому модель доверия опирается на подпись издателя. Любой язык реализации может использовать описанный протокол.

## Пользовательские настройки

Необязательное поле `settings` описывает форму целиком, поэтому оболочка
строит её без запуска процесса. Схема поддерживает обычные и секретные поля,
значения по умолчанию, варианты выбора, профили и команды формы. Старые
манифесты без `settings` читаются без изменений.

```json
"settings": {
  "schemaVersion": 1,
  "profileField": "activeProfile",
  "fields": [
    {
      "id": "activeProfile",
      "label": "Активный профиль",
      "type": "select",
      "default": "yandex",
      "options": [
        { "value": "yandex", "label": "Яндекс" },
        { "value": "google", "label": "Google" }
      ]
    }
  ],
  "profiles": [
    {
      "id": "yandex",
      "name": "Яндекс",
      "fields": [
        {
          "id": "sourceLang",
          "label": "Исходный язык",
          "type": "select",
          "default": "auto",
          "options": [
            { "value": "auto", "label": "Авто" },
            { "value": "en", "label": "Английский" },
            { "value": "ru", "label": "Русский" }
          ]
        },
        {
          "id": "targetLang",
          "label": "Целевой язык",
          "type": "select",
          "default": "ru",
          "options": [
            { "value": "en", "label": "Английский" },
            { "value": "ru", "label": "Русский" }
          ]
        },
        {
          "id": "apiKey",
          "label": "API-ключ",
          "type": "secret",
          "required": true,
          "secretRef": "translator/yandex/apiKey"
        }
      ]
    },
    {
      "id": "google",
      "name": "Google",
      "fields": [
        {
          "id": "sourceLang",
          "label": "Исходный язык",
          "type": "select",
          "default": "auto",
          "options": [
            { "value": "auto", "label": "Авто" },
            { "value": "en", "label": "Английский" },
            { "value": "ru", "label": "Русский" }
          ]
        },
        {
          "id": "targetLang",
          "label": "Целевой язык",
          "type": "select",
          "default": "ru",
          "options": [
            { "value": "en", "label": "Английский" },
            { "value": "ru", "label": "Русский" }
          ]
        },
        {
          "id": "apiKey",
          "label": "API-ключ",
          "type": "secret",
          "required": true,
          "secretRef": "translator/google/apiKey"
        }
      ]
    }
  ],
  "commands": [
    {
      "id": "testConnection",
      "name": "Проверить подключение",
      "profileField": "activeProfile",
      "fields": ["sourceLang", "targetLang", "apiKey"]
    }
  ]
}
```

Типы полей: `text`, `number`, `boolean`, `select`, `secret`. Секретное поле
обязано иметь `secretRef` и не может иметь `default`; само значение хранится
только в системном хранилище. `profileField` ссылается на поле `select`, чьи
варианты совпадают с ID профилей. Команда со ссылкой на профиль обязана
указывать поля, существующие в каждом профиле; неизвестное поле, профиль или
команда отклоняются при `Manifest::validate`.

Публичное состояние формы содержит значения обычных полей и признаки наличия
секретов:

```json
{
  "activeProfile": "yandex",
  "values": { "sourceLang": "en", "targetLang": "ru" },
  "secrets": {
    "apiKey": { "secretRef": "translator/yandex/apiKey", "present": true }
  }
}
```

Команда формы вызывается методом `command`:

```json
{"jsonrpc":"2.0","id":7,"method":"command",
 "params":{"commandId":"testConnection","profile":"yandex",
           "values":{"sourceLang":"en","targetLang":"ru"},
           "secrets":{"apiKey":{"secretRef":"translator/yandex/apiKey","present":true}}}}
```

Результат содержит сообщение, необязательные данные и ошибки конкретных полей.
Значение секрета не возвращается; при отсутствии ключа оболочка получает
`fieldErrors: [{"fieldId":"apiKey","code":"required","message":"..."}]`.

## Возможности хоста во время invoke

Во время активного вызова модуль может отправить по тому же stdout JSON-RPC
запрос `host.call`:

```json
{"jsonrpc":"2.0","id":41,"method":"host.call",
 "params":{"callId":"call-7","capability":"screen.frame",
           "method":"frame.capture","params":{"monitor":"primary"}}}
```

Хост сверяет `callId` с живым вызовом и `capability` с манифестом. Возможность
без объявления, чужой или завершённый контекст получают машинные коды
`CAPABILITY_DENIED` (1003), `CONTEXT_LOST` (1005) и `CANCELLED` (1002). Адаптер
платформы остаётся внутри хоста: в JSON нет Win32-дескрипторов и адресов.

Кадр передаётся ссылкой, а не пикселями:

```json
{
  "bufferId": "frame-42",
  "format": "bgra8",
  "width": 1920,
  "height": 1080,
  "stride": 7680,
  "origin": { "x": -1920, "y": 0 },
  "scaleFactor": 1.0,
  "expiresInMs": 5000,
  "geometry": {
    "virtualScreen": { "x": -1920, "y": 0, "width": 3840, "height": 1080 },
    "monitors": [
      {
        "rect": { "x": -1920, "y": 0, "width": 1920, "height": 1080 },
        "scaleFactor": 1.0,
        "primary": false
      },
      {
        "rect": { "x": 0, "y": 0, "width": 1920, "height": 1080 },
        "scaleFactor": 1.5,
        "primary": true
      }
    ]
  }
}
```

`width`, `height`, `stride`, `origin` и все прямоугольники `geometry` заданы в
физических пикселях виртуального рабочего стола, поэтому координаты монитора
слева от основного отрицательные. `origin` — левый верхний угол самого кадра.
`scaleFactor` кадра — масштаб монитора с наибольшей площадью пересечения;
масштаб каждого монитора остаётся в `geometry.monitors`. Порядок мониторов
соответствует системному перечислению; для запроса кадра используйте
`"primary"` или индекс этого массива. Поле `geometry` необязательно для
совместимости со старыми ответами.

Ссылка действует до истечения `expiresInMs` или завершения вызова, смотря что
наступит раньше; просроченная ссылка возвращает `BUFFER_EXPIRED` (1007).
Операции `frame.capture`, `frame.release`, `selection.get`, `buffer.copy`,
`settings.read` и `secret.read` используют один конверт. Пока обработчик ждёт
ответ хоста, SDK принимает `cancel` и `shutdown`, поэтому отмена не теряется.
Модуль без `invoke_with_host` продолжает работать по протоколу v1: например,
`control/ping` не меняет манифест и ответ.

## Доступ плагина к пикселям кадра

`frame.capture` возвращает `FrameRef` с метаданными и необязательным полем `pixelPath` — путём к локальному файлу BGRA8. Хост создаёт файл при захвате, плагин читает его через `FrameRef::read_pixels()` (или `std::fs::read`) и копирует байты в память, если кадр нужен дольше `expiresInMs`. В JSON передаются только путь и метаданные, не пиксели. [Контракт SDK в коде](../../../crates/sdk/src/host.rs) · [Хранилище кадров](../../../crates/platform/src/capture.rs)

- Хост проверяет владельца файла по `moduleId + callId`, срок действия и границы; чужой вызов получает `CAPABILITY_DENIED`, просроченный — `BUFFER_EXPIRED`.
- Файл удаляется при `frame.release`, истечении `expiresInMs`, завершении/отмене вызова и падении процесса; на Unix права `0600`.
- Плагин может читать файл только пока ссылка действительна; после `release` путь становится недействительным. Для длительной работы скопируйте пиксели в свою память.
- Координаты выбора переводить в физические пиксели с учётом геометрии каждого монитора. Начало кадра задаёт `origin`, шаг строки в **байтах** задаёт `stride`, порядок каналов — BGRA8.
- Нижний предел `hostApi` не меняется: `pixelPath` необязателен, старые клиенты его игнорируют.

## Критерии приёмки

- Передать спецификацию форматов, пример модуля с двумя действиями, инструкцию по сборке и подписи. По ним собрать модуль под новым ID, установить через UI, назначить и вызвать оба действия, поставить следующую версию на тот же хост.
- Автоматически проверить совместимое расширение необязательным полем, отказ для несовместимой major-версии, таймаут инициализации, отмену и поздний ответ. Неверное сообщение или превышение предела завершают конкретный вызов с ошибкой.
- Проверить отказ при обращении через SDK к незапрошенной возможности или к завершённому контексту. Передача полноразмерного кадра укладывается в предел IPC-сообщения за счёт ссылки на буфер.
