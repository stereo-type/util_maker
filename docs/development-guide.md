# Дополнение к общему ТЗ. Работа в проекте

## Повторяемые команды

Часто повторяемые операции разработки оформляются как цели корневого [Makefile](../Makefile). Команда проекта для разработчика, CI и документации — `make <цель>` из корня репозитория. Правило распространяется на сборку приложения и модулей, запуск тестов и проверок, упаковку установщика и другие регулярно используемые операции.

1. **Перед выполнением** проверь, есть ли в `Makefile` цель для нужного действия. Если есть, используй её.
2. **При появлении повторяемой операции** добавь цель с понятным именем и помести в неё вызов нужного инструмента или скрипта. Например, для регулярно выполняемой упаковки модуля цель может принимать путь к модулю как параметр. В описании задачи и инструкциях приводи вызов через `make` с нужными параметрами.
3. **При изменении процедуры** обнови реализацию цели в `Makefile`. Если изменился способ её вызова, обнови примеры в документации и обращения из CI.
4. **Если цель завершается ошибкой**, зафиксируй имя цели и причину сбоя. При работе по поручению пользователя сообщи об ошибке. Запуск внутренней команды в обход цели требует отдельного указания пользователя.

## Выполнение команд агентом

Проектные make-команды запускай вне песочницы с `sandbox_permissions: require_escalated`, чтобы использовалось окружение пользователя. При отклонении или недоступности такого запуска сообщи причину. Для запуска сборки frontend требуется явная просьба пользователя, в том числе если frontend собирается как часть общей цели.

## Подготовка окружения

На Ubuntu после клонирования запустить `make dev-setup`. Цель собирает Linux-образ, проверяет версии Rust, Cargo, Clippy, rustfmt, Node.js, npm, TypeScript и Tauri CLI, наличие системных библиотек и компиляцию временного Rust-проекта. Первая сборка обращается к Docker Hub, Debian, npm и источнику компонентов Rust. При ограниченном доступе это нужно учесть при подготовке сети среды. Определение образа хранится в [Dockerfile](../docker/dev/Dockerfile).

Для разовой команды использовать `make dev-run CMD="…"`, для интерактивной работы — `make dev-shell`. В контейнере checkout доступен в `/workspace`. Пакеты для разработки добавлять в образ, зависимости проекта и их lock-файлы — в репозиторий.

## Передача на Windows

Агент работает с переносимым ядром, SDK, модулями и тестами в Ubuntu. В рамках первого прототипа он готовит цель `make build-windows` для ручного запуска пользователем в локальной копии с Linux Docker, например из WSL. Цель собирает хост и модули для Windows x64 и экспортирует NSIS-установщик в `dist/`. Инструменты кросс-сборки помещаются в отдельный Docker stage для локальной сборки. [Сборка Tauri под Windows из Linux](https://v2.tauri.app/distribute/windows-installer/#build-windows-apps-on-linux-and-macos).

Пользователь получает изменения, запускает эту цель локально и сам открывает полученный файл на Windows 11. Для ручной проверки агент указывает проверяемую ревизию, путь к результату, действия и ожидаемое поведение. Сценарии с треем, системными сочетаниями, UI Automation, DPI и измерением ресурсов закрываются по фактическому результату пользователя. Автоматическая сборка EXE и удалённый запуск на Windows из среды разработки в процесс не входят.
