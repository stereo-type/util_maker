# Как работать с задачами

[Сводный список](tasks/README.md) задаёт порядок очередей. У каждого компонента есть ТЗ в `docs/blocks/<блок>/README.md` и очередь в `docs/tasks/blocks/<блок>/README.md`. Например, для HTTP-адаптеров Яндекса и Google это [ТЗ провайдеров](blocks/plugins/translator/providers/README.md) и [очередь провайдеров](tasks/blocks/plugins/translator/providers/README.md). Файл задачи лежит рядом с README её очереди.

## Куда положить задачу

| Какой результат принимаем | Где разместить карточку |
| --- | --- |
| После переназначения шорткей вызывает только новое действие | `docs/tasks/blocks/core/`. Правила владения сочетанием реализует ядро. |
| Редактор показывает владельца занятого шорткея и запрашивает подтверждение | `docs/tasks/blocks/desktop/`. Окно использует результат проверки ядра. |
| Переводчик отменяет ожидание выделения по Esc | `docs/tasks/blocks/plugins/translator/`. |
| Адаптер Google обрабатывает ответ об исчерпанной квоте | `docs/tasks/blocks/plugins/translator/providers/`. |
| На чистой Windows проверена вся поставка, включая установку и вызов обоих инструментов | `docs/tasks/`. Строка карточки находится в разделе «Общие задачи» сводного списка. |

Для одной карточки выберите одного владельца по результату приёмки. Если функция включает отдельно проверяемые изменения нескольких компонентов, заведите карточку в каждой нужной очереди. Например, для захвата экрана адаптер Windows отвечает за кадр, а плагин — за обрезку и аннотации. Согласуйте общий контракт и укажите зависимость, если без его реализации работу нельзя начать. Для независимой части достаточно описать, с каким тестовым адаптером её проверять.

## Как создать карточку

Все файлы в `docs/` и его подпапках называйте по-английски. В именах Markdown-документов и карточек используйте строчные латинские буквы и дефисы между словами, например `hotkey-reassignment.md`. Индексы называйте `README.md`. Заголовки и текст документации пишите на русском. При переносе или переименовании файла обновите все ссылки на него в репозитории.

1. Найдите требование в [карте блоков](blocks/README.md) или [общем ТЗ](specification.md). Для работы из [плана развития](roadmap.md) укажите в карточке также соответствующий этап. Если появляется новый компонент, заведите его ТЗ и одноимённую очередь, свяжите их ссылками и добавьте в обе карты.
2. Проверьте открытые и завершённые карточки. Создайте один Markdown-файл с коротким именем и заголовком в форме действия. Укажите статус, ссылку на ТЗ, наблюдаемый результат, критерии приёмки и зависимости со ссылками. Разделяйте зависимости для старта и для последующей сквозной проверки.
3. Добавьте строку с названием, ссылкой и статусом в README своей очереди. Порядок строк задаёт приоритет. У общих задач эту роль выполняет сводный список. Для компонентной задачи достаточно одной строки в её локальной очереди.

## Как выбрать и взять задачу

- Если указана карточка, откройте её напрямую. Если указан блок, например `plugins/screenshot`, возьмите первую доступную карточку только из его очереди. У `plugins/translator` и `plugins/translator/providers` отдельные очереди.
- Без указания блока следуйте порядку из [сводного списка](tasks/README.md). Пропускайте занятые, заблокированные, переданные на ревью и завершённые карточки. Если готовых карточек в выбранной области нет, сообщите об этом.
- Перед началом сверьте строку и карточку с актуальным состоянием очереди. Одним изменением поставьте в обоих местах 🛠️ **В работе**. Если карточку уже взяли, повторите выбор в той же области.
- Для одновременной работы в отдельных checkout назначайте агентам разные блоки или конкретные карточки. Изменение Markdown в одной локальной ветке становится видно в другой после синхронизации. Общий контракт, который нужен обоим агентам, закрепите в ТЗ владельца и свяжите карточки.

## Статусы и передача на ревью

| Статус | Когда ставить |
| --- | --- |
| 📥 К выполнению | Результат и критерии сформулированы. |
| 🛠️ В работе | Исполнитель взял карточку или устраняет замечания ревью. |
| ⛔ Заблокирована | Дальше двигаться нельзя. В карточке записаны препятствие и условие продолжения. После устранения верните задачу в работу. |
| 👁️ На ревью | Реализация и доступные проверки закончены. В раздел «Проверка» добавлены команды, результаты и оставшиеся шаги. |
| ✅ Выполнена | Результат принят после ревью, требуемые проверки подтверждены. Сохраните карточку и строку по прежним путям. |

При каждом переходе обновляйте карточку и строку её очереди одним изменением. Отмечайте только фактически пройденные критерии. Для ручной приёмки на Windows укажите ревизию, команду локальной сборки, действия и ожидаемый результат. Пользователь собирает и запускает установщик на своей машине. Команды проекта и правила запуска описаны в [руководстве по работе в проекте](development-guide.md).
