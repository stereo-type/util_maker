# Исполнять запросы возможностей только в контексте активного вызова

**Статус** — 📥 К выполнению

[Этап 3 плана развития](../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../blocks/core/README.md)

Встроить двусторонний обмен в `ModuleProcess` и реальный маршрут вызова. Хост закрепляет внешний источник до показа собственных окон и передаёт соответствующему адаптеру контекст модуля, действия и вызова. Для старта использовать подменную ОС.

**Зависимости для старта** — [Дать модулю доступ к возможностям хоста во время invoke](../sdk/host-capabilities.md).

## Критерии приёмки

- [ ] Два одновременно работающих модуля получают только заявленные возможности и свои контексты, кадры и секреты. Подмена чужого ID или просроченной ссылки получает отказ.
- [ ] Вызов из меню использует последнее внешнее окно, шорткей — источник в момент события. При потере источника модуль получает определённый исход.
- [ ] Выход, отмена и падение освобождают буферы, подписки и дочерние процессы. Поздний ответ отбрасывается, зависший процесс останавливается в срок из ТЗ, второй модуль остаётся доступен.

## Проверка

На Linux через `make test` проверить доступ, таймаут, повторный вызов и освобождение ресурсов на двух процессах. Платформенные обработчики подключаются через этот же маршрут.
