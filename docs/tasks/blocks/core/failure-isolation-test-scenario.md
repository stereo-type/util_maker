# Дать воспроизводимый сценарий сбоя плагина

**Статус** — 👁️ На ревью

[Этап 4 плана развития](../../../../roadmap.md#4-принять-первую-поставку-windows) · замечание к [«Изолировать необработанную ошибку плагина и сообщить о сбое оболочке»](plugin-failure-isolation.md)

## Наблюдение

Проверка предлагает завершить `control-module.exe` «во время действия», но
контрольный модуль живёт доли секунды и сразу завершается. Пользователь не успевает
открыть Диспетчер задач, поэтому сценарий невоспроизводим.

## Критерии приёмки

- [ ] В поставке или тестовом наборе есть плагин/действие с задержкой, которое остаётся запущенным достаточно долго для ручного завершения процесса.
- [ ] Или есть скрипт, который сам завершает процесс в нужный момент и собирает результат.
- [ ] Инструкция описывает точные шаги, момент завершения процесса и ожидаемое сообщение об ошибке.
- [ ] Пользователь видит `moduleId`, `actionId`, машинную категорию сбоя и причину без секретов и stderr.
- [ ] Второй плагин продолжает отвечать; сбойный можно вызвать повторно, пока он не отключён.
- [ ] Проверка кнопки «Отключить плагин» выполняется после задачи [«Управлять локальными пакетами из настроек»](../desktop/package-management.md).

## Зависимости

- [Изолировать необработанную ошибку плагина и сообщить о сбое оболочке](plugin-failure-isolation.md) — контракт `InvokeFailure`.

## Что сделано

- Добавлен `scripts/kill-plugin.ps1`: запускается до вызова, ждёт появления процесса и завершает его.
- Для контрольного модуля это позволяет воспроизвести сбой без ручного поиска в Диспетчере задач.
- Проверка кнопки «Отключить плагин» остаётся после задачи управления пакетами.
