# Вызвать действие контрольного модуля через IPC

**Статус** — ✅ Выполнена

**Основание** — [ТЗ блока «Ядро»](../../../blocks/core/README.md).

Провести один invoke от пары moduleId и actionId до handler в дочернем процессе. Начать с тестового транспорта. Для сквозной проверки подключить [handshake SDK](module-sdk-handshake.md).

## Критерии приёмки

- [x] Из теста на Ubuntu запускается контрольный процесс и возвращает результат с ID вызова.
- [x] Аварийное завершение дочернего процесса завершает вызов ошибкой. Повторный вызов успешен.
- [x] После отмены поздний ответ игнорируется, зависший процесс завершается в пределах 2 с.

## Что сделано

- `InvokeOutcome.call_id` — ядро возвращает идентификатор вызова; контрольный модуль дублирует его в `data.callId`.
- `CoreError::Cancelled` и `ModuleProcess::invoke_cancellable`: флаг отмены проверяется не реже раза в 50 мс, модулю отправляется `cancel`, затем процесс получает 500 мс на выход и принудительно завершается.
- Тестовый модуль получил режимы `crash`, `hang` и `late-invoke` для проверки аварии, зависания и позднего ответа.
- `crates/core/tests/host_invoke.rs` — четыре сценария вызова через реальные процессы.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make test` — 22 теста пройдено, в том числе 4 сценария invoke:
  - результат контрольного модуля содержит ID вызова, совпадающий с `data.callId`;
  - процесс, завершившийся при вызове, даёт ошибку `module_exited`, следующий процесс успешно выполняет действие;
  - отмена зависшего процесса возвращает `cancelled` меньше чем за 2 с, процесс исчезает из `/proc`;
  - поздний ответ после таймаута пропускается по id, следующее рукопожатие успешно.
- `make lint` — Clippy без предупреждений, `make fmt` — без изменений.

Пользователь подтвердил работу прототипа после изменений; автоматические проверки invoke пройдены.
