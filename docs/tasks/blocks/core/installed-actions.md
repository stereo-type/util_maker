# Обновлять реестр действий из каталога активных пакетов

**Статус** — 👁️ На ревью

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/core/README.md)

Подключить существующие `Registry` и `ActionRef` к каталогу пакетов. Дать оболочке единый интерфейс перечисления и вызова действий по стабильной паре ID.

**Зависимости для старта** — [Установить проверенный пакет в профиль пользователя](../packages/install-package.md).

## Критерии приёмки

- [x] Добавление и отключение пакета меняют доступные действия без перезапуска. Чтение меню не запускает процессы.
- [x] Вызов выбирает исполняемый файл активной версии. Уже начатый вызов сохраняет свою версию до завершения. Менеджер пакетов может определить, когда безопасно переключать версию.
- [x] Отключённый пакет и исчезнувшее действие дают понятную ошибку. Контрольный модуль и пакет с незнакомым ID проходят один маршрут.
- [x] Отключение доступно по ID любого включённого плагина, в том числе исправного. С момента отключения ядро отклоняет новые вызовы, активному вызову передаёт отмену и завершает его по обычным правилам. Повтор команды безопасен. После перезапуска плагин остаётся отключённым до явного включения.

## Что сделано

- `Registry` хранит модули под `RwLock`, поэтому каталог можно заменить без перезапуска. `replace_packages` принимает `ModuleEntry` с активной версией, точкой входа и признаком включения; уже начатый вызов работает со снимком старой версии.
- `actions()` отдаёт действия для меню без запуска процессов, `all_actions()` — включая отключённые. `set_enabled` по ID освобождает/возвращает пакет, отменяет активные вызовы и сохраняет отключённое состояние в JSON рядом с профилем.
- Появились `ActionListing`, `InvokeOutcome.moduleVersion/cold`, `ModuleEntry::new`, `with_arguments`, `Registry::active_calls/can_switch/cancel_all`.
- Ошибки `module_disabled`, `module_not_found` и `action_unavailable` приходят до запуска процесса.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make check` — 106 тестов, Clippy и rustfmt без замечаний.
- `cargo test -p util-maker-core --test installed_actions` — 5/5:
  - каталог отдаёт действия двух модулей без запуска процессов, оба вызываются по разным ID;
  - начатый вызов сохраняет версию `1.0.0`, после замены каталога на `2.0.0` новый вызов увидит новую версию, а `can_switch` станет истинным только после завершения;
  - отключение во время `hang` отменяет вызов, повтор идемпотентен, новый вызов отклоняется;
  - после повторного открытия реестра с тем же файлом состояния пакет остаётся отключённым;
  - неизвестный модуль и исчезнувшее действие дают разные машинные категории до spawn.
