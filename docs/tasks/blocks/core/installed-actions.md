# Обновлять реестр действий из каталога активных пакетов

**Статус** — 🛠️ В работе

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/core/README.md)

Подключить существующие `Registry` и `ActionRef` к каталогу пакетов. Дать оболочке единый интерфейс перечисления и вызова действий по стабильной паре ID.

**Зависимости для старта** — [Установить проверенный пакет в профиль пользователя](../packages/install-package.md).

## Критерии приёмки

- [ ] Добавление и отключение пакета меняют доступные действия без перезапуска. Чтение меню не запускает процессы.
- [ ] Вызов выбирает исполняемый файл активной версии. Уже начатый вызов сохраняет свою версию до завершения. Менеджер пакетов может определить, когда безопасно переключать версию.
- [ ] Отключённый пакет и исчезнувшее действие дают понятную ошибку. Контрольный модуль и пакет с незнакомым ID проходят один маршрут.
- [ ] Отключение доступно по ID любого включённого плагина, в том числе исправного. С момента отключения ядро отклоняет новые вызовы, активному вызову передаёт отмену и завершает его по обычным правилам. Повтор команды безопасен. После перезапуска плагин остаётся отключённым до явного включения.

## Проверка

На Linux через `make test` вызвать два тестовых процесса по разным ID, обновить снимок каталога и проверить маршрут повторного вызова.
