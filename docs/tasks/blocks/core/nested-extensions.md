# Подключать и вызывать плагины-расширения микроприложений

**Статус** — 📥 К выполнению

[ТЗ ядра](../../../blocks/core/README.md) · [Контракт плагинов-расширений](../../../blocks/core/extensions.md) · [ТЗ SDK](../../../blocks/sdk/README.md)

Расширить реестр ядра: связать установленные пакеты-расширения с точками
родителя, хранить выбор активного плагина и маршрутизировать вызовы родителя
в дочерний процесс. Родитель не должен знать путь к чужому исполняемому файлу
и не должен иметь возможности обойти выбор пользователя.

**Зависимости для старта** — [Описать контракт плагинов-расширений в манифесте и SDK](../sdk/extension-manifest.md).

**Для сквозной проверки** — [Показывать плагины-расширения на странице микроприложения](../desktop/extension-packages-ui.md), [Перевести переводчик на провайдеров-плагинов](../plugins/translator/provider-extension-point.md).

## Критерии приёмки

- [ ] `HOST_API_VERSION` поднят до `1.1.0`; пакеты расширений с прежним диапазоном `hostApi` отклоняются, а обычные пакеты на `1.0.x` продолжают работать.
- [ ] Реестр строит индекс вкладов из активных манифестов и не запускает процессы при чтении. Вклад активен только при наличии включённого родителя, совпадающего контракта и совместимой версии.
- [ ] Публичный API ядра позволяет прочитать и изменить выбор для точки `single` с проверкой родителя и вклада. Выбор сохраняется по `moduleId + pointId` и переживает перезапуск. Без явного выбора единственный доступный вклад выбирается автоматически; при нескольких доступных вкладах возвращается `EXTENSION_NOT_SELECTED`.
- [ ] Отключение, удаление или несовместимость выбранного плагина не стирает сохранённый ID; при восстановлении плагина прежний выбор снова действует. Отключение родителя скрывает точку и вклады, но сохраняет дочерние пакеты.
- [ ] `extensions.list` возвращает только точки вызвавшего родителя и доступные вклады без запуска процессов. `extension.invoke` принимает только точку родителя и только активный совместимый вклад.
- [ ] Дочерний процесс запускается со своими возможностями, настройками и секретами. Возможности родителя не наследуются, чужие секреты недоступны, локальный идентификатор вызова и связь с родительским вызовом попадают в журнал.
- [ ] Отмена родителя отменяет дочерний вызов; таймаут, падение и нарушение протокола плагина дают `EXTENSION_FAILED` с ID плагина и не ломают родителя, другие вызовы и трей.
- [ ] Поздний ответ завершённого дочернего вызова игнорируется, его процесс и закреплённые ресурсы освобождаются. Активный вызов не даёт переключить версию плагина.
- [ ] Пакет-расширение без действий не появляется в меню трея и общем списке действий.

## Проверка

Linux: `make check`, тесты `util-maker-core` с тестовым родителем и
`fixture-extension`:

- выбор одного и нескольких вкладов, сохранение и восстановление выбора;
- отказ вкладу без родителя, с чужим контрактом и несовместимой версией;
- вызов только активного плагина и отказ обхода выбора;
- изоляция настроек и секретов родителя и ребёнка;
- отмена, таймаут, падение и поздний ответ дочернего процесса;
- обновление и удаление плагина во время активного вызова.

Windows: отдельных действий для этой карточки нет; сквозной сценарий с
переводчиком проверяется в карточке провайдеров.
