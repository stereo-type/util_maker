# Сохранять привязки всех действий при изменении состава пакетов

**Статус** — 📥 К выполнению

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/core/hotkeys.md)

Реализовать постоянное хранилище для существующего `HotkeyRegistry`. Привязка принадлежит `moduleId + actionId`, включая отключённые и временно недоступные действия. Проверять на подменном каталоге и адаптере регистрации.

**Зависимости для старта** — можно начинать на текущей ревизии.

**Для сквозной проверки** — [Обновлять реестр действий из каталога активных пакетов](installed-actions.md).

## Критерии приёмки

- [ ] При первом чтении настроек прототипа сохраняется пользовательская комбинация контрольного модуля. После перезапуска восстанавливаются все назначения, включая несколько сочетаний одного действия.
- [ ] Отключение освобождает регистрации, удаление действия при обновлении помечает привязку недоступной, возврат того же ID позволяет её восстановить. Рекомендация нового пакета не забирает чужое сочетание.
- [ ] При устаревшем подтверждении, отказе ОС или записи прежняя рабочая привязка сохраняется. Перенос меняет только выбранное сочетание.

## Проверка

На Linux через `make test` прогнать перенос, отключение, изменение списка действий и повторное открытие хранилища, в том числе на старом формате настроек.
