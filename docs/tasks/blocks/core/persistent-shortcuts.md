# Сохранять привязки всех действий при изменении состава пакетов

**Статус** — 👁️ На ревью

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/core/hotkeys.md)

Реализовать постоянное хранилище для существующего `HotkeyRegistry`. Привязка принадлежит `moduleId + actionId`, включая отключённые и временно недоступные действия. Проверять на подменном каталоге и адаптере регистрации.

**Зависимости для старта** — можно начинать на текущей ревизии.

**Для сквозной проверки** — [Обновлять реестр действий из каталога активных пакетов](installed-actions.md).

## Критерии приёмки

- [x] При первом чтении настроек прототипа сохраняется пользовательская комбинация контрольного модуля. После перезапуска восстанавливаются все назначения, включая несколько сочетаний одного действия.
- [x] Отключение освобождает регистрации, удаление действия при обновлении помечает привязку недоступной, возврат того же ID позволяет её восстановить. Рекомендация нового пакета не забирает чужое сочетание.
- [x] При устаревшем подтверждении, отказе ОС или записи прежняя рабочая привязка сохраняется. Перенос меняет только выбранное сочетание.

## Что сделано

- `JsonHotkeyStore` пишет массив `AssignmentRecord` атомарной заменой файла и читает старый объект прототипа с `shortcut`, `hotkey` или `combo`.
- В `AssignmentRecord`/`Owner` добавлены `available` и `registration_error`. `HotkeyRegistry::restore` регистрирует доступные привязки после старта и сохраняет причину отказа.
- `sync_actions` принимает `ActionAvailability`: отключённый модуль освобождает регистрации, исчезнувшее действие становится недоступным, возврат ID восстанавливает привязку. `set_module_enabled` делает то же по ID модуля.
- Перенос по-прежнему меняет только выбранное сочетание; устаревшее подтверждение, отказ регистрации и ошибка записи откатывают состояние.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `cargo test -p util-maker-core --test persistent_shortcuts` — 4/4:
  - старый `{"shortcut":"Ctrl+Shift+U"}` преобразуется в запись контрольного модуля, после добавления второго сочетания оба восстанавливаются из файла;
  - отключение модуля освобождает регистрацию, включение возвращает её;
  - удаление действия оставляет запись недоступной, возврат действия снова регистрирует её;
  - занятое сочетание сохраняется с причиной и успешно регистрируется после освобождения; рекомендация нового пакета не забирает чужое сочетание.
- `make check` — 106 тестов, Clippy и rustfmt без замечаний.
