# Изолировать необработанную ошибку плагина и сообщить о сбое оболочке

**Статус** — 📥 К выполнению

[Этап 4 плана развития](../../../roadmap.md#4-принять-первую-поставку-windows) · [ТЗ ядра](../../../blocks/core/README.md) · [Правила диагностики](../../../blocks/core/diagnostics.md)

Довести существующую обработку ошибок в `ModuleProcess` до публичного маршрута вызова через `Registry`. Оболочке нужно знать, какой именно плагин завершился, чтобы показать пользователю причину и предложить отключить его. Ядро определяет наблюдаемый исход по IPC и состоянию дочернего процесса. Исключение внутри чужого процесса может завершить его до отправки ответа.

**Зависимости для старта** — можно начинать на текущей ревизии с `fixture-module` и контрольным плагином.

## Критерии приёмки

- [ ] Аварийный выход при инициализации или во время действия и внутренняя ошибка, о которой плагин успел сообщить по RPC, дают по одному конечному исходу на вызов. В оболочку приходят ID модуля и действия, машинная категория и понятная причина в пределах сведений хоста. Отмена пользователем и ожидаемая прикладная ошибка различимы со сбоем процесса.
- [ ] При двух активных плагинах падение первого освобождает ресурсы его вызова. Второй продолжает отвечать. Хост остаётся в трее, а следующий явный вызов первого плагина возможен, пока пользователь его не отключил.
- [ ] Сообщение оболочке позволяет однозначно адресовать отключение сбойному модулю даже при поступлении результата другого вызова. Текст исключения, необработанный stderr, содержимое выделения и ключи не попадают в сообщение пользователю или журнал.

## Проверка

На Linux через `make test` дополнить [проверки IPC](../../../../crates/core/tests/host_invoke.rs) сценарием с двумя плагинами через реестр. Воспроизвести исключение до ответа, ошибку, возвращённую по протоколу, и штатную отмену. Проверить, какой модуль указан в каждом исходе, и вызвать исправный плагин во время сбоя. На Windows пользователь проверяет сообщение и действие «Отключить плагин» по [карточке desktop](../desktop/package-management.md).
