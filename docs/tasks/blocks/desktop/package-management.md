# Управлять локальными пакетами из настроек

Подключить команды установки, обновления, отката, включения, отключения и удаления к менеджеру пакетов. Заменить прототипный переключатель `set_plugin_enabled`, который сейчас управляет паузой шорткея контрольного модуля, командой для конкретного ID. Её используют и переключатель в настройках, и кнопка в сообщении о сбое. Добавить регистрацию доверенного открытого ключа с показом отпечатка.

## Критерии приёмки

- [ ] Выбор файла показывает имя, версию, издателя, совместимость и возможности до подтверждения. Отмена сохраняет текущую установку. Для нового издателя пользователь может явно подтвердить отпечаток ключа.
- [ ] Успешное обновление и откат видны в списке и применяются к следующему вызову. Ошибка проверки оставляет рабочий пакет и показывает причину.
- [ ] На странице исправного плагина пользователь может выключить его в любой момент. Статус меняется после успешного отключения. Действия исчезают из меню трея, его глобальные сочетания освобождаются. Второй плагин и общая пауза сохраняют своё состояние.
- [ ] После перезапуска плагин остаётся отключённым. При повторном включении доступны прежние настройки и свободные привязки. Если сочетание за это время заняла другая программа, интерфейс показывает причину.
- [ ] При необработанной ошибке из трея или по шорткею сообщение называет плагин, действие и причину. «Отключить плагин» отключает именно указанный модуль. Если закрыть сообщение, плагин остаётся включённым и вызов можно повторить. При ошибке сохранения интерфейс показывает фактическое состояние и причину отказа.
- [ ] Удаление освобождает назначения и инициирует очистку секретов этого модуля. Повтор операции безопасен.

## Проверка

На Linux проверить команды оболочки с тестовым каталогом и хранилищем секретов. Пользователь на Windows импортирует две версии, откатывает и удаляет пакет. На двух установленных плагинах отдельно проверить отключение исправного из настроек и сбойного из сообщения. В обоих случаях вызвать второй плагин, перезапустить хост и снова включить первый.

## Что уже сделано

- `PackageManager` в desktop: проверка, установка, публикация в каталог, откат, удаление.
- Интерфейс: путь к `.umpkg`, издатель, ключ, проверка, отпечаток SHA-256, установка, откат и удаление.
- Доверенные ключи сохраняются в `trusted-keys.json`.
- Отключение и удаление контрольного плагина освобождают сочетание; после перезапуска отключённое состояние сохраняется.
- В сообщении о сбое есть кнопка «Отключить плагин».

## Что осталось

- Освобождение привязок для произвольных плагинов через общий реестр сочетаний.
- Проверка внешнего конфликта при повторном включении.
- Очистка секретов при удалении.

## Проверка

Linux: Clippy, сборка, JavaScript, тесты пакетов.

Windows: перетащить `.umpkg`, проверить отпечаток и подтвердить; установить, откатить, удалить; отключить плагин из карточки и из сообщения о сбое; перезапустить хост; включить обратно и проверить свободное/занятое сочетание.
