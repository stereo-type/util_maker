# Показывать иконку контрольного плагина в настройках

**Статус** — ✅ Выполнена

[Этап 2 плана развития](../../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · замечание к [«Строить трей и список микроприложений по манифестам»](action-menu.md)

## Наблюдение

В списке и на странице контрольного модуля нет иконки. В манифесте плагина указано
`"icon": "assets/icon.png"`, но установщик копирует только `control-module.exe` и
`manifest.json`; файл иконки в каталог установки не попадает.

## Критерии приёмки

- [ ] Иконка из манифеста видна в списке микроприложений и на странице модуля.
- [ ] Установщик копирует файл иконки по пути, указанному в манифесте.
- [ ] Если иконка отсутствует или повреждена, показывается нейтральная заглушка, интерфейс не ломается.
- [ ] Иконка не требует чтения произвольных путей из JavaScript.

## Зависимости

- [Строить трей и список микроприложений по активным манифестам](action-menu.md).

## Что сделано

- Установщик копирует `assets/icon.png` в каталог контрольного модуля рядом с `manifest.json`.
- `collect_plugins` уже читает иконку по пути из манифеста и передаёт её в интерфейс как data URL.

## Проверка

Linux: `make build-windows` собирает установщик. Визуальная проверка — на Windows.
