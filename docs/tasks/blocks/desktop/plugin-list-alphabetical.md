# Сортировать микроприложения по алфавиту в настройках и трее

**Статус** — 📥 К выполнению

[ТЗ блока](../../../blocks/desktop/README.md) · [Интерфейс и настройки](../../../blocks/desktop/settings.md)

## Наблюдение

В настройках список микроприложений идёт в порядке ID пакетов: «Пипетка цвета» (`org.utilmaker.color-picker`), «Контрольный модуль» (`org.utilmaker.control`), «Скриншоты» (`org.utilmaker.screenshot`), «Переводчик» (`org.utilmaker.translator`). В меню трея пункты идут в том же порядке. По видимым названиям это не алфавит: «Пипетка цвета» оказывается выше «Контрольного модуля», а «Скриншоты» — выше «Переводчика».

Порядок задаёт `Registry` в `crates/core/src/registry.rs`: модули хранятся в `BTreeMap` по ID, а `modules()` и `actions()` возвращают значения в этом порядке. `collect_plugins` (`apps/desktop/src/main.rs`) и `rebuild_tray_menu` это перечисление не сортируют, в интерфейсе сортировки тоже нет. Поэтому порядок зависит от ID, а не от имени, и меняется при добавлении пакета.

## Ожидаемое поведение

1. Список микроприложений в настройках и пункты действий в трее идут по алфавиту отображаемых имён (`manifest.name`) без учёта регистра.
2. Оба списка показывают одинаковый порядок модулей. Для текущей поставки: «Контрольный модуль», «Переводчик», «Пипетка цвета», «Скриншоты».
3. При совпадении имён порядок детерминирован: сравнивается ID.
4. Отключённый пакет остаётся на своём месте в настройках; в трее его пунктов нет, но остальные не сдвигаются.
5. Действия внутри одного микроприложения в трее сохраняют порядок манифеста.
6. Порядок не зависит от установки, обновления и перезапуска: тестовый пакет с именем на «А» встаёт первым, с именем на «Я» — последним.
7. Сравнение русских названий алфавитное: «ё» идёт после «е», регистр не влияет.

## Критерии приёмки

- [ ] В настройках порядок: «Контрольный модуль», «Переводчик», «Пипетка цвета», «Скриншоты».
- [ ] В трее пункты действий в том же порядке; формат подписи «модуль — действие» не меняется.
- [ ] Тестовый пакет с именем на «А» появляется первым, с именем на «Я» — последним в обоих списках, без перезапуска.
- [ ] Отключение и включение пакета не меняют позиции; отключённый остаётся в настройках на своём месте.
- [ ] Порядок одинаков после перезапуска и после обновления пакета; регистр имени не влияет.
- [ ] Оба списка используют один общий порядок, без второй независимой сортировки в интерфейсе.
- [ ] `make check` проходит, добавлен тест на порядок модулей и действий.

## Зависимости

**Для старта** — можно начинать на текущей ревизии.

**Для сквозной проверки** — Windows-сборка: настройки и трей. Отдельных карточек не требуется.

## Как проверять

Linux, контейнер `util-maker-dev:local`:

- `make check` — сборка, rustfmt, Clippy, тесты.
- Новый тест реестра: модули с именами вразброс и разным регистром возвращаются по алфавиту; при совпадении имён — по ID.
- Тест меню: `actions()` идёт по именам модулей, действия внутри модуля — в порядке манифеста.

Windows: `make build-windows`, установить сборку, открыть настройки и трей. Ожидаемо: «Контрольный модуль», «Переводчик», «Пипетка цвета», «Скриншоты» в обоих местах. Добавить манифест с именем на «А» и проверить, что пакет встал первым в обоих списках.
