# Открывать настройки микроприложения в модальном окне

**Статус** — 📥 К выполнению

**Основание** — [Настройки desktop](../../../blocks/desktop/settings.md) · [Страницы микроприложений](../микроприложения-страницы.md)

## Наблюдение

Сейчас кнопка «Открыть» разворачивает карточку микроприложения прямо в общем
списке. Настройки, действия и форма плагина появляются ниже списка, страница
удлиняется и прокручивается. Пользователю неочевидно, что открылась отдельная
страница: визуально это продолжение списка, а не окно настроек.

## Ожидаемое поведение

- «Открыть» показывает настройки выбранного микроприложения в модальном окне
  поверх списка.
- В окне один заголовок с названием, версией и состоянием; ниже — действия,
  сочетания и настройки.
- Закрытие по Esc, кнопке «Закрыть» и клику по затемнённому фону возвращает к
  списку без изменения прокрутки.
- Фокус остаётся внутри модального окна; после закрытия возвращается на кнопку
  «Открыть» этого плагина.
- Одновременно открыто не больше одного окна настроек.
- На узком экране окно прокручивается внутри, а не растягивает страницу.

## Критерии приёмки

- [ ] Настройки плагина открываются в модальном окне, а не inline.
- [ ] Список и общий экран не меняют высоту и положение прокрутки.
- [ ] Esc/фон/кнопка закрывают окно; фокус возвращается на исходную кнопку.
- [ ] Tab не выходит за пределы окна.
- [ ] Название, версия и состояние показаны один раз.
- [ ] Действия, редактор сочетания и форма настроек работают внутри окна.
- [ ] Ошибки и результат действия видны внутри модального окна.
- [ ] На 100/150/200 % и в светлой/тёмной теме окно остаётся читаемым.

## Проверка

Linux: разметка, фокус, Esc, отсутствие скачка прокрутки.

Windows: открыть контрольный модуль, переводчик и скриншоты; изменить
сочетание и настройки, закрыть окно, убедиться, что список остался на месте.
