# Показывать и сохранять настройки плагина по схеме манифеста

**Статус** — ✅ Выполнена

[Этап 3 плана развития](../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../blocks/desktop/settings.md)

Построить общий экран из схемы активного пакета. Подключить сохранение параметров и команду формы к нужному модулю. Разрабатывать на тестовом манифесте со списками, секретным полем и командой.

**Зависимости для старта** — [Описать пользовательские настройки и команды формы в манифесте](../sdk/module-settings.md), [Строить трей и список микроприложений по активным манифестам](action-menu.md).

**Для сквозной проверки** — [Исполнять запросы возможностей только в контексте активного вызова](../core/capability-dispatch.md), [Хранить секреты профилей в системном хранилище Windows](../platform/windows/profile-secrets.md).

## Критерии приёмки

- [ ] Доступны значения по умолчанию, редактирование и ошибки валидации у поля. После закрытия и повторного открытия окна сохраняются выбранные значения.
- [ ] Для секретного поля видно наличие ключа, замена идёт в хранилище ОС. Команда формы адресуется её модулю и показывает состояние и результат.
- [ ] Статус «Нужна настройка» открывает нужный профиль. Работа формы для нового ID не требует добавления специального случая в desktop.

## Проверка

На Linux проверить команды чтения/сохранения на подменном хранилище. На Windows пользователь открывает страницу тестового пакета, меняет параметры и вызывает команду формы.

## Что уже сделано

- `PluginDto` передаёт схему настроек из манифеста.
- Desktop читает и атомарно сохраняет значения в `<данные>/plugin-settings/<id>.json`.
- Интерфейс строит поля text/number/boolean/select/secret из схемы, включая профили, и сохраняет значения.
- Секретные поля не записываются в JSON настроек.

## Что осталось

- Отображение факта сохранённого секрета и запись в системное хранилище.
- Команды формы и адресация конкретному модулю.
- Открытие нужного профиля по статусу «Нужна настройка».

## Итог

- Значения по умолчанию, редактирование, обязательные поля и сохранение в `<данные>/plugin-settings/<id>.json`.
- Секретные поля не попадают в JSON: наличие проверяется, значение пишется в DPAPI.
- Команды формы из манифеста выполняются отдельным процессом через `command`; ошибки полей показываются пользователю.
- Форма строится для любого ID без специальных случаев.

## Проверка

Linux: Clippy, JavaScript, сборка. Windows: открыть страницу плагина со схемой, сохранить значения, записать ключ, перезапустить и выполнить команду проверки.
