# Менять иконку трея по состоянию: работа и пауза

**Статус** — ✅ Выполнена

**Основание** — [Трей и состояние](../desktop/action-menu.md) · [Пауза сочетаний](../../blocks/core/hotkeys.md)

## Ожидаемое поведение

- У иконки трея только два состояния: работа — зелёный «play», пауза — жёлтый «pause».
- Третьего цвета нет: синяя иконка при старте не показывается.
- Подсказка трея и пункт «Пауза/Возобновить» совпадают с состоянием.
- Смена состояния обновляет иконку сразу, без перезапуска.
- После перезапуска иконка соответствует сохранённому состоянию паузы.

## Критерии приёмки

- [x] Иконка зелёная с «play» в работе и жёлтая с «pause» в паузе; третьего состояния нет.
- [x] Смена через трей и через настройки обновляет иконку.
- [x] Подсказка содержит состояние; при недоступном сочетании причина указана текстом, без отдельного цвета иконки.
- [x] После перезапуска состояние и иконка согласованы.

## Что сделано

- `scripts/make-icons.py` в стиле «Пастель» рисует только две иконки трея: `tray-working.png` — зелёная плитка с «play», `tray-paused.png` — жёлтая плитка с «pause». Отдельные синяя, жёлтая и красная статусные иконки (`status-*.png`) удалены из assets и генератора.
- Трей получает иконку и подсказку из одного состояния: работа, пауза или недоступное сочетание. Начальная иконка создаётся уже по сохранённому состоянию, без вспышки чужого цвета.
- Пункт меню называется «Пауза сочетания» в работе и «Возобновить сочетание» на паузе. После переключения меню пересобирается.
- Пауза сохраняется в `prototype-state.json`. При старте она применяется до регистрации сочетаний, а `sync_action_hotkeys` на паузе только заполняет карту и не захватывает клавиши.
- Отключение и включение контрольного пакета в настройках останавливает и восстанавливает все сохранённые сочетания, а не только основное.

## Проверка

Linux: `make check` — rustfmt, Clippy и все тесты workspace прошли. Тест `tray_visual_switches_icon_and_tooltip_by_state` проверяет, что работа и недоступное сочетание дают одну зелёную иконку, пауза — жёлтую, а причина недоступности остаётся в подсказке. Проверена обратная совместимость `paused` в сохранённом JSON.

Windows: 0.4.30 — проверены жёлтая иконка и подсказка «на паузе», зелёная после возобновления; пауза даёт 0 вызовов, возобновление возвращает сочетание.

Синяя иконка при старте была остатком третьего состояния: трей брал `status-active.png`, пока сочетание ещё не зарегистрировано. Теперь иконка выбирается только по паузе, поэтому при старте сразу показывается зелёный «play», а причина недоступного сочетания пишется в подсказку.

Windows 0.4.35: пользователь подтвердил — старт без паузы даёт зелёный «play», пауза — жёлтый «pause», возобновление снова зелёное, перезапуск в паузе остаётся жёлтым, подсказка «на паузе», сочетание не срабатывает.
