# Удалять каталог установки полностью при удалении приложения

**Статус** — 👁️ На ревью

**Основание** — [Установка Windows](../../../../installer/README.txt)

## Наблюдение

После удаления приложения остаётся каталог `D:\Util Maker` с файлами.
Пользователь ожидает полное удаление установленных файлов.

## Ожидаемое поведение

- Деинсталлятор удаляет exe, `modules`, `packages`, `scripts`, `logs`,
  `README.txt`, `uninstall.exe` и сам каталог установки, если в нём не осталось
  пользовательских файлов.
- Профиль `%LOCALAPPDATA%\org.utilmaker.prototype` не удаляется без отдельного
  подтверждения (текущая политика).
- Если каталог занят или содержит посторонние файлы, показывается причина.
- Повторный запуск деинсталлятора безопасен.

## Критерии проверки

- [ ] После удаления `D:\Util Maker` отсутствует.
- [ ] Не осталось exe, manifests, packages, scripts, logs.
- [ ] Пользовательский профиль сохранён.
- [ ] Удаление с занятым файлом показывает понятную ошибку.

## Что сделано

- Деинсталлятор сначала завершает всё приложение: `taskkill /F /T /IM util-maker-desktop.exe` убивает хост вместе с дочерними процессами, дополнительно завершаются `control-module`, `screenshot-plugin`, `translator-module`, `color-picker-module`, `qr-code-module` и `screen-ocr-module`. Только после этого удаляются ярлыки и каталоги `modules`, `packages`, `scripts`, `logs`.
- `util-maker-desktop.exe` удаляется с повторами: Windows отпускает файл не сразу после `taskkill`. Если за 20 попыток (по 300 мс) удалить не удалось, файл помечается `Delete /REBOOTOK`, а пользователь видит сообщение, что он исчезнет после перезагрузки. Затем удаляются `README.txt`, `uninstall.exe` и сам `$INSTDIR`, если не осталось посторонних файлов.
- Журнал в резервном пути `%LOCALAPPDATA%\Util Maker\logs` удаляется и при нестандартном каталоге установки.
- Если каталог занят или в нём остались файлы, показывается окно с путём и списком оставшихся элементов, а также рекомендацией закрыть приложение и проверить права.
- Профиль `%LOCALAPPDATA%\org.utilmaker.prototype` не затрагивается. Записи автозапуска и реестра удаления очищаются.
- Инструкция `installer/README.txt` и сценарий проверки Windows обновлены под новую политику: журнал удаляется, профиль остаётся.

## Проверка

Windows: установить, удалить через «Приложения», проверить каталог и профиль.

0.4.29: установка во временный каталог и удаление — каталог полностью исчез.

Linux: `makensis` собрал тестовый установщик из `installer/util-maker.nsi` со stub-файлами без ошибок.

После слияния: деинсталлятор завершает `util-maker-desktop.exe` и `control-module.exe`, удаляет каталоги и файлы, а если что-то осталось — показывает список.

После сообщения пользователя (удаление при работающем приложении оставляло exe): завершение переведено на дерево процессов `/T`, добавлены остальные модули, а удаление exe повторяется с паузой и резервной пометкой `/REBOOTOK`. Проверка на Linux: `makensis` собирает установщик со stub-файлами без ошибок. Требуется проверка Windows: удаление при работающем приложении — каталог исчезает целиком, без exe; и отдельно — с посторонним файлом, где показывается список.
