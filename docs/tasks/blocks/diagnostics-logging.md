# Записать сбой действия без пользовательских данных

**Статус** — Выполнена

**Основание** — [ТЗ блока «Диагностика»](../../blocks/diagnostics.md).

Реализовать структурированный локальный журнал с ротацией. Проверку выполнить на искусственных ошибках IPC и HTTP с контрольными значениями.

## Критерии приёмки

- [x] По записи можно определить версию, модуль, действие, длительность и код ошибки.
- [x] Ключ, заголовок авторизации, URL с секретом, исходный текст, перевод и данные буфера отсутствуют в сформированном журнале.
- [x] При достижении настроенного порога файл ротируется, следующее событие доступно в текущем журнале.

## Что сделано

- `crates/core/src/diagnostics.rs` — `DiagnosticsLog`: JSON-строка на событие в `util-maker.jsonl`, текущий файл и один архив `util-maker.jsonl.1`, порог задаётся в байтах.
- `LogEntry` содержит только служебные поля: время, версия приложения, ID модуля и действия, длительность, исход и код ошибки. Полей для исходного текста, перевода, снимка и буфера в структуре нет.
- `sanitize` скрывает сообщение целиком при упоминании заголовка авторизации (`Authorization`, `Api-Key`, `api_key`), удаляет параметры URL и значения `key=`, `token=`, `secret=`.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make test` — 36 тестов пройдено, в том числе 4 теста журнала:
  - запись содержит версию, модуль, действие, длительность и код ошибки;
  - сообщение с `Authorization: Api-Key secret-key-123`, URL с ключом и контрольной фразой не оставляет в файле ни ключа, ни текста, ни заголовка;
  - параметры URL удаляются и без заголовка авторизации;
  - при пороге 260 байт создаётся архив, а последнее событие остаётся в текущем журнале.
- `make lint` — Clippy без предупреждений, `make fmt` — без изменений.

Подключение журнала к общим настройкам и к записям HTTP-адаптеров выполняется в задачах интерфейса и провайдеров.

Пользователь подтвердил работу прототипа после изменений; автоматические проверки журнала пройдены.
