# Устанавливать пакеты поставки при первом запуске

**Статус** — ✅ Выполнена

**Основание** — [Упаковка в установщик](../../windows-distribution.md) · [Менеджер пакетов](../../../blocks/packages/README.md)

## Наблюдение

На Windows 0.4.5 в каталоге установки лежат `packages\*.umpkg` и
`packages\org.utilmaker-public.json`, но после запуска установлен только
контрольный модуль. В журнале:

```text
пакетная поставка: ключ поставки: missing field `public_key` at line 4 column 1
```

`org.utilmaker-public.json` содержит поле `publicKey`, а структура
`BundledPublicKey` в `apps/desktop/src/main.rs` ожидает `public_key`.

## Ожидаемое поведение

- При первом запуске «Скриншоты» и «Переводчик» устанавливаются из подписанных
  `.umpkg`.
- В трее и настройках доступны три микроприложения.
- Повторный запуск не переустанавливает пакеты.
- Открытый ключ читается из JSON независимо от стиля полей.

## Критерии приёмки

- [ ] `BundledPublicKey` читает `publicKey` и `publisher` из файла поставки.
- [ ] Первый запуск устанавливает оба пакета и публикует их в каталог модулей.
- [ ] В журнале нет ошибки `missing field public_key`.
- [ ] Повторный запуск не создаёт дублей и не сбрасывает настройки.

## Проверка

Windows: удалить профиль пакетов/маркер, запустить установщик, проверить три
модуля и журнал.

0.4.6: после установки в `modules` появились screenshot/translator 0.4.6, маркер `bundled-packages-v1` создан; ошибка `public_key` исчезла.
