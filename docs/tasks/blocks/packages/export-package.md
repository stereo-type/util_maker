# Экспортировать подписанный пакет .umpkg

**Статус** — 👁️ На ревью

[Этап 1 плана развития](../../../roadmap.md#1-подготовить-два-исполняемых-плагина-и-экспорт-пакетов)

**Основание** — [ТЗ менеджера пакетов](../../../blocks/packages/README.md) и [формат .umpkg](../../../blocks/packages/package-format.md).

Разработчик может собрать из подготовленного каталога плагина, включая собранную точку входа, архив для передачи пользователю. Архив должен приниматься существующим проверяющим кодом. Экспорт работает без запуска хоста и установки пакета.

**Зависимости для старта** — существующие парсер манифеста и проверка пакета. Для приёмки использовать временный ключ и подготовленный каталог с манифестом контрольного плагина. Можно начать до появления процессов штатных плагинов.

## Критерии приёмки

- [x] В [инструкции по формату](../../../blocks/packages/package-format.md) описана цель Makefile для экспорта с исходным каталогом, выходным файлом и способом передачи ключа издателя. Закрытый ключ остаётся за пределами пакета и журнала.
- [x] Экспорт добавляет хеши SHA-256 полезной нагрузки в манифест и подписывает итоговые байты Ed25519. Существующая проверка принимает архив с соответствующим доверенным ключом и возвращает ожидаемые ID, версию и точку входа.
- [x] Отсутствующая точка входа и попытка включить файл вне исходного каталога приводят к отказу. При неудачном экспорте ранее созданный выходной файл остаётся пригодным к проверке.
- [x] Проверки выполняются на Linux. Установка архива и подключение команды к desktop-интерфейсу могут разрабатываться отдельно.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make check` — 111 тестов, Clippy и rustfmt без замечаний.
- `cargo test -p util-maker-packages` — 14/14; среди них:
  - экспорт с хешами и Ed25519 возвращает ожидаемые ID, версию и точку входа;
  - отсутствующая точка входа не заменяет прежний пакет, а прежний файл после отказа проходит `verify_path`;
  - символическая ссылка на файл вне исходного каталога и выходной файл внутри источника отклоняются;
  - ключ внутри исходного каталога и выход, совпадающий с ключом, отклоняются.
- `make control-samples` — собраны и проверены `control-0.4.1-linux-x64.umpkg` и `control-0.5.0-linux-x64.umpkg`.
- `make package-export PACKAGE_SOURCE=... PACKAGE_MANIFEST=... PACKAGE_OUTPUT=... PACKAGE_PRIVATE_KEY=... PACKAGE_VERSION=0.4.1 PACKAGE_PLATFORM=linux-x64` — создан пакет; `verify` вернул `org.utilmaker.control`, `0.4.1`, `control-module`.
- `unzip -l` созданного пакета: только `manifest.json`, `signature.ed25519`, `assets/icon.png` и `control-module`; закрытого ключа в архиве нет, JSON экспорта содержит только путь пакета, SHA-256, ID, версию, точку входа и размеры.
- Попытка экспорта с ключом внутри `PACKAGE_SOURCE` завершилась ошибкой «закрытый ключ не должен находиться внутри каталога пакета»; выходной файл не создан.
- `make example-package` — подписанный пример `com.example.echo` собран и проверен существующим `verify`.

Установка архива и команда desktop-интерфейса остаются в отдельных карточках. Ручная проверка Windows для этой карточки не требуется: критерии ограничены Linux-экспортом и проверяющим кодом.

Ревизия для проверки — ``26b3c1d``.
