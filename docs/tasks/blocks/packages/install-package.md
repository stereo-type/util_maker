# Установить проверенный пакет в профиль пользователя

**Статус** — 👁️ На ревью

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/packages/README.md)

Расширить `crates/packages`: после предварительного просмотра и подтверждения сохранить подписанное содержимое в каталог версии и опубликовать активную запись. Начать можно с уже используемых в тестах подписанных архивов.

**Зависимости для старта** — можно начинать на текущей ревизии.

**Для сквозной проверки** — [Экспортировать подписанный пакет .umpkg](export-package.md).

## Критерии приёмки

- [x] На чистом профиле после установки и повторного открытия хранилища доступны ID, версия, манифест, состояние и путь к исполняемому файлу. Чтение каталога не запускает модуль.
- [x] Существующая проверка подписи, издателя, API, платформы и путей применяется к тем же байтам, которые распаковываются. Повреждение или ошибка записи не публикует частичную установку.
- [x] Повторная установка тех же байтов даёт одну запись. Попытка заменить уже известный ID другим издателем отклоняется.

## Что сделано

- `crates/packages/src/install.rs` — `PackageStore` с профилем `installed.json` и каталогами `<id>/<версия>/`. Пакет читается один раз, проверяется существующим `verify_reader` и распаковывается из тех же байтов.
- Версия пишется во временный каталог, переименовывается и только затем атомарно публикуется в индексе. Ошибка проверки, распаковки или записи индекса не меняет активную запись и удаляет временные файлы.
- `installed()` и `package(id)` после повторного открытия профиля возвращают ID, издателя, версию, манифест, состояние включения, SHA-256 пакета, платформу и путь к активному исполняемому файлу. Модуль при чтении не запускается.
- Повторная установка тех же байтов идемпотентна. Для известного ID сохраняется первый издатель; другой издатель и другая полезная нагрузка под той же версией отклоняются.
- `VerifiedPackage` сохраняет точные подписанные байты манифеста и подпись для записи в каталог версии.
- CLI `util-maker-package install` и `list`, цель `make package-install`; формат профиля описан в `docs/blocks/packages/package-format.md`.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make check` — версия 0.4.3, rustfmt и Clippy без замечаний, **143 теста** пройдено.
- `cargo test -p util-maker-packages --all-targets` — **21/21**. Среди них: установка и повторное открытие профиля, отказ повреждённого архива без публикации, идемпотентный повтор, смена издателя, другая полезная нагрузка под той же версией, ошибка записи вложенного файла с сохранением активной версии, сохранение состояния после перезапуска.
- `make control-samples` — собраны и проверены контрольные пакеты `0.4.1` и `0.5.0`.
- `make package-install PACKAGE_OUTPUT=dist/control-samples/control-0.4.1-linux-x64.umpkg PACKAGE_PUBLIC_KEY=dist/control-samples/keys/org.utilmaker-public.json PACKAGE_PROFILE=dist/test-profile PACKAGE_PLATFORM=linux-x64` — установлен `org.utilmaker.control 0.4.1`; `installed.json` содержит одну активную запись, каталог версии — манифест, подпись и `control-module`.
- Повтор той же команды вернул `alreadyInstalled: true` и не создал вторую запись; `util-maker-package list` показал манифест, `enabled: true` и путь к исполняемому файлу.
- Установленный `control-module` запущен через stdio из профиля: `initialize`, `ping` и `shutdown` вернули `status: ok`, `moduleVersion: 0.4.1`.

Ручная проверка на Windows для этой карточки не требуется: результат — переносимое хранилище профиля без UI. Выбор файла и установка из настроек проверяются в [«Управлять локальными пакетами из настроек»](../desktop/package-management.md).
