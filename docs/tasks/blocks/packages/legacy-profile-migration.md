# Запускать приложение после перехода на единое хранилище пакетов

**Статус** — ✅ Выполнена

**Основание** — [Единое хранилище пакетов](unify-package-store.md) · [Установка пакета](install-package.md)

## Наблюдение

После перехода на канонический `PackageStore` приложение 0.4.8 завершалось
до открытия окон. В журнале были только строки старта, затем процесс выходил с
кодом 101:

```text
Failed to setup app: хранилище пакетов: JSON состояния установленных пакетов:
missing field `version` at line 24 column 1
```

Причина: у пользователя остался `installed.json` старого desktop-хранилища
(`modules`/`previous`), а новый формат ждёт `version`/`packages`.

## Что сделано

- `PackageStore::open` при несовместимом `installed.json` переносит старый
  профиль: каталоги `modules/<id>/<version>` копируются в
  `<id>/<version>`, записи версий и активная версия попадают в новый индекс.
- Старый каталог `modules` переименовывается в `modules.legacy`; повторный
  запуск миграции безопасен.
- Добавлен тест `opens_and_migrates_legacy_desktop_profile`.

## Проверка

- `cargo test -p util-maker-packages` — 23/23.
- Windows 0.4.9: установка поверх 0.4.8, запуск — приложение остаётся в трее,
  повторный запуск открывает настройки, `installed.json` уже в новом формате.

## Критерии приёмки

- [x] Старый профиль не мешает запуску.
- [x] Активная и предыдущая версии пакета доступны после миграции.
- [x] Повторный запуск и миграция идемпотентны.
