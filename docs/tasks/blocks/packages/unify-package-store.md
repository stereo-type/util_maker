# Свести два хранилища пакетов к одному

**Статус** — 📥 К выполнению

**Основание** — [Формат профиля](../../../blocks/packages/package-format.md) · [Установка пакета](install-package.md)

## Наблюдение

В `crates/packages` сейчас два независимых `PackageStore`:

- `install.rs` — канонический установщик с CLI `util-maker-package install/list`;
- `store.rs` — хранилище desktop с откатом версии, снимком настроек и `.update.lock`.

У них разные каталоги и API. Пакет, установленный CLI, не обязан быть виден
desktop-менеджеру, и наоборот; откат/настройки работают только во втором
хранилище.

## Ожидаемое поведение

- Одно хранилище профиля с установкой, списком, обновлением, откатом,
  включением/отключением и настройками.
- CLI и desktop используют один и тот же профиль и один формат `installed.json`.
- Повторная установка идемпотентна, откат возвращает версию и настройки.

## Критерии приёмки

- [ ] В крейте один публичный `PackageStore`.
- [ ] CLI `install`/`list` и desktop-команды работают с одним профилем.
- [ ] Откат версии и снимок настроек доступны и из CLI, и из desktop.
- [ ] Тесты не дублируют два хранилища.

## Проверка

Linux: установить пакет CLI, открыть профиль desktop-командой, обновить и
откатить; проверить один `installed.json`.
