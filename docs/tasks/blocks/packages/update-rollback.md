# Атомарно переключать версию пакета и откатывать настройки

**Статус** — 🛠️ В работе

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/packages/README.md)

Подготовить версию рядом с действующей, проверить handshake кандидата и выполнить миграцию на копии настроек. Переключать версию вместе с конфигурацией после завершения текущего действия.

**Зависимости для старта** — [Установить проверенный пакет в профиль пользователя](install-package.md), [Обновлять реестр действий из каталога активных пакетов](../core/installed-actions.md).

**Для сквозной проверки** — [Подготовить две различимые версии контрольного пакета](../plugins/control/version-samples.md).

## Критерии приёмки

- [ ] При успешном обновлении второй плагин остаётся доступным. Откат возвращает предыдущую версию и её настройки.
- [ ] Ошибка handshake, несовместимый API, смена издателя или неудачная миграция сохраняют действующую пару версии и настроек.
- [ ] При прерывании до или после переключения, повторе либо конкурентном обновлении одного ID после восстановления доступна одна целостная пара.

## Проверка

Через `make test` на Linux прерывать операцию на границах записи, заново открывать профиль и вызывать действие. Для сквозной проверки использовать две версии контрольного пакета.

## Что уже сделано

- `PackageStore` хранит предыдущую версию рядом с активной.
- Установка новой версии атомарно переключает активную запись; при ошибке записи состояние откатывается.
- `rollback(id)` возвращает предыдущую версию и её метаданные; повторное открытие профиля сохраняет результат.
- Проверка: `cargo test -p util-maker-packages --lib store` — 5/5, включая обновление `0.1.0 → 0.2.0` и откат.

## Что осталось

- Снимок и миграция настроек модуля.
- Конкурентное обновление и восстановление после прерывания на границах записи.
- Handshake кандидата выполняется перед публикацией: при ошибке возвращается предыдущая пара.
