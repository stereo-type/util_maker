# Получать кадр и геометрию рабочего стола до показа overlay

**Статус** — 🛠️ В работе

[Этап 3 плана развития](../../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../../blocks/platform/windows/README.md)

Реализовать Windows-адаптер захвата для операций SDK. Передать плагину снимок в физических пикселях вместе с началом виртуального экрана, геометрией и масштабом мониторов. Подключить обработчик к хосту, когда доступна диспетчеризация. Захват и геометрию можно проверить отдельно от IPC на контракте ТЗ адаптера.

**Зависимости для старта** — можно начинать на текущей ревизии.

**Для сквозной проверки** — [Дать модулю доступ к возможностям хоста во время invoke](../../sdk/host-capabilities.md), [Исполнять запросы возможностей только в контексте активного вызова](../../core/capability-dispatch.md).

## Критерии приёмки

- [ ] Снимок создан до показа редактора. Прямоугольник на мониторе слева от основного и область на стыке разных DPI попадают в ожидаемые координаты.
- [ ] Кадр доступен только своему вызову. После отмены, завершения и ошибки захвата ресурс освобождён, ссылка становится недействительной.

## Проверка

На Linux проверить расчёт координат и время жизни ресурса на синтетическом кадре. На Windows пользователь сверяет геометрию двух мониторов и размеры контрольной области.
