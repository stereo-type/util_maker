# Хранить секреты профилей в системном хранилище Windows

**Статус** — 📥 К выполнению

[Этап 3 плана развития](../../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../../blocks/platform/windows/README.md)

Подключить операции сохранения, получения, замены и удаления ключа для пары модуль/профиль текущего пользователя. Предоставить desktop-хосту очистку секретов при удалении пакета.

**Зависимости для старта** — [Дать модулю доступ к возможностям хоста во время invoke](../../sdk/host-capabilities.md).

**Для сквозной проверки** — [Исполнять запросы возможностей только в контексте активного вызова](../../core/capability-dispatch.md).

## Критерии приёмки

- [ ] Два профиля одного плагина и одинаковые имена профиля разных плагинов изолированы. Замена ключа не меняет соседнюю запись.
- [ ] Обычные настройки содержат ссылку на секрет. После удаления модуля его записи исчезают; повторная очистка безопасна. Содержимое ключа не попадает в журнал или DTO настроек.

## Проверка

На Linux проверить изоляцию и очистку с тестовым хранилищем. Пользователь на Windows записывает тестовые значения, перезапускает приложение и удаляет один профиль или модуль.
