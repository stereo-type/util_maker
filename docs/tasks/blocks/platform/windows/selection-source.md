# Читать выделение исходного окна через UI Automation

**Статус** — 📥 К выполнению

[Этап 3 плана развития](../../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../../blocks/platform/windows/README.md)

Реализовать захват внешнего источника до открытия окон хоста и операции чтения/ожидания в Windows-адаптере. Возвращать типизированное состояние и координаты для окна результата.

**Зависимости для старта** — [Дать модулю доступ к возможностям хоста во время invoke](../../sdk/host-capabilities.md).

**Для сквозной проверки** — [Исполнять запросы возможностей только в контексте активного вызова](../../core/capability-dispatch.md).

## Критерии приёмки

- [ ] Состояния различают текст, пустое выделение, неподдерживаемый элемент, парольное поле и потерю источника. Пароль проверяется до чтения текста.
- [ ] При пустом диапазоне адаптер ждёт один жест в исходном приложении. При отмене, смене приложения и завершении снимает подписки. Наблюдение в простое отсутствует.
- [ ] Готовый текст и координаты относятся к исходному окну, в том числе после открытия меню трея.

## Проверка

На Linux проверить переходы на подменном источнике. На Windows пользователь проверяет оба порядка выделения в Блокноте и Edge, отмену и парольное поле.
