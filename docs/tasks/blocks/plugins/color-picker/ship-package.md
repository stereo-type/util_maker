# Поставлять пипетку отдельным подписанным пакетом

**Статус** — 👁️ На ревью

[ТЗ плагина](../../../../blocks/plugins/color-picker/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Включить `org.utilmaker.color-picker` в расширенную поставку Windows 11 x64. Пакет устанавливается и обновляется обычным менеджером Util Maker.

**Зависимости для старта** — Нужны манифест и исполняемый процесс из [карточки пипетки](pick-and-copy.md). Для экспорта использовать [формат пакета](../../../../blocks/packages/package-format.md).

**Для сквозной проверки** — [Выборка цвета](sample-pixel.md), [лупа и копирование](pick-and-copy.md) и [доступ к кадру](../../sdk/plugin-frame-access.md).

## Критерии приёмки

- [x] Локальная сборка пользователя через `make build-windows` включает подписанный `.umpkg` с точкой входа Windows x64 и совместимым `hostApi`. Архив проходит общую проверку подписи и файлов.
- [ ] В чистом профиле доступны действие из трея и назначение сочетания. После установки следующей версии только пипетки сохраняются шорткей и формат цвета. После закрытия процесс пипетки завершается.
- [ ] На контрольном изображении 1:1 в SDR строка в Блокноте совпадает с эталоном в обоих форматах. Выбор после долгой паузы, отказ занятого буфера и повтор позволяют скопировать прежнюю точку. Esc сохраняет прежний буфер.

## Что сделано

- `make build-windows` собирает `color-picker-module.exe` и пакует `org.utilmaker.color-picker` вместе с иконкой и подписью в отдельный Windows-пакет; установщик копирует все `.umpkg` и открытый ключ издателя.
- Версия манифеста приведена к версии workspace `0.4.30`; `make bump-version` и `make check-version` теперь учитывают манифест пипетки.
- Добавлена цель `make color-picker-package`: release-процесс, подписанный `.umpkg`, проверка подписи, `hostApi`, `files` и имитация обновления только пакета пипетки.
- При имитации обновления `0.4.30 → 0.4.31` активная версия меняется в профиле, а подготовленные `settings.json` с форматом `rgb` и `shortcuts.json` с `Ctrl+Shift+P` остаются без изменений.
- `color-picker-module` добавлен в список дочерних процессов, которые хост завершает при выходе.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make color-picker-check` — 27 unit-тестов и 7 IPC-тестов процесса; все прошли.
- `make color-picker-package` — для `0.4.30` и `0.4.31` проверены ID, издатель, `hostApi`, Linux-точка входа, иконка, SHA-256 файлов и подпись; обновление сохранило настройки и сочетание. Windows-точка входа и вызов `package_plugin` проверены по сборочному скрипту.
- `make check-version` — версия `0.4.30` согласована с манифестом.
- `make check` — rustfmt, Clippy, сборка workspace и все тесты прошли.
- `docker/windows/build-windows.sh` — `sh -n` без ошибок, сборка `color-picker-module.exe` и вызов `package_plugin` для пипетки проверены по скрипту; полная Windows-сборка в этой среде не запускалась.

## Осталось

Пользователь собирает `make build-windows` на Windows 11 x64 и проверяет чистый профиль: действие `pick-color` в трее, назначение сочетания, обновление только пакета пипетки с сохранением формата и привязки, завершение процесса после закрытия. На контрольном изображении 1:1 в SDR строка в Блокноте должна совпасть с эталоном в HEX и CSS RGB; после долгой паузы, занятого буфера и Esc проверяется повторное копирование прежней точки. Сквозное копирование на реальном кадре проверяется с окном выбора из [карточки пипетки](pick-and-copy.md): процесс читает пиксели через [доступ к кадру](../../sdk/plugin-frame-access.md), а замороженный кадр и лупу показывает хост. Ревизия будет указана в итоговом ответе.
