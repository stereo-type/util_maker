# Включить подписанный пакет с двумя QR-действиями в поставку

**Статус** — 📥 К выполнению

[ТЗ плагина](../../../../blocks/plugins/qr-code/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Поставлять оба действия `org.utilmaker.qr-code` в одном независимо обновляемом `.umpkg` для Windows 11 x64.

**Зависимости для старта** — Нужен [процесс с манифестом](show-selection.md). Упаковка использует общий [формат](../../../../blocks/packages/package-format.md).

**Для сквозной проверки** — [Показ QR](show-selection.md), [кодирование](encode-text.md), [чтение с экрана](read-region.md) с [декодером](decode-region.md) и [доступ к кадру](../../sdk/plugin-frame-access.md).

## Критерии приёмки

- [ ] Локальная сборка пользователя через `make build-windows` включает один подписанный пакет с обеими точками вызова и совместимым `hostApi`. Общая проверка принимает подпись и файлы.
- [ ] На чистом профиле оба действия видны в трее и редакторе шорткеев. Разные сочетания запускают соответствующие действия. После обновления только этого пакета обе привязки сохраняются. Отключение пакета прекращает оба вызова.
- [ ] Оба сценария работают офлайн. После закрытия или отмены освобождаются окно, процесс и данные. Показ QR и отменённое чтение сохраняют прежний буфер.

## Проверка

На Linux проверить манифест, содержимое архива и подпись с тестовым ключом. Передать ревизию, команду локальной сборки, эталонные QR и строки пользователю для проверки сканирования телефоном, второго монитора и обновления на Windows.
