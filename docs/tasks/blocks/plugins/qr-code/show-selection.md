# Показывать QR из выделения или ручного ввода

**Статус** — 📥 К выполнению

[ТЗ плагина](../../../../blocks/plugins/qr-code/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Добавить процесс и манифест `org.utilmaker.qr-code` издателя `org.utilmaker` с действиями `show-qr` и `read-qr-region`. Реализовать окно и handler `show-qr`. Обработчик второго действия поставляет [карточка чтения](read-region.md).

**Зависимости для старта** — Можно начать с тестовой матрицы и ответов `selection.get` от тестового хоста. Граница процесса следует [SDK](../../../../blocks/sdk/README.md).

**Для сквозной проверки** — [Кодирование текста](encode-text.md) и [источник выделения Windows](../../platform/windows/selection-source.md).

## Критерии приёмки

- [ ] Манифест объявляет `selection.read`, `screen.capture` и `clipboard.write`. Для `show-qr` требуется только `selection.read`. До показа окна запрашивается выделение внешнего приложения, в том числе при запуске из трея. Известное парольное поле исключает чтение значения и автозаполнение.
- [ ] При наличии выделения сразу видны исходный текст и QR. Пустой, недоступный или потерянный источник открывает поле ручного ввода и вставки. Правка обновляет QR, пустой и слишком большой ввод убирают старый код и показывают причину.
- [ ] При смене DPI и размера окна масштаб модулей пересчитывается. Если изображение не помещается, окно предлагает увеличить его или сократить текст. Повторный вызов активирует открытое окно, Esc закрывает его. Системный буфер сохраняется.

## Проверка

В Linux проверить порядок вызовов и состояния окна с тестовым источником. На Windows пользователь выделяет ссылку в Блокноте, вызывает действие шорткеем и из трея, проверяет ручной ввод и считывает точную строку телефоном при 150%.
