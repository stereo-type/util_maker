# Показывать QR из выделения или ручного ввода

**Статус** — 👁️ На ревью

[ТЗ плагина](../../../../blocks/plugins/qr-code/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Добавить процесс и манифест `org.utilmaker.qr-code` издателя `org.utilmaker` с действиями `show-qr` и `read-qr-region`. Реализовать окно и handler `show-qr`. Обработчик второго действия поставляет [карточка чтения](read-region.md).

**Зависимости для старта** — Можно начать с тестовой матрицы и ответов `selection.get` от тестового хоста. Граница процесса следует [SDK](../../../../blocks/sdk/README.md).

**Для сквозной проверки** — [Кодирование текста](encode-text.md) и [источник выделения Windows](../../platform/windows/selection-source.md).

## Критерии приёмки

- [x] Манифест объявляет `selection.read`, `screen.capture` и `clipboard.write`. Для `show-qr` требуется только `selection.read`. До показа окна запрашивается выделение внешнего приложения, в том числе при запуске из трея. Известное парольное поле исключает чтение значения и автозаполнение.
- [x] При наличии выделения сразу видны исходный текст и QR. Пустой, недоступный или потерянный источник открывает поле ручного ввода и вставки. Правка обновляет QR, пустой и слишком большой ввод убирают старый код и показывают причину.
- [x] При смене DPI и размера окна масштаб модулей пересчитывается. Если изображение не помещается, окно предлагает увеличить его или сократить текст. Повторный вызов активирует открытое окно, Esc закрывает его. Системный буфер сохраняется.

## Что сделано

- Добавлены `plugins/qr-code/manifest.json` и процесс `qr-code-module` с действиями `show-qr` и `read-qr-region`; возможности манифеста — `selection.read`, `screen.capture`, `clipboard.write`.
- `show-qr` до создания окна вызывает `selection.get`. Парольное состояние не передаёт значение в окно. Пустое, неподдерживаемое, потерянное или недоступное выделение открывает ручное поле с причиной.
- Добавлен `ShowWindow`: точный текст, матрица QR, исходный текст для правки, ошибки `EmptyInput`/`TooLong`/`TooSmall`, пересчёт целого масштаба при изменении размера и повторная активация.
- Окно результата хоста получило QR-панель: canvas, редактируемое поле и `encode_qr_text`. Правка и изменение размера пересчитывают матрицу; при ошибке canvas очищается. Esc закрывает окно, `buffer.copy` не вызывается.
- `QrMatrix::layout` отделён от отрисовки: окно получает модули, масштаб, смещение и белое поле без лишней копии пикселей.
- `read-qr-region` пока возвращает машинную причину `read-qr-not-implemented`; handler и копирование результата входят в [карточку чтения](read-region.md).
- `Makefile` сверяет версию и запускает тесты процесса; обновлены README плагина и список текущих плагинов.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make qr-code-check` — 13 unit-тестов библиотеки, 5 тестов эталонов и 5 тестов процесса; все прошли.
- `cargo clippy -p util-maker-qr-code --all-targets -- -D warnings` — без замечаний.
- `make check` — версия 0.4.24, rustfmt, Clippy, сборка workspace и все тесты прошли (для экономии места debug info отключён).
- `node --check` для скрипта `result.html` — синтаксис без ошибок.

Проверено: `selection.get` вызывается раньше окна; ручной ввод не запрашивает выделение; парольный текст не попадает в ответ; исходный текст сохраняется побайтно; QR получает целый масштаб; пустой и слишком большой ввод убирают прежний код; изменение размера пересчитывает масштаб; повторный вызов не делает новый захват; системный буфер не меняется.
