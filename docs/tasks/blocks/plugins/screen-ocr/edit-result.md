# Редактировать результат OCR и копировать исправленный текст

**Статус** — 📥 К выполнению

[ТЗ плагина](../../../../blocks/plugins/screen-ocr/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Довести действие от подтверждения области до редактируемого результата. Связать состояние распознавания, возврат к выбору и копирование с жизненным циклом одного вызова.

**Зависимости для старта** — Можно начать с отложенного ответа распознавателя и тестового буфера. Интерфейс использует текст, признак пустого результата и ошибку модели из [задачи распознавания](recognize-crop.md).

**Для сквозной проверки** — [Выбор области](select-region.md) и [реальный движок](recognize-crop.md) для полного вызова.

## Критерии приёмки

- [ ] Во время обработки видны «Распознавание…» и возможность отмены. Непустой ответ открывается в многострочном поле. При пустом ответе видны «Текст не найден» и «Выбрать другую область».
- [ ] «Копировать» и Ctrl+Enter отправляют текущую редакцию через `clipboard.write` и закрывают окно только при успехе. Пустой текст скопировать нельзя. Занятый буфер оставляет правки в поле для повтора.
- [ ] Esc во время распознавания или редактирования завершает сессию. Поздний ответ отменённого вызова не открывает окно и не меняет новый результат. Повторный шорткей возвращает в действующее окно.

## Проверка

В Linux задержать первый ответ, отменить, начать второй вызов и вернуть ответы в обратном порядке. Имитировать отказ буфера и повтор, проверить ровно одну успешную запись исправленного текста. На Windows пользователь вставляет результат в Блокнот.
