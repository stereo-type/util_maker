# Запускать OCR из трея и выбирать область на снимке экрана

**Статус** — 📥 К выполнению

[ТЗ плагина](../../../../blocks/plugins/screen-ocr/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Добавить манифест и исполняемую точку входа `org.utilmaker.screen-ocr / recognize-region`. Действие читает языки через SDK и показывает выбор области на одном зафиксированном снимке.

**Зависимости для старта** — Можно брать сразу. Для разработки доступны контракт кадра и тестовый источник пикселей. Для обработчика выбора достаточно подставного распознавателя.

**Для сквозной проверки** — [Доступ дочернего процесса к кадру](../../sdk/plugin-frame-access.md), [распознавание](recognize-crop.md) и [окно результата](edit-result.md).

## Критерии приёмки

- [ ] Манифест издателя `org.utilmaker` объявляет `screen.capture`, `settings.read`, `clipboard.write` и поле «Языки распознавания». Значение по умолчанию — «Русский и английский». После смены на один язык следующий вызов получает сохранённое значение.
- [ ] Шорткей и трей вызывают одно действие. Оно захватывает экран до показа окна, читает пиксели в память и освобождает ссылку через `frame.release`. Сбой захвата или истечение ссылки до чтения позволяют запросить новый снимок.
- [ ] Выделение работает в любом направлении и передаёт физические координаты с учётом геометрии каждого монитора. Вырожденный прямоугольник оставляет выбор открытым. При повторном вызове активируется текущая сессия.
- [ ] Esc закрывает выбор и освобождает кадр. Если пользователь ждёт дольше `expiresInMs`, выделение по сохранённому снимку остаётся рабочим.

## Проверка

В Linux проверить процесс с тестовым хостом, в том числе порядок захвата и открытия окна, обратное выделение, смену языка и истечение ссылки. Для Windows передать выбор на левом мониторе и на стыке разных DPI с ожидаемой границей фрагмента.
