# Поставлять и обновлять подписанный OCR-пакет с моделями

**Статус** — 📥 К выполнению

[ТЗ плагина](../../../../blocks/plugins/screen-ocr/README.md) · [Этап «После первой поставки»](../../../../roadmap.md#после-первой-поставки)

Включить в расширенную штатную поставку отдельный `.umpkg` с исполняемым процессом, Tesseract, его runtime-зависимостями и моделями `rus` и `eng`. Загрузки при первом вызове исключены.

**Зависимости для старта** — [Манифест и процесс](select-region.md) и [движок с моделями](recognize-crop.md) должны присутствовать в checkout. Использовать существующий [формат пакета](../../../../blocks/packages/package-format.md).

**Для сквозной проверки** — [Редактор результата](edit-result.md) и [доступ к кадру](../../sdk/plugin-frame-access.md).

## Критерии приёмки

- [ ] Локальная сборка пользователя через `make build-windows` включает подписанный `org.utilmaker.screen-ocr` для Windows 11 x64. Архив проходит общую проверку подписи, файлов и `hostApi`. Версии движка и обеих моделей воспроизводимы.
- [ ] В чистом профиле без сети работают трей, назначенный шорткей, распознавание и копирование. После обновления только OCR-пакета остаются выбранный язык и назначение действия.
- [ ] При долгом выборе, отмене и повторном запуске буфер меняется только по команде копирования. После закрытия исчезают процесс и загруженные модели.

## Проверка

На Linux проверить состав и подпись пакета на подготовленных входах. Передать пользователю ревизию, команду локальной сборки, версии моделей, эталонный растр и шаги проверки на Windows из ТЗ, включая разные DPI и работу без сети.
