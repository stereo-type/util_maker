# Центрировать окно редактора снимка на активном мониторе

**Статус** — 📥 К выполнению

**Основание** — [Стиль интерфейса](../../../../ui-style-guide.md#окна) · [Фиксировать размер окна редактора](editor-fixed-window.md) · [Показывать все всплывающие окна по центру экрана](../../desktop/centered-modals.md)

## Наблюдение

На Windows с двумя мониторами окно редактора открывается на стыке экранов:
центр окна попадает на границу мониторов. Остальные окна приложения —
настройки, результат, подтверждение — центрируются правильно по активному
монитору.

`show_editor_window` в `apps/desktop/src/main.rs` считает позицию от кадра
виртуального рабочего стола:

```rust
let window_x = origin_x + (frame_width as i32 - editor_width as i32) / 2;
let window_y = origin_y + (frame_height as i32 - editor_height as i32) / 2;
```

Overlay занимает оба монитора, поэтому центр кадра оказывается на стыке. Для
остальных окон используется `center_on_active_monitor`, который берёт монитор
под курсором.

## Ожидаемое поведение

- Редактор открывается по центру монитора, на котором пользователь завершил
  выделение, а не по центру виртуального рабочего стола.
- Окно не пересекает стык мониторов и целиком помещается в рабочую область
  активного монитора; заголовок и нижняя панель доступны.
- Положение не зависит от точки внутри монитора, координат выделения и
  предыдущего открытия.
- При повторном открытии редактор снова центрируется, а не остаётся смещённым.
- На одном мониторе поведение прежнее — окно по центру экрана.
- Позиция и размер учитывают рабочие области и масштаб 100/150/200 %.

## Критерии приёмки

- [ ] Выделение на левом мониторе открывает редактор по центру левого, на
  правом — по центру правого.
- [ ] Окно не пересекает стык мониторов при любом взаимном расположении
  экранов, включая отрицательный `x` левого монитора.
- [ ] Окно целиком в рабочей области активного монитора на 100/150/200 %.
- [ ] На одном мониторе окно по-прежнему по центру.
- [ ] Положение не зависит от выделения и предыдущего открытия.
- [ ] Повторный вызов не оставляет окно смещённым.

## Зависимости

**Для старта** — [Открывать overlay скриншота на весь виртуальный экран](../../desktop/overlay-window-geometry.md) и [Фиксировать размер окна редактора](editor-fixed-window.md) выполнены; геометрия мониторов и `center_on_active_monitor` уже есть в хосте.

**Для сквозной проверки** — Windows 11 x64 с двумя мониторами разного DPI.

## Проверка

Linux: `make test` и `make lint`. Выбор монитора по точке вынести в чистую
функцию и покрыть тестом (координата курсора → прямоугольник монитора), если
это не усложняет вызов из `show_editor_window`.

Windows: `make build-windows`, установить сборку и на двух мониторах с разным
масштабом (например, 100 % и 150 %) снять область сначала на левом, затем на
правом мониторе. Ожидается: редактор каждый раз открывается по центру того
монитора, где завершено выделение, не на стыке, а повторный вызов возвращает
окно в центр.
