# Открывать редактор снимка на активном мониторе

**Статус** — ✅ Выполнена

**Основание** — [ТЗ плагина](../../../../blocks/plugins/screenshot/README.md) · [Стиль интерфейса](../../../../ui-style-guide.md)

## Наблюдение

Раньше редактор центрировался по всему виртуальному рабочему столу. На двух мониторах окно могло оказаться на стыке экранов, перекрыть оба монитора или открыться не на том, где пользователь выделил область.

## Ожидаемое поведение

1. После выделения редактор открывается на мониторе, где сделано выделение.
2. Если выделение пересекает несколько мониторов, выбирается монитор с наибольшей площадью пересечения; при равенстве — основной.
3. Окно целиком помещается в выбранный монитор с нейтральным отступом; на маленьком мониторе размер уменьшается, панели остаются доступны.
4. Отрицательные координаты монитора слева и разный DPI не меняют положение окна относительно выбранного монитора.
5. Если геометрия мониторов недоступна, используется прежнее центрирование по захваченному кадру.

## Критерии приёмки

- [x] Выделение на левом мониторе с отрицательным `x` открывает редактор по центру этого монитора, а не на стыке.
- [x] Выделение на правом мониторе открывает редактор на нём же.
- [x] При пересечении стыка выбирается монитор с большей площадью выделения; при равенстве — основной.
- [x] Окно и его панели не выходят за границы выбранного монитора; на мониторе меньше 1100×760 размер уменьшается с отступами.
- [x] Без геометрии мониторов окно центрируется по захваченному кадру.
- [x] Положение и размер одинаковы для маленького и большого выделения на одном мониторе.
- [x] На Windows проверены два монитора с разным DPI и стык экранов.

## Что сделано

- Геометрия мониторов сохраняется вместе с кадром в `OverlayFrame`, а не только начало и размер виртуального экрана.
- Добавлен `editor_placement::place_editor`: выбирает монитор по площади пересечения с выделением, при равенстве — основной, и центрирует на нём окно 1100×760.
- Размер ограничивается площадью монитора с отступом 32 px; координаты считаются в `i64`, поэтому отрицательный `x` левого монитора не переполняется.
- Если мониторы не переданы или выделение вне их, используется захваченный кадр.
- Позиция и размер не зависят от величины и координат выделения внутри одного монитора.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `cargo test -p util-maker-desktop` — 11 тестов, включая 7 новых: левый монитор с отрицательным `x`, правый монитор, стык, равенство площадей, маленький монитор, отсутствие геометрии и независимость от размера выделения.
- `make screenshot-check` — 11 тестов библиотеки скриншотов и 2 теста процесса.
- `make check` — `check-version`, `fmt`, `clippy`, сборка workspace и все тесты прошли.

Windows остаётся ручная проверка: ревизия будет указана в итоговом ответе, команда локальной сборки `make build-windows`. Выделить область на левом и правом мониторе, на стыке и на мониторе с масштабом 150 %. Ожидаемо: редактор открывается по центру монитора выделения, целиком помещается на нём и не перекрывает соседний экран.

Пользователь подтвердил на Windows 0.4.35: редактор открывается на активном мониторе, в том числе на стыке экранов с разным DPI.
