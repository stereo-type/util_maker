# Настраивать папку сохранения снимков

**Статус** — ✅ Выполнена

**Основание** — [ТЗ плагина](../../../../blocks/plugins/screenshot/README.md) · [Интерфейс и настройки](../../../../blocks/desktop/settings.md)

## Наблюдение

Кнопка «Сохранить» в редакторе всегда пишет PNG в `%USERPROFILE%\Pictures\Util Maker`. Пользователь не может выбрать диск или каталог, а на системах с ограниченным профилем путь может быть недоступен для записи.

## Ожидаемое поведение

1. На странице микроприложения «Скриншоты» есть текстовое поле «Папка для сохранения».
2. Пустое значение означает стандартную папку `%USERPROFILE%\Pictures\Util Maker`.
3. Можно указать полный путь к существующей или новой папке; относительный путь отклоняется с понятной ошибкой.
4. Каталог создаётся при сохранении, а ошибка записи показывается в редакторе без потери кадра.
5. Изменённый путь применяется к следующему сохранению без перезапуска приложения.
6. Настройка хранится в общем хранилище настроек модуля и удаляется вместе с пакетом.

## Критерии приёмки

- [x] Манифест «Скриншотов» объявляет поле `saveDirectory`, и форма настроек строится без запуска плагина.
- [x] Пустое или отсутствующее значение сохраняет снимок в стандартную папку.
- [x] Абсолютный путь сохраняет PNG в выбранный каталог и создаёт его при необходимости.
- [x] Относительный путь и путь к файлу дают понятную ошибку.
- [x] Изменение настройки действует при следующем сохранении без перезапуска.
- [x] Linux-тесты проверяют выбор пути и валидацию.
- [x] На Windows настроить папку, сохранить PNG, изменить путь и сохранить снова.

## Зависимости

Для старта достаточно текущей ревизии. Ручная проверка записи в пользовательскую папку выполняется на Windows.

## Что сделано

- В `plugins/screenshot/manifest.json` добавлена схема настроек с полем `saveDirectory`; форма строится существующим универсальным экраном настроек плагина.
- `save_editor_image` читает `saveDirectory` из `SettingsStore` при каждом сохранении, поэтому изменение применяется без перезапуска.
- Пустое значение использует `%USERPROFILE%\Pictures\Util Maker`; на Linux для проверок резервно берётся `HOME`.
- Полный путь принимается, относительный отклоняется, путь к файлу даёт отдельную ошибку. Каталог создаётся через `create_dir_all`.
- Кодирование PNG и запись вынесены в `write_screenshot_png`, чтобы проверять реальное создание файла в тесте.
- Текст ошибок создания каталога и записи файла содержит конкретный путь.

## Проверка

Linux, контейнер `util-maker-dev:local`, версия `0.4.24`:

- `make check` — `check-version`, `rustfmt`, Clippy и все тесты workspace прошли.
- `util-maker-desktop` — 15 тестов, включая `screenshot_save_directory_defaults_and_validates_custom_path`: пустой путь, абсолютный путь, отклонение относительного пути и файла, запись PNG во вложенный новый каталог.
- `util-maker-core / screenshot_module` — 2 теста; манифест проверяет поле `saveDirectory` с типом `text` и пустым значением по умолчанию.

Windows остаётся ручная проверка: ревизия будет указана в итоговом ответе, команда локальной сборки `make build-windows`. Открыть настройки «Скриншотов», указать `D:\Скриншоты`, снять область, нажать «Сохранить» — PNG должен появиться в `D:\Скриншоты`. Затем очистить поле, сохранить ещё раз — файл должен попасть в `%USERPROFILE%\Pictures\Util Maker`. Относительный путь должен дать ошибку в редакторе.

Пользователь подтвердил на Windows 0.4.35: папка сохранения настраивается, PNG пишется в выбранный путь после смены пути.
