# Сохранять ключ под профилем выбранного сервиса

**Статус** — 📥 К выполнению

**Основание** — [Форма настроек](../../desktop/settings-form.md) · [Профили провайдеров](../providers/active-profile.md)

## Наблюдение

В форме переводчика ключ Яндекса сохранён, поле показывает «Ключ сохранён», но
файл секрета создан с профилем `default`:

```text
...translator__default__translator/yandex/apiKey.bin
```

Процесс переводчика при вызове запрашивает `secret.read` для профиля `yandex`
и ссылки `translator/yandex/apiKey`. Такой записи нет, поэтому ключ не будет
найден, хотя интерфейс показывает сохранение.

Причина: в схеме настроек нет `profiles`, а `renderPluginSettings` подставляет
`profiles?.[0]?.id || "default"`.

## Ожидаемое поведение

- Ключ Яндекса сохраняется под профилем `yandex`.
- Ключ Google — под профилем `google`.
- Смена активного сервиса использует соответствующий ключ.
- «Ключ сохранён» не показывается, если запись создана под другим профилем.

## Критерии приёмки

- [ ] Ключ сохраняется под профилем, который читает процесс переводчика.
- [ ] Форма показывает наличие ключа именно для выбранного сервиса.
- [ ] В файловой системе нет записи `default` для ключей переводчика.
- [ ] Проверка подключения реально использует сохранённый ключ.

## Проверка

Windows: сохранить ключ Яндекса, проверить имя файла секрета, вызвать перевод
и убедиться, что запрос ушёл с ключом.
