# Передать пример подключения стороннего плагина с двумя действиями

**Статус** — ✅ Выполнена

[Этап 4 плана развития](../../../roadmap.md#4-принять-первую-поставку-windows) · [ТЗ блока](../../../blocks/sdk/README.md)

Подготовить переносимый пример с новым ID и двумя различимыми действиями. Описать сборку, подпись, доверие издателю, установку и выпуск следующей версии. Оставить прототип `control/ping` рабочим.

**Зависимости для старта** — [Экспортировать подписанный пакет .umpkg](../packages/export-package.md), [Описать пользовательские настройки и команды формы в манифесте](module-settings.md).

**Для сквозной проверки** — [Подключить редактор и глобальные клавиши к общему реестру](../desktop/live-shortcuts.md), [Управлять локальными пакетами из настроек](../desktop/package-management.md), [Атомарно переключать версию пакета и откатывать настройки](../packages/update-rollback.md).

## Критерии приёмки

- [x] Следуя инструкции с чистого checkout, разработчик получает подписанный пакет нового ID. Оба действия вызываются через действующий SDK.
- [x] На том же хосте пользователь добавляет открытый ключ, устанавливает пакет, назначает разные сочетания и обновляет пакет. Сохранившийся ID действия сохраняет привязку.

## Проверка

На Linux, контейнер `util-maker-dev:local`:

- `make example-package` — собран и проверен `echo-plugin-0.1.0-linux-x64.umpkg` (`com.example.echo`, `fileCount=1`, `entrypoint=echo-plugin`).
- `actions.jsonl` — `hello` и `clock` вернули `status: ok` через `run_stdio`; затем процесс ответил на `shutdown`.
- `make example-package EXAMPLE_VERSION=0.2.0` — тот же ID и тот же ключ `com.example`, версия в манифесте и `hello.moduleVersion` стала `0.2.0`; ID действий `hello`/`clock` сохранились.
- Архив `0.1.0` повторно проверен тем же открытым ключом; SHA-256 первого пакета — `54ee1d1ee8eb9989b84e8fe55482bf12c4c5e253a440e493b9d21c389cac8242`.
- Инструкция сборки, подписи, установки и выпуска следующей версии — [examples/echo-plugin/README.md](../../../../examples/echo-plugin/README.md).

Windows, приложение 0.4.29-dev (HEAD `210bcd9`), Windows 11 Pro 26200, 2026-11-15:

- `cargo xwin` собрал `echo-plugin.exe` версий 0.1.0 и 0.2.0. Пакеты `echo-plugin-0.1.0-windows-x64.umpkg` (SHA-256 `8c71713ca35699fa574f19de1a5fc4a51dd044910e6d29bec9b80eb0ee506c7f`) и `0.2.0` (`c1345abcd8d3b963d3f0af62541be58100884d85b402ff5f636536617b0e5c59`) прошли `verify` с платформой `windows-x64`.
- В настройках добавлен ключ `com.example`, установлен 0.1.0: предпросмотр показал два действия и один файл, в списке появился «Пример Echo» 0.1.0.
- Назначены `Ctrl+Alt+Shift+H` для `hello` и `Ctrl+Alt+Shift+M` для `clock`. Оба сочетания вызвали действие: в журнале `com.example.echo / hello` и `/ clock`, `outcome=Ok`, процесс `echo-plugin` версии 0.1.0.
- Установлен 0.2.0 поверх: `installed.json` содержит обе версии и `activeVersion: 0.2.0`; `shortcuts.json` сохранил обе привязки. Повторные вызовы запустили `echo-plugin` версии 0.2.0, ID действий не изменились.
- Чужой ключ отклонён: «Ошибка проверки: подпись манифеста неверна».
- Инструкция Windows в [examples/echo-plugin/README.md](../../../../examples/echo-plugin/README.md) дополнена созданием ключа, `--version` и `UTIL_MAKER_MODULE_VERSION`; исправлено устаревшее утверждение, что установки из UI нет.

Замечание вне критериев карточки: сообщение об успешной установке показывает `undefined` вместо имени пакета. В `apps/desktop/ui/index.html` используется `installed.name`, а у `InstalledPackage` есть `manifest.name`. На установку, обновление и привязки это не влияет; нужен отдельный мелкий фикс интерфейса.
