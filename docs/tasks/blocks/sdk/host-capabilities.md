# Дать модулю доступ к возможностям хоста во время invoke

**Статус** — ✅ Выполнена

[Этап 3 плана развития](../../../roadmap.md#3-довести-оба-действия-до-результата-в-windows) · [ТЗ блока](../../../blocks/sdk/README.md)

Расширить JSON-RPC и цикл `run_stdio` для обращений модуля к хосту в пределах активного вызова. Зафиксировать контракты операций над кадром, выделением, буфером, настройками и секретами профиля.

**Зависимости для старта** — можно начинать на текущей ревизии.

## Критерии приёмки

- [x] Запрос к хосту и его ответ сопоставляются с живым вызовом и объявленной возможностью. В контракте различимы отказ, потеря контекста и отмена. Дескрипторы Win32 остаются внутри адаптера.
- [x] Кадр передаётся по ограниченной временем жизни ссылке, с форматом, размерами, шагом строки и координатами. Полноразмерное изображение не помещается в JSON-сообщение.
- [x] `cancel` и `shutdown` принимаются, пока handler ждёт операцию. Существующий `ping` продолжает работать с прежним манифестом и протоколом v1.

## Проверка

На Linux, контейнер `util-maker-dev:local`:

- `cargo test -p util-maker-sdk --lib` — 18/18, включая `host_call_is_matched_with_live_call`, `cancel_is_accepted_while_handler_waits_for_host`, `shutdown_is_accepted_while_handler_waits_for_host`.
- `cargo test -p util-maker-core --test host_capabilities` — 3/3: кадр по ссылке, отказ без возможности (`1003`), потеря контекста (`1005`).
- `cargo test -p util-maker-core --test control_module_ipc` — 5/5; `ping` и протокол v1 не изменились.
- `make test` — 84 теста пройдены; `make lint` — без замечаний.
- `FrameRef` сериализуется меньше 512 байт и не содержит пикселей; ответ и запрос ограничены `MAX_MESSAGE_BYTES` (1 МиБ).

Закрыта по Linux-проверкам: критерии подтверждены тестами, ручная проверка на Windows для этой карточки не требуется.
