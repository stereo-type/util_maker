# Описать пользовательские настройки и команды формы в манифесте

**Статус** — 📥 К выполнению

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/sdk/README.md)

Расширить существующий `Manifest` совместимым описанием типов полей, значений по умолчанию, ссылок на секреты и команд формы. Переводчик использует этот механизм для выбора профиля и проверки подключения.

**Зависимости для старта** — можно начинать на текущей ревизии.

## Критерии приёмки

- [ ] Старый манифест контрольного плагина читается без изменений. Некорректные ссылки на поля или команды дают ошибку при валидации. Обычные параметры и секретные поля различимы.
- [ ] В ТЗ SDK есть пример двух профилей с выбором языков, активного профиля и команды проверки. Оболочка может построить форму из схемы без запуска процесса.
- [ ] Описан обмен значениями и результатом команды, в том числе ошибка поля. Публичное состояние формы раскрывает наличие сохранённого ключа без его значения.

## Проверка

На Linux через `make test` проверить загрузку прежнего и нового манифестов, ошибочную схему и сериализацию доступного оболочке состояния.
