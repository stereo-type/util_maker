# Описать пользовательские настройки и команды формы в манифесте

**Статус** — ✅ Выполнена

[Этап 2 плана развития](../../../roadmap.md#2-устанавливать-и-обновлять-инструменты-из-настроек) · [ТЗ блока](../../../blocks/sdk/README.md)

Расширить существующий `Manifest` совместимым описанием типов полей, значений по умолчанию, ссылок на секреты и команд формы. Переводчик использует этот механизм для выбора профиля и проверки подключения.

**Зависимости для старта** — можно начинать на текущей ревизии.

## Критерии приёмки

- [x] Старый манифест контрольного плагина читается без изменений. Некорректные ссылки на поля или команды дают ошибку при валидации. Обычные параметры и секретные поля различимы.
- [x] В ТЗ SDK есть пример двух профилей с выбором языков, активного профиля и команды проверки. Оболочка может построить форму из схемы без запуска процесса.
- [x] Описан обмен значениями и результатом команды, в том числе ошибка поля. Публичное состояние формы раскрывает наличие сохранённого ключа без его значения.

## Проверка

На Linux, контейнер `util-maker-dev:local`:

- `make test` — 84 теста пройдены, включая `util-maker-sdk` (18/18).
- `make lint` — Clippy с `-D warnings` без замечаний.
- В `crates/sdk/src/manifest.rs` проверены прежний манифест `control`, валидная схема двух профилей, висячие ссылки на поле/профиль, секрет с `default`, варианты у не-select поля.
- `form_state` сериализован с секретом во входных значениях: значение не попало в JSON, `present: true` и `secretRef` остались.
- Пример двух профилей, обмен `command`/`formCommand` и публичное состояние формы добавлены в [ТЗ SDK](../../../blocks/sdk/README.md).

Закрыта по Linux-проверкам: критерии подтверждены тестами, ручная проверка на Windows для этой карточки не требуется.
