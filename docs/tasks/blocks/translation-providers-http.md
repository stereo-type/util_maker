# Подключить HTTP-адаптеры Яндекса и Google

**Статус** — ✅ Выполнена

**Основание** — [ТЗ блока «Провайдеры»](../../blocks/translation-providers.md).

Реализовать перевод и проверку подключения через единый интерфейс провайдера. Для проверок использовать тестовый HTTP-транспорт и отдельные профили.

## Критерии приёмки

- [x] Для обоих API проверены endpoint, авторизация, языковые параметры, формат plain text и чтение результата.
- [x] При переключении профиля следующий запрос уходит выбранному сервису с его ключом. Проверка подключения отправляет фиксированную фразу.
- [x] Ошибки авторизации, HTTP 429, таймаут и отмена дают ожидаемый исход без пересылки текста второму сервису.

## Что сделано

- `plugins/translator/providers` — `Profile`, `ProviderHub`, `HttpTransport`, `ReqwestTransport`, `translate` и `check_connection`.
- Яндекс: `Authorization: Api-Key`, `texts`, `targetLanguageCode`, необязательный `sourceLanguageCode`, чтение `translations[0].text`.
- Google: `key` в URL, `q`, `target`, `format=text`, необязательный `source`, чтение `data.translations[0].translatedText`.
- Ошибки авторизации, квоты, 429, таймаута, сети и отмены различаются; активный профиль определяет единственный получатель текста.
- Инструкция настройки — [провайдеры перевода](../../providers-setup.md).

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make test` — 63 теста, в том числе 7 тестов провайдеров:
  - поля и заголовки Яндекса, автоопределение языка;
  - поля Google, явный источник и ключ в URL без заголовка Authorization;
  - переключение профиля отправляет запрос только с ключом нового сервиса;
  - проверка подключения использует фиксированную фразу `Util Maker`;
  - 401 → `Unauthorized`, 429 → `RateLimited`, таймаут → `Timeout`, по одному запросу;
  - отмена не отправляет запрос, пустой ключ отклоняется до сети.
- `make lint` — Clippy без предупреждений, `make fmt` — без изменений.

Пользователь подтвердил работу в Windows 11 и закрыл задачу в версии 0.4.1.
