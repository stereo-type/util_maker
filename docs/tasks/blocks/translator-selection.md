# Обработать выделение до и после вызова переводчика

**Статус** — 👁️ На ревью

**Основание** — [ТЗ блока «Переводчик»](../../blocks/translator.md).

Реализовать состояния выбора текста на тестовых адаптерах источника и перевода. Контекст исходного окна живёт в пределах одного вызова.

## Критерии приёмки

- [x] При готовом выделении запрос содержит ровно выбранный текст. При пустом диапазоне запрос отправляется один раз после завершения жеста.
- [x] Esc, смена приложения в режиме ожидания и известное парольное поле дают ноль запросов.
- [x] При неподдерживаемом источнике ручной ввод отправляется только по команде «Перевести».

## Что сделано

- `plugins/translator` — `SelectionController` с фазами Idle/Awaiting/Manual и снимками источника `Selected`, `Empty`, `Unsupported`, `Password`, `ContextLost`.
- `SourceAdapter` и `TranslationSink` — тестовые адаптеры источника и перевода; `run_shortcut` проводит один вызов от шорткея до запроса.
- Готовое выделение передаётся побайтно как есть, включая пробелы и переносы. Повторный жест после первого запроса игнорируется; Esc и смена приложения сбрасывают ожидание без запроса; парольное поле блокирует вызов; ручной текст хранится до явной команды.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make test` — 63 теста, в том числе 7 тестов состояний переводчика:
  - готовое выделение уходит ровно выбранной строкой;
  - пустой диапазон даёт `AwaitSelection`, затем ровно один запрос;
  - Esc и смена контекста не дают запросов;
  - парольное поле возвращает `Blocked` без запросов;
  - неподдерживаемый источник требует `confirm_manual`, ручной текст сам запрос не отправляет;
  - потерянный контекст блокируется.
- `make lint` — Clippy без предупреждений, `make fmt` — без изменений.
