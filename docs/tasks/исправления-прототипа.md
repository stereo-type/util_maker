# Исправить установку, паузу, автозапуск и журнал прототипа

**Статус** — 👁️ На ревью

**Основание** — замечания пользователя по [первому прототипу](первый-прототип.md): установка поверх работающей версии, зависание после паузы, отсутствие автозапуска и журнала рядом с приложением.

## Критерии приёмки

- [ ] Повторная установка поверх запущенной версии не требует ручного удаления: мастер останавливает приложение, удаляет прежнюю установку и ставит новую.
- [ ] В настройках есть автозапуск при входе в Windows; состояние сохраняется и снимается повторно.
- [ ] Пауза освобождает сочетание, меню трея и окно настроек не зависают, «Выход» завершает приложение.
- [ ] Тип сборки задаётся через `UTIL_MAKER_BUILD`, журнал пишется в `<папка установки>\logs` и содержит события запуска, сочетания, вызова и сбоя.
- [ ] В трее видно состояние: «работает», «на паузе» или «сочетание недоступно» — иконкой и подсказкой.
- [ ] Окно настроек, вызванное из трея, поднимается поверх других окон.
- [ ] «Перерегистрировать сочетание» не снимает паузу: для возврата используется пункт паузы.

## Что сделано

- NSIS-установщик перед копированием файлов завершает `util-maker-desktop.exe` и `control-module.exe`, при другой прошлой установке запускает её деинсталлятор, сохраняет включённый автозапуск и переписывает его на новый путь.
- `util-maker-platform::autostart` хранит значение `UtilMaker` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; в настройках появился переключатель «Автозапуск при входе в Windows».
- Причина зависания паузы: поток слушателя постоянно удерживал мьютекс службы сочетаний, а обработчик меню ждал его. Приёмник событий теперь забирается из службы один раз, слушатель не держит мьютекс; пауза сначала запрещает обработку, затем освобождает `RegisterHotKey`.
- Журнал перенесён в `<папка установки>\logs\util-maker.log` (fallback — `%LOCALAPPDATA%`). `UTIL_MAKER_BUILD=dev` передаётся из Makefile в кросс-сборку, пишется в шапку журнала и показывается в настройках.
- Добавлены debug-записи для dev-сборки: запуск, WM_HOTKEY, пауза/регистрация, вызов действия, stderr модуля.
- Иконка трея отражает состояние: синяя — работает, жёлтая с паузой — пауза, красная — сочетание недоступно; подсказка дублирует состояние текстом.
- Окно настроек при вызове из трея поднимается через Win32 `SetForegroundWindow`/`BringWindowToTop`.
- «Перерегистрировать сочетание» на паузе только сообщает «на паузе» и не меняет состояние; снять паузу можно соответствующим пунктом меню.

## Проверка

Linux, контейнер `util-maker-dev:local`:

- `make test` — 38 тестов пройдено.
- `make lint` — Clippy без предупреждений, `make fmt` — без изменений.
- `make version` — версия `0.2.0`, тип сборки `dev`; `make check-version` подтверждает совпадение `Cargo.toml` и `tauri.conf.json`.
- `make build-windows` — установщик `dist/UtilMaker-Setup-0.4.0-dev.exe`, тип сборки в имени файла, без предупреждений.

Windows (ожидает проверки пользователем):

1. Запустить установщик поверх работающего прототипа. **Ожидаемо:** файл не заблокирован, прежняя версия закрыта и заменена, ручное удаление не требуется.
2. Открыть настройки → «Запуск»: включить автозапуск, перезайти в систему или проверить `HKCU\...\Run`, затем выключить.
3. Нажать «Пауза / возобновить сочетание»: меню и настройки отвечают, иконка трея становится жёлтой, сочетание не срабатывает; возобновление возвращает синюю иконку и сочетание. «Выход» закрывает приложение.
4. На паузе выбрать «Перерегистрировать сочетание»: состояние остаётся «на паузе», сочетание не включается.
5. Проверить `<папка установки>\logs\util-maker.log`: шапка `version=0.4.0 build=dev`, записи о сочетании и вызове; путь журнала виден в настройках.
6. Вызвать настройки из трея при открытом другом окне: окно Util Maker должно оказаться сверху.
