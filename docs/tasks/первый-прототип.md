# Подготовить первый прототип для локальной проверки на Windows

**Статус** — На ревью

Основание — разделы 2, 9 и 10 [общего ТЗ](../ТЗ.md). Начать с `make dev-setup`. Реализовать минимальную цепочку от события в трее или глобального шорткея до вызова контрольного модуля в отдельном процессе. Добавить локальную Docker-сборку под `x86_64-pc-windows-msvc` с cargo-xwin, LLVM/LLD и NSIS.

## Критерии приёмки

- [x] На Ubuntu тест переносимого ядра вызывает контрольный handler через IPC без рабочего стола.
- [x] Пользователь после получения ревизии запускает `make build-windows` локально. Цель выводит путь к полученному установщику в `dist/`.
- [ ] Пользователь устанавливает прототип на Windows 11, открывает и закрывает настройки, вызывает контрольный модуль шорткеем и видит результат. В задаче записаны ревизия, результат ручной проверки и первые замеры по разделу 8 ТЗ.

**Ревизия для проверки** — тег `prototype-0.1.0` в ветке `master` (хеш HEAD указан в сообщении о передаче).

## Что реализовано

- `crates/sdk` — манифест `.umpkg` (обязательные поля, проверка ID, версии, диапазона `hostApi`, безопасных относительных путей), сообщения JSON-RPC 2.0 контракта v1 и цикл stdio для процесса модуля.
- `crates/core` — переносимое ядро без Tauri, Win32 и графической сессии: реестр модулей и действий, запуск модуля отдельным процессом, рукопожатие за 3 с, вызов действия, предел сообщения 1 МиБ, таймауты, завершение процесса в любом исходе.
- `crates/control-module` — контрольный модуль с действием `ping`; отвечает из отдельного процесса и не обращается к рабочему столу.
- `apps/desktop` — хост на Tauri 2: иконка и меню трея, глобальное сочетание `Ctrl+Shift+U`, окно настроек по запросу, компактное окно результата, повторный запуск открывает существующий экземпляр, «Выход» завершает дочерние процессы. Окно настроек прототипа — статическая страница без сборки frontend; полноценный интерфейс относится к задаче блока настроек.
- `docker/windows` + `installer/` — отдельный Docker-stage с Rust, LLVM/LLD, cargo-xwin и NSIS; цель `make build-windows` собирает хост и модуль под Windows x64 и упаковывает установщик для текущего пользователя.
- [Инструкция по установке и замерам](../windows-прототип.md), `scripts/measure-windows.ps1` для Private Working Set, CPU и p95 по журналу.

## Проверка

### Linux (выполнено агентом)

- `make dev-setup` — `Linux development environment ready`: rustc/cargo 1.100.0, clippy 0.1.100, rustfmt 1.11.0, node 24.22.3, npm 11.19.1, tsc 5.9.3, tauri-cli 2.12.4, webkit2gtk-4.1 2.50.6, libayatana-appindicator3 0.5.90, librsvg 2.54.7, openssl 3.0.22.
- `make test` — 11 тестов пройдено: 6 в SDK (манифест и протокол), 4 интеграционных теста ядра с настоящим процессом `control-module` (initialize, invoke `ping`, ошибка неизвестного действия, маршрутизация через реестр), 1 тест формата журнала. Тест IPC не требует рабочего стола и дисплея.
- `make lint` — Clippy по всему workspace без предупреждений при `-D warnings`.
- `make fmt` — `cargo fmt --check` без изменений.
- `make build-windows` — образ `util-maker-windows:local`, кросс-сборка `x86_64-pc-windows-msvc`, NSIS собрал `dist/UtilMaker-Setup-0.1.0.exe` (1,9 МиБ; SHA-256 печатается целью и зависит от пути сборки). Сборка повторена из чистого архива тега `git archive prototype-0.1.0` — установщик собирается без локальных кешей. Хост — `PE32+ GUI x86-64`, модуль — `PE32+ console x86-64`, установщик — NSIS self-extracting. Цель печатает путь к установщику.
- Сборка проходит без предупреждений: обёртка `docker/windows/clang-cl` разбирает абсолютные Unix-пути в режиме CL, а `LNK4099` для CRT без PDB подавлен через `/IGNORE:4099` в `build.rs`.

### Windows (ручная проверка)

- Пользователь установил прототип на Windows 11 x64 и подтвердил работу: настройки открываются и закрываются, приложение остаётся в трее, `Ctrl+Shift+U` вызывает контрольный модуль, результат виден. Проверка выполнена до правки предупреждений сборки; код приложения в этой правке не менялся.
- Замечание к сборке из `dist/error.log` разобрано: журнал содержал не ошибку, а предупреждения `clang-cl` об абсолютных путях и `LNK4099` о PDB в CRT. Оба устранены обёрткой `docker/windows/clang-cl` и флагом `/IGNORE:4099`; полная чистая сборка проходит с кодом 0 и без предупреждений.
- Осталось для закрытия задачи: замеры по разделу 8 ТЗ командой `scripts/measure-windows.ps1` (простой, 100 циклов, p95 по 50 холодным вызовам) вместе с моделью CPU, сборкой Windows 11, версией WebView2 и масштабом.

Сценарий и ожидаемые результаты — в [Проверке прототипа на Windows 11](../windows-прототип.md).
