# Чек-лист проверки задач на ревью

Ревизия **`ad094d6`**, версия **0.4.0**, установщик
`dist/UtilMaker-Setup-0.4.0-dev.exe`.

Каждая карточка закрывается после того, как отмечены её пункты и статус
переведён в ✅ **Выполнена**. Ниже — что именно проверять.

## 0. Общая автоматическая проверка

На Ubuntu из корня репозитория:

```sh
make check
```

Ожидается: версия `0.4.0` согласована, `cargo fmt --check` без изменений,
Clippy без предупреждений, **63 теста** пройдены. Это закрывает автоматическую
часть всех задач ниже.

```sh
make build-windows
```

Ожидается установщик `dist/UtilMaker-Setup-0.4.0-dev.exe` и отсутствие
предупреждений сборки.

## 1. ✅ Автоматические задачи (без отдельного окна в приложении)

Эти карточки можно закрыть сразу после `make check`: их критерии проверяются
тестами, пользовательского интерфейса у них пока нет.

- [ ] `make dev-run CMD="cargo test -p util-maker-packages"` — 7 тестов.
- [ ] Корректный пакет даёт preview без запуска модуля.
- [ ] Изменённая нагрузка, чужая подпись и несовместимый API отклоняются.

- [ ] Без аннотаций результат совпадает пиксель в пиксель.

- [ ] Esc, смена окна и парольное поле — ноль запросов.

### [Провайдеры Яндекса и Google](blocks/translation-providers-http.md)

- [ ] Для обоих API проверены endpoint, ключ, языки, формат и разбор ответа.
- [ ] Переключение профиля отправляет текст только выбранному сервису.
- [ ] 401, 429, таймаут и отмена дают разные исходы без второго запроса.

### [Конфликт в редакторе шорткея](blocks/settings-conflict.md)

## 2. Windows: установка, трей, пауза, журнал

Карточка: [Исправить установку, паузу, автозапуск и журнал](исправления-прототипа.md).

- [ ] Запустить `UtilMaker-Setup-0.4.0-dev.exe` **поверх работающей** старой версии.
      Ожидается: мастер сам закрывает приложение, ставит новую версию, ручное
      удаление и ошибка блокировки exe не нужны.
- [ ] Первый запуск открывает настройки; закрытие оставляет приложение в трее.
- [ ] Трей: синяя иконка — работает, жёлтая — пауза, красная — сочетание недоступно;
      подсказка соответствует состоянию.
- [ ] Меню трея: «Пауза / возобновить сочетание» работает; на паузе
      «Перерегистрировать сочетание» не снимает паузу. «Выход» закрывает приложение
      без оставшихся процессов.
- [ ] Настройки, вызванные из трея, поднимаются поверх других окон.
- [ ] «Запуск» → автозапуск: включить, проверить
      `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, выключить.
- [ ] Журнал: `<папка установки>\logs\util-maker.log`; в шапке
      `version=0.4.0 build=dev`; путь виден в настройках; записи о сочетании и вызове есть.

## 3. Windows: регистрация сочетания Win32

Карточка: [Зарегистрировать глобальное сочетание в Windows](blocks/windows-registration.md).

- [ ] Ввести в редакторе `Win+L` и `Alt+Tab`: видны названия функций Windows,
      сохранение запрещено.
- [ ] Запустить в отдельном PowerShell `scripts/hold-hotkey.ps1`.
- [ ] Запустить прототип или нажать «Изменить сочетание» на `Ctrl+Shift+U`:
      статус «занято другой программой» / ошибка занятия.
- [ ] Нажать Enter в скрипте, повторить изменение на `Ctrl+Shift+U` — сочетание
      регистрируется и работает.
- [ ] Удерживать `Ctrl+Shift+U`: окно результата появляется один раз, без автоповтора.
- [ ] Пауза освобождает регистрацию, возобновление возвращает.

## 4. Windows: микроприложения и страницы

Карточка: [Показать установленные микроприложения и их настройки](микроприложения-страницы.md).

- [ ] «Микроприложения»: контрольный модуль установлен; «Скриншоты» и
      «Переводчик» явно помечены «не установлен».
- [ ] Открыть контрольный модуль: действие «Проверить связь» и сочетание
      `Ctrl+Shift+U`; «Вызвать» показывает результат.
- [ ] «Изменить сочетание»: модальное окно по центру, фон затемнён, ширина страницы
      не прыгает; сохранить `Ctrl+Shift+3`, перезапустить приложение — сочетание
      сохранилось.
- [ ] Ввести `Win+L` или занятое сочетание — ошибка с причиной, прежнее сочетание
      продолжает работать.
- [ ] Переключатель микроприложения: отключить — сочетание не срабатывает; включить —
      снова работает.
- [ ] Автозапуск и журнал на месте; закрытие и «Выход» работают.

## Порядок закрытия

1. Выполнить `make check` и `make build-windows`.
2. Закрыть автоматические задачи из раздела 1.
3. Пройти проверки раздела 2 (установка/трей/журнал).
4. Пройти проверку Win32-регистрации из раздела 3.
5. Пройти экран микроприложений из раздела 4.
6. Закрыть карточку `settings-conflict` как заменённую экраном микроприложений
   либо оставить до появления реальных пакетов «Скриншоты»/«Переводчик».

После проверки сообщите, какие пункты не прошли — карточки вернутся в работу.
