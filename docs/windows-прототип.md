# Проверка прототипа на Windows 11 x64

Этот документ описывает ручную приёмку задачи
[«Подготовить первый прототип для локальной проверки на Windows»](tasks/первый-прототип.md).
Автоматические проверки выполняются в Linux, установка и работа с треем — на
Windows 11 x64 в обычной интерактивной сессии без административных прав.

## Что входит в прототип

- нативный хост на Rust + Tauri 2: иконка и меню трея, одно глобальное
  сочетание `Ctrl+Shift+U`, окно настроек по запросу, компактное окно результата;
- переносимое ядро `util-maker-core`: манифест, реестр действий, запуск процесса
  модуля и JSON-RPC 2.0 по stdin/stdout с таймаутами;
- контрольный модуль `control-module` в отдельном процессе: рукопожатие
  `initialize` и действие `ping`;
- NSIS-установщик для текущего пользователя.

Штатные модули «Скриншоты» и «Переводчик», менеджер пакетов и полноценные
настройки в этот прототип не входят. Окно настроек — временная статическая
страница без сборки frontend: она нужна только чтобы открыть и закрыть окно и
увидеть результат вызова.

## Сборка установщика

На Linux с Docker (например, в WSL Ubuntu) из корня репозитория:

```sh
make build-windows
```

Цель собирает отдельный образ `docker/windows` с Rust, LLVM/LLD, cargo-xwin и
NSIS, затем кросс-собирает `util-maker-desktop.exe` и `control-module.exe` под
`x86_64-pc-windows-msvc` и упаковывает установщик. Первый запуск скачивает
зависимости Cargo и CRT/SDK Microsoft, поэтому занимает больше времени.

Результат: `dist/UtilMaker-Setup-<версия>-<тип>.exe`, например `UtilMaker-Setup-0.2.0-dev.exe`. Цель печатает полный путь,
размер и SHA-256. Каталоги сборки и кеши лежат в `.cache/windows-build/`, в
репозиторий не попадают.

## Установка и проверка

1. Скопируйте `dist/UtilMaker-Setup-<версия>-<тип>.exe` на Windows 11 x64 и запустите.
   Административные права не требуются: установка идёт в
   `%LOCALAPPDATA%\Util Maker`. Установщик прототипа не подписан, поэтому
   SmartScreen может показать предупреждение: «Подробнее» → «Выполнить всё равно».
   Повторная установка выполняется поверх работающей версии: мастер сам
   останавливает приложение, удаляет прежнюю установку и ставит новую.
   Если выбран другой каталог, старый экземпляр удаляется автоматически.
2. На последней странице установщика оставьте галочку «Запустить Util Maker».
   **Ожидаемо:** при первом запуске открывается окно настроек с контрольным
   модулем, версией, действием «Проверить связь» и сочетанием `Ctrl+Shift+U`.
3. Нажмите «Проверить связь» в настройках. **Ожидаемо:** появится сообщение
   «Контрольный модуль на связи. PID …», внизу — время ядра и от нажатия.
4. Закройте настройки крестиком. **Ожидаемо:** окно исчезает, приложение
   остаётся в трее; повторный клик по ярлыку открывает настройки того же
   экземпляра, второй экземпляр не появляется.
5. Переключитесь в Блокнот или браузер и нажмите `Ctrl+Shift+U`.
   **Ожидаемо:** появляется компактное окно результата с сообщением модуля и
   временем вызова; Esc закрывает окно. Сочетание срабатывает один раз, в том
   числе при удержании клавиш.
6. Откройте меню трея правой кнопкой: «Настройки», «Проверить связь», «Выход».
   Пункт «Проверить связь» даёт тот же результат, что и сочетание.
7. Нажмите «Выход». **Ожидаемо:** иконка трея исчезает, в Диспетчере задач не
   остаётся `util-maker-desktop.exe` и `control-module.exe`.
8. Удалите прототип через «Параметры → Приложения». **Ожидаемо:** ярлыки и
   каталог установки удаляются; журнал и состояние пользователя остаются.

Если установщик не собирается или окно результата не появляется, приложите к
задаче вывод `make build-windows`, версию Windows 11 и строки журнала из
`<папка установки>\logs\util-maker.log` (точный путь виден в настройках;
если каталог установки недоступен для записи — `%LOCALAPPDATA%\Util Maker\logs`).

## Автозапуск и журнал

- В настройках блок «Запуск» включает автозапуск при входе в Windows. Значение
  хранится в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Журнал лежит в `<папка установки>\logs\util-maker.log`; точный путь показан
  в настройках. Для dev-сборки в шапке указано `build=dev`, пишутся события
  запуска, сочетания, вызова и stderr модуля.

## Первые замеры по разделу 8 ТЗ

Замеры выполняются на release-сборке из установщика, в обычной сессии, при
одинаковом профиле питания. Запишите модель CPU, версию Windows 11 и WebView2,
масштаб и разрешение основного монитора.

### Простой в трее

1. Закройте окна настроек и результата, подождите 60 секунд.
2. В PowerShell из корня репозитория запустите:

   ```powershell
   .\scripts\measure-windows.ps1 -Seconds 600
   ```

   Скрипт раз в секунду суммирует Private Working Set хоста и всех его
   потомков (процесс модуля, WebView2) и считает среднюю загрузку CPU по дельте
   времени этих процессов. Чужие экземпляры `msedgewebview2` не учитываются.
3. **Бюджет:** сумма Private Working Set ≤ 60 МиБ, средний CPU за 10 минут
   ≤ 0,2 % суммарной мощности. Если процессы WebView2 отсутствуют, это
   ожидаемо: настройки закрыты, WebView уничтожен.

### Проверка регистрации сочетания

1. В отдельном PowerShell запустите `scripts/hold-hotkey.ps1` — он займёт
   `Ctrl+Shift+U`. Запустите прототип: в настройках и подсказке трея будет
   «занято другой программой», сочетание не сработает.
2. Нажмите Enter в скрипте (сочетание освободится) и выберите в меню трея
   «Перерегистрировать сочетание». Статус должен стать «зарегистрировано».
3. Пункт «Пауза / возобновить сочетание» освобождает и возвращает регистрацию.
4. Удерживайте `Ctrl+Shift+U`: окно результата появляется один раз, без
   автоповтора.

### Холодный вызов действия

1. Убедитесь, что настройки и окно результата закрыты, а процесс
   `control-module.exe` отсутствует (модуль запускается по требованию).
2. 50 раз нажмите `Ctrl+Shift+U` и закройте окно результата клавишей Esc.
3. Соберите статистику из журнала:

   ```powershell
   .\scripts\measure-windows.ps1 -InvokeBenchmark
   ```

   Скрипт берёт строки `since_event_ms=` (от события сочетания до показа окна
   результата) и печатает минимум, медиану, p95 и максимум.
4. **Бюджет:** p95 ≤ 350 мс. Замер `since_event_ms` включает создание окна
   результата и потому является консервативной оценкой первого видимого кадра;
   время сетевого перевода в прототипе не измеряется — его нет.

### Возврат ресурсов

1. Выполните 100 циклов «вызов → Esc» и подождите 60 секунд.
2. Снова запустите `.\scripts\measure-windows.ps1 -Seconds 60`.
3. **Бюджет:** память возвращается в бюджет простоя, рост относительно первого
   замера ≤ 10 МиБ; после «Выход» дочерних процессов нет.
