# Как работать с задачами

| Где хранить | Что писать | Пример |
| --- | --- | --- |
| [ТЗ.md](ТЗ.md) | Общее ТЗ проекта. Определяет состав поставки, общие требования и сквозные сценарии приёмки. | Пользователь назначает глобальные шорткеи действиям разных микроприложений. |
| [blocks/](blocks/) | Отдельное ТЗ на каждый функциональный блок. Указывает раздел общего ТЗ, уточняет границы блока, его поведение, контракты и критерии приёмки. | `blocks/hotkeys.md` описывает регистрацию сочетаний и разрешение конфликтов. |
| [tasks/blocks/](tasks/blocks/) | Один Markdown-файл на одну задачу конкретного блока. В имени файла используется имя блока, внутри — ссылка на его ТЗ. | `tasks/blocks/hotkeys-переназначение.md` |
| [tasks/](tasks/) | Общие задачи проекта и работы, результат которых принимается сразу для нескольких блоков. Файлы лежат непосредственно в этой папке. | `tasks/проверить-установку-на-чистой-windows.md` |

## Как завести задачу

1. Найди требование в общем ТЗ или ТЗ блока. Если поведение ещё не определено, опиши его в соответствующем ТЗ. В задаче достаточно ссылки на документ и указания раздела.
2. Определи, где принимается результат. Например, перенос сочетания со «Скриншотов» на «Переводчик» относится к блоку шорткеев: решение о конфликте принимает ядро. Проверка полной поставки на чистой Windows относится к общим задачам. Если общая задача зависит от работ отдельных блоков, свяжи файлы относительными Markdown-ссылками.
3. Проверь, есть ли уже задача на этот результат. Для новой задачи создай файл с коротким именем, заголовком в форме действия и начальным статусом «К выполнению». Сформулируй наблюдаемый результат и условия, по которым его можно принять.

### Пример задачи блока

Содержимое файла `docs/tasks/blocks/hotkeys-переназначение.md` после появления ТЗ блока `docs/blocks/hotkeys.md`:

```markdown
# Передать занятое сочетание другому действию

**Статус** — К выполнению

**Основание** — раздел о внутреннем конфликте в [ТЗ блока шорткеев](../../blocks/hotkeys.md).

При назначении занятого сочетания пользователь видит текущее и новое действия
и выбирает, какому из них оставить сочетание.

## Критерии приёмки

- [ ] После «Отмена» сочетание вызывает прежнее действие.
- [ ] После «Переназначить» сочетание вызывает только новое действие.
- [ ] После перезапуска назначение сохраняется. Остальные привязки обоих действий работают.
```

Для общей задачи подходит тот же шаблон. Из файла в `docs/tasks/` ссылка на общее ТЗ имеет вид `[Общее ТЗ](../ТЗ.md)`. Зависимости указывай, когда без результата другой задачи нельзя выполнить работу или провести приёмку.

## Как вести и закрывать задачу

- **К выполнению** — результат и критерии записаны. При начале работы поменяй статус на **В работе**.
- **Заблокирована** — укажи конкретное препятствие и условие, при котором можно продолжить. Если препятствие связано с другой задачей, добавь ссылку на неё. После устранения верни статус **В работе**.
- **Выполнена** — проверь каждый критерий, отметь пройденные пункты и добавь в конец файла раздел «Проверка». Укажи, что запускалось или проверялось вручную и какой результат получен.

При изменении требований обнови соответствующее ТЗ и критерии затронутых задач. Завершённая задача остаётся на прежнем пути, чтобы ссылки на неё продолжали работать.
