# Техническое задание на разработку Util Maker

**Первая поставка** — desktop-приложение для Windows, два независимо устанавливаемых микроприложения «Скриншоты» и «Переводчик», комплект для подключения следующего микроприложения.

Требования по отдельным компонентам собраны в [карте функциональных блоков](blocks/README.md). Повторяемые команды оформляются целями корневого Makefile и выполняются через `make` по [правилам работы в проекте](Работа%20в%20проекте.md).

## 1. Назначение и границы

Util Maker работает в трее текущего пользователя. Человек назначает глобальное сочетание клавиш действию микроприложения и вызывает его во время работы в другой программе. Открывать главное окно для каждого действия не требуется.

| Что хочет сделать пользователь | Как выглядит успешный результат |
| --- | --- |
| Поделиться фрагментом экрана | Вызывает действие, выделяет область, при необходимости добавляет стрелку или рамку и вставляет готовое изображение из буфера обмена в другую программу. |
| Перевести слово или фразу | Вызывает перевод из активного приложения, указывает текст и видит перевод рядом с местом работы. При желании копирует результат. |
| Добавить новый инструмент | Устанавливает пакет, видит его действия в настройках, назначает клавиши. Обновляет пакет отдельно от Util Maker с сохранением назначений. |

Целевая конфигурация первой версии — Windows 11 x64, обычная интерактивная сессия, установка для одного пользователя. Это проектное допущение. Для будущих портов на Ubuntu и macOS требуется сохранить контракт пакета и отделить платформенные операции. Поставка и приёмка на этих ОС относятся к последующим версиям.

## 2. ADR-01. Резидентное ядро и запускаемые по требованию микроприложения

**Контекст.** Большую часть дня пользователь держит Util Maker в трее с закрытыми окнами. Для настроек нужен современный UI, для скриншота — быстрый первый кадр. Новая версия одного инструмента должна устанавливаться при работающем ядре.

| Вариант | Преимущество | Цена выбора |
| --- | --- | --- |
| **Rust для ядра, Tauri 2 и TypeScript для настроек, модули в отдельных процессах** | Трей и обработка системных событий живут в нативном процессе. Окно настроек с системным WebView можно создавать по запросу. У модулей собственный цикл выпуска. | Потребуются IPC-контракт, управление процессами и Windows-адаптеры. Холодный запуск модуля входит в замер отклика. |
| Electron и вспомогательные процессы | Единый TypeScript-стек для главного процесса и настроек, привычная разработка интерфейсов. | Постоянно работающая оболочка включает среду Node.js и компоненты Chromium. Для выбранного бюджета простоя это дополнительная стоимость. |
| Нативная оболочка на Win32 | Прямое управление окнами, захватом экрана и временем жизни ресурсов. | Для Ubuntu и macOS пришлось бы заменить также оболочку настроек и трея. |

**Выбор для оценки и прототипа** — первый вариант. В трее работает один экземпляр ядра на сессию пользователя. Настройки открываются в локальном WebView и уничтожаются при закрытии. Интерактивный экран модуля принадлежит его процессу и может быть нативным. Язык модуля свободен при соблюдении протокола. Отдельный процесс локализует падения, но запускается с правами пользователя. Источники по стеку: [архитектура Tauri](https://v2.tauri.app/concept/architecture/), [трей из Rust](https://v2.tauri.app/learn/system-tray/), [системные WebView](https://v2.tauri.app/reference/webview-versions/), [модель процессов Electron](https://www.electronjs.org/docs/latest/tutorial/process-model).

| Компонент | Ответственность |
| --- | --- |
| Ядро Util Maker | Реестр пакетов и действий, шорткеи, маршрутизация, настройки, запуск и остановка процессов. Список действий доступен из манифестов при остановленных модулях. |
| Платформенный адаптер | Трей, регистрация комбинаций, активное окно, получение выделения, снимок экрана, буфер обмена, хранилище секретов и сведения о мониторах. Наружу возвращает данные контракта и типизированный результат о доступности операции. |
| Микроприложение | Объявляет действия и настройки, выполняет предметный сценарий, показывает собственный интерактивный UI. Получает платформенные возможности через SDK. Ядро не содержит условий по ID штатных модулей. |
| SDK и спецификация протокола | Описывают манифест, сообщения, разрешения, ошибки и жизненный цикл. SDK предоставляет адаптер между идентификатором действия и handler модуля. |

Системные дескрипторы окон, виртуальные коды клавиш и пути Windows остаются внутри Windows-реализации. Публичный контракт использует идентификаторы клавиш, контекст вызова с ограниченным сроком жизни, геометрию экрана с явно заданными единицами и перечень доступных операций. Для будущего порта доставляются новый платформенный адаптер, сборка модуля и при необходимости его overlay. На Ubuntu/Wayland доступность операции проверяется во время выполнения, на macOS предусмотрен результат «требуется системное разрешение». [Global Shortcuts в XDG Desktop Portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html).

## 3. Поведение платформы

1. **Запуск и выход.** Первый запуск открывает настройки с двумя штатными модулями и их действиями. Последующие запуски открывают трей. Повторный запуск показывает настройки существующего экземпляра. Автозапуск при входе включается пользователем. Закрытие настроек возвращает в трей. «Выход» отменяет активные операции, освобождает комбинации и завершает дочерние процессы.
2. **Трей.** Основной клик открывает настройки, контекстное меню содержит доступные действия, переключатель паузы шорткеев и «Выход». Действия из меню и с клавиатуры вызывают один handler. Для операций с чужим окном ядро запоминает последнее активное внешнее окно до открытия меню. При его закрытии или смене контекста операция предлагает выбрать источник заново.
3. **Назначения.** Каждому действию можно назначить ноль, одно или несколько сочетаний. У каждого модуля может быть несколько действий. Назначение хранится по паре `moduleId + actionId`. Пользователь может записать комбинацию с клавиатуры, удалить её и восстановить предложенную модулем. Без привязки действие остаётся доступным из меню.
4. **Регистрация.** Все привязки проходят единую проверку ядра по правилам ниже. Только ядро владеет глобальными регистрациями. Windows-адаптер получает события через `RegisterHotKey` и подавляет автоповтор при удержании клавиш. [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).
5. **Сбой и восстановление.** Падение, зависание или неверный ответ модуля завершают текущий вызов с понятной ошибкой. Пользователь может запустить действие повторно. После выхода из сна, разблокировки или перезапуска Explorer приложение восстанавливает доступность трея и проверяет привязки. Отключение модуля освобождает все его комбинации и сохраняет настройки для следующего включения.

### 3.1. Проверка шорткеев и разрешение конфликтов

При вводе сочетания поле сразу показывает результат предварительной проверки. При сохранении ядро повторяет проверку с учётом актуального состояния. Модификаторы нормализуются: разный порядок ввода `Ctrl+Shift` и `Shift+Ctrl` обозначает одно сочетание. В реестре есть все сохранённые назначения, включая отключённые модули. Одна комбинация имеет не более одного владельца.

| Ситуация | Что видит пользователь | Результат |
| --- | --- | --- |
| Сочетание принадлежит другому действию этого же или другого модуля | Предупреждение с комбинацией, именами прежнего и нового модулей и действий. Кнопки «Отмена» и «Переназначить». | «Отмена» сохраняет обе настройки. «Переназначить» одной операцией снимает только эту привязку с прежнего действия и передаёт её новому. Другие сочетания обоих действий продолжают работать. |
| Сочетание используется или зарезервировано Windows | Блокирующая ошибка с комбинацией и известной системной функцией. Например, «Win+L — блокировка компьютера». | Сохранение запрещено. Кнопка «Переназначить» недоступна. Прежняя рабочая комбинация и системная функция сохраняются. |
| Windows отклонила регистрацию, а владелец неизвестен | «Сочетание недоступно для глобального назначения. Выберите другое». Если код ошибки указывает на занятость, сообщение уточняет это. | Сохранение запрещено. Интерфейс не приписывает комбинацию конкретной программе без сведений об этом. |
| Свободная комбинация или повтор того же назначения | В поле виден текущий владелец либо статус доступности. | Свободная привязка сохраняется после успешной регистрации. Повторное сохранение того же назначения идемпотентно. |

**Как определить системный конфликт.** Windows-адаптер ведёт версионированный перечень системных комбинаций с русским названием функции, включая зарезервированные семейства. Например, Win+L, Alt+Tab и Ctrl+Alt+Del блокируются до попытки регистрации. Для резервов без известной функции показывается «Зарезервировано Windows». Поле позволяет указать клавиши по отдельности, поскольку некоторые системные сочетания ОС перехватывает ещё до окна настроек. Для остальных сочетаний ядро проверяет фактическую регистрацию в текущей сессии. Одна успешная проба недостаточна для известных системных клавиш: Windows допускает временный перехват отдельных стандартных сочетаний активным окном. [Сочетания Windows](https://support.microsoft.com/en-us/accessibility/windows/keyboard-shortcuts-in-windows), [особенности RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).

**Приоритет и восстановление.** Системный запрет имеет приоритет над внутренним переносом. Если ядро уже владеет регистрацией, оно меняет маршрутизацию без повторного захвата комбинации у самого себя. При ошибке сохранения или изменении владельца между предупреждением и подтверждением прежнее назначение сохраняется, результат проверки обновляется. Для отключённого модуля и на паузе свободная комбинация проверяется пробной регистрацией с немедленным освобождением. При следующем включении выполняется фактическая регистрация. После обновления ОС или появления внешнего конфликта проблемная привязка помечается как неактивная с причиной. Остальные продолжают работать.

Те же правила действуют при первом запуске, установке, обновлении, откате и восстановлении рекомендуемых сочетаний. Ни манифест, ни обновление не перезаписывают чужое назначение автоматически. Новое действие при конфликте остаётся доступным из меню.

## 4. Контракт микроприложения v1

**Пакет.** Файл `.umpkg` содержит манифест в UTF-8, иконку, исполняемый файл для заявленной пары ОС/архитектуры и подпись издателя. Один ID обозначает один модуль на протяжении его обновлений. В манифесте обязательны ID, издатель, отображаемое имя, версия пакета, версия схемы, диапазон поддерживаемых версий API хоста, точки входа по платформам, список действий и запрашиваемые возможности. У действия есть стабильный ID, название, описание и необязательные рекомендуемые сочетания. Ниже приведён пример содержимого манифеста.

```json
{
  "manifestVersion": 1,
  "id": "org.utilmaker.screenshot",
  "publisher": "org.utilmaker",
  "name": "Скриншоты",
  "version": "1.2.0",
  "hostApi": ">=1.0.0 <2.0.0",
  "entrypoints": { "windows-x64": "bin/screenshot.exe" },
  "icon": "assets/icon.png",
  "capabilities": ["screen.capture", "clipboard.writeImage"],
  "actions": [
    { "id": "capture-region", "name": "Снять область", "description": "Выделить и скопировать фрагмент экрана" }
  ]
}
```

**Вызов.** ОС сообщает ядру о сочетании → ядро находит действие и фиксирует исходный контекст до открытия собственных окон → запускает модуль → согласует версию API → передаёт действие → модуль вызывает handler и при необходимости обращается к возможностям хоста → возвращает результат. Трей принимает следующие события, пока модуль ждёт пользователя или сеть.

| Обмен | Минимальная семантика |
| --- | --- |
| Транспорт | Двунаправленный JSON-RPC 2.0 через stdin/stdout дочернего процесса. Один объект UTF-8 на строку, предел 1 МиБ на сообщение. Служебная диагностика идёт отдельно. Открывать сетевой порт для IPC не требуется. [Спецификация JSON-RPC](https://www.jsonrpc.org/specification). |
| `initialize`, `invoke` | Хост передаёт согласуемые версии и возможности, затем уникальный ID вызова, локальный `actionId` и ссылку на исходный контекст. Модуль подтверждает готовность за 3 с. Интерактивный выбор живёт до завершения пользователем или отмены. |
| Операции хоста | Встречный запрос привязан к модулю и активному вызову. Хост проверяет выданную возможность. Снимок передаётся ссылкой на временный буфер с размерами, форматом, шагом строки и временем жизни до конца вызова. Мегабайты пикселей не кодируются в JSON. |
| Завершение | Вызов даёт один конечный исход — успех, отмена или ошибка с машинным кодом. `cancel` и `shutdown` разрешены во время действия. После отмены хост игнорирует поздний результат, освобождает контекст и принудительно завершает процесс, если тот не вышел за 2 с. После закрытия последнего UI и завершения работы модуль выгружается. |
| Настройки | Модуль объявляет в пакете схему настроек с типами, значениями по умолчанию и секретными полями. Хост рисует форму на странице модуля. Для специфических проверок, например проверки API-ключа, форма вызывает команду модуля. Значение секрета после сохранения доступно только через хранилище ОС в контексте этого модуля. |

**Версии.** Версия пакета и версия API хоста меняются независимо. В рамках major-версии API новые поля и возможности добавляются совместимо, неизвестные необязательные поля игнорируются. Удаление обязательного метода или изменение смысла его параметров требует новой major-версии. Хост проверяет диапазон до запуска. Переименование действия в UI сохраняет привязку. При удалении ID после обновления хост показывает, какая привязка стала недоступной, и предлагает переназначить её. [Semantic Versioning](https://semver.org/lang/ru/).

### Установка и независимое обновление

1. Пользователь выбирает локальный пакет в разделе «Микроприложения». Приложение показывает имя, издателя, версию, возможности и совместимость. Этот же путь используется для обновлений. Два штатных пакета поставляются с установщиком и проходят общий механизм. Публичный каталог можно добавить позже.
2. До запуска проверяются подпись манифеста, подписанные хеши файлов полезной нагрузки, схема, целевая платформа, версия API и привязка ID к издателю. Распаковка ограничена каталогом новой версии. Абсолютные пути, выход из каталога и ссылки на внешние файлы отклоняются. Ключ штатного издателя поставляется с хостом. Для собственного модуля пользователь может добавить открытый ключ разработчика по отпечатку через настройки. Обновление существующего модуля должно подтверждаться ключом его издателя.
3. Новая версия распаковывается рядом с активной. После завершения текущего действия хост проверяет handshake новой версии и миграцию копии настроек. Переключение активной версии и её настроек атомарно. При несовместимости, сбое миграции или прерывании установки следующий запуск восстанавливает целостную версию. Обновление одного модуля не прерывает работу второго.
4. В интерфейсе доступны включение, отключение, удаление и откат к предыдущей установленной версии вместе с её настройками. Удаление освобождает сочетания и удаляет учётные данные модуля из хранилища. Установка, замена и откат пакета не требуют пересборки или перезапуска Util Maker.

Заявленные возможности ограничивают вызовы SDK. Нативный процесс сохраняет права текущего пользователя на прямые вызовы ОС. Поэтому v1 рассчитана на доверенных издателей. Поддержка произвольного недоверенного кода потребует отдельного решения об изоляции.

## 5. Микроприложение «Скриншоты»

**Действие «Снять область».** По шорткею экран фиксируется до показа интерфейса захвата. Пользователь протягивает прямоугольник мышью. На отпускании кнопки видит выделенный фрагмент и компактную панель. Enter или «Копировать» сразу помещает изображение в системный буфер и закрывает overlay. Esc в любой момент отменяет операцию, сохраняя прежнее содержимое буфера. Главные настройки в этом сценарии не открываются.

- В редакторе доступны стрелка, прямоугольная рамка и отмена последней аннотации. После копирования аннотации входят в изображение. Выделение, маркеры редактора и панель инструментов остаются за пределами результата.
- Снимок можно начать на любом подключённом мониторе, включая дополнительный монитор слева от основного. Если область пересекает границу мониторов, результат собирается по физическим координатам виртуального рабочего стола. Масштаб Windows не должен сдвигать рамку или изменять размеры фрагмента в пикселях.
- Повторный шорткей при открытом редакторе возвращает к текущему захвату. При занятом буфере пользователь может повторить копирование с сохранёнными аннотациями. Модуль работает офлайн, хранит кадр в памяти до завершения действия и отдаёт изображение в формате, который принимает стандартная вставка Windows.

## 6. Микроприложение «Переводчик»

**Действие «Перевести текст».** Есть два равноправных сценария. Если пользователь уже выделил слово, фразу или строку, шорткей переводит текущее выделение. Если выделения ещё нет, шорткей включает однократный режим выбора. Подсказка «Выделите текст» оставляет фокус в исходной программе. Пользователь выделяет текст обычным жестом мыши. Завершение жеста запускает перевод без повторного шорткея. Esc отменяет ожидание. При смене исходного приложения ожидание выбора прекращается.

На Windows адаптер запрашивает выделение у исходного элемента через UI Automation. Пустой диапазон у текстового курсора означает отсутствие выделения. События отслеживаются на время вызова. Для элемента без доступного текстового выделения модуль предлагает вставить или ввести текст вручную и нажать «Перевести». Такой резервный путь работает также для интерфейсов с нестандартным рендерингом. Известное парольное поле блокирует захват и сетевой запрос. Защищённый рабочий стол Windows, распознавание текста на картинках и чтение из приложения с недоступным уровнем привилегий находятся за границей автоматического сценария. [Получение выделения](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern-getselection), [свойство парольного поля](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationelement-get_currentispassword).

**Настройки самого переводчика.** На его странице пользователь выбирает активного провайдера, вводит или заменяет API-ключ, задаёт исходный и целевой языки. Для исходного доступно автоопределение. Целевой по умолчанию — русский. Для каждого провайдера сохраняется отдельный профиль. Видны имя сервиса, которому будет передан текст, статус настройки и кнопка «Проверить подключение». Проверка отправляет короткую фиксированную фразу. Если ключа нет, первое действие предлагает открыть нужный профиль. Переключение провайдера действует со следующего вызова без переустановки модуля, перезапуска ядра или изменения шорткея.

| Обязательный провайдер v1 | Контракт интеграции |
| --- | --- |
| Яндекс, Yandex Translate API v2 | Профиль принимает API-ключ сервисного аккаунта. Адаптер вызывает `translate/v2/translate`, передаёт ключ в заголовке `Authorization: Api-Key`, текст в `texts`, целевой язык в `targetLanguageCode`. Для этого способа авторизации `folderId` не передаётся. Результат берётся из `translations[].text`. [Метод Translate](https://aistudio.yandex.ru/ru/docs/translate/api-ref/Translation/translate), [авторизация Яндекса](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication). |
| Google Cloud Translation Basic v2 | Профиль принимает API-ключ проекта с включённым Cloud Translation API. Адаптер вызывает `language/translate/v2`, передаёт текст, целевой язык и формат plain text. Результат берётся из `data.translations[].translatedText` и отображается как текст. [Метод translate](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate), [поддержка ключей в Basic v2](https://docs.cloud.google.com/translate/docs/authentication). |

Обе интеграции входят в поставку. Внутри модуля каждый провайдер реализует один интерфейс с операциями проверки подключения и перевода с отменой. Профиль определяет параметры, авторизацию и разбор ошибок своего API. Отправляется только явно выбранный или введённый текст напрямую активному провайдеру по HTTPS. Окружающий документ, заголовок окна и буфер не отправляются. Ключи хранятся в системном хранилище текущего пользователя, в обычной конфигурации сохраняются ссылки на секреты. Изменение поставщика не переносит его ключ в другой профиль.

**Результат и сбои.** Компактное окно рядом с выделением показывает ход запроса, затем перевод и кнопку «Копировать». Если координаты недоступны, окно открывается на мониторе источника. Esc закрывает его. Исходный текст приложения и буфер сохраняются до явной команды копирования. Общий таймаут одного запроса — 10 с. Ошибки авторизации, исчерпания квоты, временного ограничения запросов, отсутствия сети и таймаута различимы в UI, если их различает API. Пользователь может повторить запрос. Автоматического повтора с передачей текста другому провайдеру нет. Отмена и новый вызов исключают показ устаревшего ответа.

## 7. Интерфейс и настройки

Интерфейс поставляется на русском языке. Основной экран — список установленных микроприложений. В строке модуля видны узнаваемая иконка, название, версия, состояние и переключатель. Статус «Нужна настройка» у переводчика ведёт прямо к выбору провайдера. На странице модуля рядом расположены список действий, текущие шорткеи и собственные параметры, ниже — обновление из файла, откат и удаление.

В разделе «Шорткеи» видны все комбинации, владельцы и причины недоступности. Работает поиск по действию, модулю и сочетанию. Раздел «Общие» содержит автозапуск, тему оформления и доступ к локальному журналу. Ошибка редактирования выводится рядом с соответствующим полем и содержит доступное следующее действие.

Иконки трея, модулей и команд образуют единый набор с различимыми силуэтами в светлой и тёмной теме. Стартовая тема следует за Windows. Для кнопок только с иконкой обязательны подсказка и доступное имя. Предусмотреть навигацию Tab, видимый фокус, подтверждение с клавиатуры и обозначение состояний текстом в дополнение к цвету. При масштабе 100%, 150% и 200% текст, поля и основные команды остаются читаемыми и доступны без перекрытий.

## 9. Приёмка и состав поставки

| Проверка | Критерий приёмки на Windows |
| --- | --- |
| 01. Чистая установка | На чистом профиле установлены хост и два отдельных пакета. Второй запуск использует тот же экземпляр. Оба действия доступны из трея. Закрытие настроек и выход дают разные результаты согласно разделу 3. |
| 02. Внутренний конфликт | Назначить свободное сочетание скриншоту, затем ввести его для перевода. Видны прежний и предлагаемый владельцы. После «Отмена» срабатывает скриншот. Проверить перенос также с отключённого модуля и между двумя действиями одного модуля. |
| 03. Системный и внешний конфликты | Указать Win+L и Alt+Tab через редактор сочетаний. Видны функции Windows, сохранить или принудительно переназначить невозможно. Другой процесс занимает контрольное сочетание. Приложение отказывает в назначении, прежнее работает. После освобождения внешним процессом контрольное сочетание можно назначить. |
| 04. Глобальный вызов | При фокусе в Блокноте и браузере шорткей вызывает нужное действие один раз, включая удержание клавиш. Пауза освобождает регистрацию, включение восстанавливает её либо указывает новый внешний конфликт. |
| 05. Скриншоты | Взять область известного размера на дополнительном мониторе и на стыке двух экранов с разным DPI. Добавить стрелку и рамку, отменить одну правку, скопировать и вставить в Paint. Проверить размер, положение аннотаций и отсутствие панели. При Esc буфер сохраняет прежнее значение. |
| 06. Захват текста | В Блокноте и на обычной текстовой странице Microsoft Edge проверить оба порядка действий — выделение до шорткея и после него. В запрос уходит ровно выбранный фрагмент. При неподдерживаемом элементе доступен ручной ввод, отмена ожидания и известное парольное поле дают ноль сетевых запросов на перевод. |
| 07. Два реальных провайдера | С действующими тестовыми ключами настроить оба профиля в переводчике. Перевести контрольную фразу через Яндекс, переключить на Google и повторить тем же шорткеем. В каждом случае ответ получен от выбранного сервиса и копируется. При неверном ключе, 429, отсутствии сети и отмене пользователь видит соответствующий исход. | 08. Независимость пакетов | Установить второй выпуск одного модуля при работающем хосте. Версия хоста, второй модуль и назначения продолжают работать. Проверить невалидную подпись, несовместимую major-версию, прерывание перед переключением и откат. После каждого случая доступна целостная рабочая версия. |
| 09. Изоляция сбоя | Принудительно завершить один модуль во время действия, затем воспроизвести зависание. Трей и второй модуль отвечают. Можно отменить зависший вызов, повторно вызвать действие и штатно выйти. После сна и перезапуска Explorer трей и допустимые привязки работают. |
