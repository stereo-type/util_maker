# Плагин «Пипетка цвета»

Переносимая часть микроприложения `org.utilmaker.color-picker`: выборка пикселя
из кадра BGRA8, проверка геометрии мониторов и форматирование значения.

- Крейт — `util-maker-color-picker`;
- процесс — `color-picker-module`, действие — `pick-color`; манифест и настройка формата — в [`manifest.json`](manifest.json);
- формат по умолчанию — `#RRGGBB`, второй вариант — `rgb(R, G, B)`;
- эталон и таблица координат — в [`reference/`](reference/README.md).

## Контракт выборки

`FrameView::new` принимает пиксели BGRA8, `width`, `height`, `stride` в байтах,
начало кадра и прямоугольники мониторов. `sample(x, y)` сначала проверяет, что
физическая точка принадлежит монитору, затем — что она входит в кадр. Только
после этого вычисляется смещение:

```text
offset = (y - origin.y) * stride + (x - origin.x) * 4
```

Три первых байта — B, G, R. Альфа игнорируется. Промежуток между мониторами
даёт `OutsideMonitors`, точка за пределами снимка — `OutsideFrame`, неполный
буфер или короткий `stride` отклоняются при создании `FrameView`.

`FrameView::from_frame_ref` использует `FrameRef` и его `geometry`. Ответ без
геометрии отклоняется как `GeometryUnavailable`: без мониторов нельзя отличить
пиксель от промежутка.

## Процесс и манифест

`manifest.json` объявляет издателя `org.utilmaker`, возможности `screen.capture`,
`clipboard.write`, `settings.read`, действие `pick-color` и настройку
«Формат цвета» с вариантами `hex` (по умолчанию) и `rgb`.

`color-picker-module` читает формат через `settings.read`, запрашивает один
`frame.capture`, читает пиксели из локальной копии хоста (`pixelPath`,
`FrameRef::read_pixels`) и сразу вызывает `frame.release`. Дальше процесс
работает по собственной копии кадра: проверяет точку по геометрии мониторов,
форматирует значение и пишет строку через `buffer.copy`. Полноразмерные пиксели
не попадают ни в JSON, ни в журнал.

Без точки выбора (`params.point`) действие возвращает исход
`awaiting-selection` с размерами кадра: интерактивное окно показывает хост.
Ошибка `2002` осталась только для честных отказов SDK — хост не отдал файл
пикселей или геометрию мониторов.

## Окно выбора

Процесс модуля живёт в пределах одного вызова и не создаёт окон, поэтому
замороженный кадр, лупу и копирование в интерактивном режиме показывает хост —
так же, как overlay «Скриншотов». Окно `apps/desktop/ui/picker.html` получает
кадр PNG data URL, рисует его без сглаживания и ведёт выбор через команды
`get_picker_geometry`, `get_picker_frame`, `picker_set_point`, `picker_arrow`,
`picker_copy` и `picker_cancel`. Состояние выбора — `PickerSession` из этого
крейта, поэтому выборка, окно лупы, шаг стрелками, проверка смены геометрии и
семантика копирования не дублируются в JavaScript.

- Кадр снимается один раз до появления окна; движение мыши и стрелки читают
  только копию в памяти.
- Лупа показывает 15 физических пикселей с увеличением ×12 без сглаживания,
  у края кадра окно лупы смещается, а выбранная точка остаётся на месте.
- Клик или Enter копирует ровно показанную строку и закрывает окно. Занятый
  буфер сохраняет точку и значение, окно показывает «Повторить копирование».
  Esc закрывает выбор и не меняет буфер.
- После смены конфигурации дисплеев копирование блокируется: точка могла бы
  указывать на другой пиксель.
- Повторный вызов действия возвращает в открытое окно, новый снимок не
  делается.
- Кадр освобождается при успешном копировании и по Esc. Окно, закрытое без
  команды (Alt+F4), освобождает кадр при следующем вызове пипетки или выходе
  хоста.

## Выбор и лупа

`picker.rs` содержит переносимое состояние поверх `FrameData`:

- `Picker::start` получает кадр один раз, освобождает `FrameLease` и открывает
  `PickerSession`;
- `PickerSession::set_point` и `move_arrow` читают только копию кадра;
- `Loupe::for_point` строит окно без сглаживания, сдвигает его у края и
  возвращает координаты перекрестия;
- `PickerSession::copy` пишет ровно показанную строку через `ClipboardSink`,
  сохраняет точку при занятом буфере и запрещает копирование после смены
  геометрии;
- `PickerSession::escape` не меняет буфер, `Picker::finish` освобождает кадр;
- `FrameData::rgba_rows` отдаёт кадр в RGBA без отступа строки для окна выбора.

## Проверка

```sh
make color-picker-check
make test
```

`make color-picker-check` проверяет переносимую выборку, лупу, копирование и
границу процесса. `make test` дополнительно запускает IPC-тест
`color-picker-module`.

Тесты покрывают отрицательное начало кадра, `stride` с отступом, соседние
пиксели, чёрный и белый, альфу, промежуток между мониторами, точку вне кадра,
неполный буфер, отсутствие геометрии и эталон из `reference/sample.json`. Для
процесса проверены чтение кадра 1024×1024 с отступом строки, ожидание точки,
копирование в выбранном формате и отказы без геометрии, пикселей и вне монитора.

## Поставка

`make color-picker-package` собирает release-процесс, экспортирует подписанный
`.umpkg` и проверяет архив тем же верификатором, что и установка. Цель также
строит следующий patch-пакет и имитирует обновление профиля: активная версия
меняется, а файлы `module-settings` и `shortcuts.json` остаются байт-в-байт.

`make build-windows` добавляет `color-picker-module.exe` и подписанный
`org.utilmaker.color-picker-<версия>-windows-x64.umpkg` в установщик вместе с
открытым ключом издателя. Пакет устанавливается штатным `bootstrap`-механизмом
хоста при первом запуске.
