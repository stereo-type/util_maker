# Контрольный плагин

Минимальный плагин для сквозной проверки: отдельный процесс, рукопожатие и
действие `ping`.

- ID — `org.utilmaker.control`
- Действие — `ping` («Проверить связь»)
- Точки входа — `control-module.exe` для `windows-x64` и `control-module` для
  `linux-x64` (значения из [`manifest.json`](manifest.json))
- Возможности — нет

## Контракт ответа

Хост запускает процесс по требованию, передаёт `initialize`, затем `invoke` с
`callId`, `actionId` и источником вызова. На `ping` плагин возвращает текст для
пользователя и объект `data`:

| Поле | Значение |
| --- | --- |
| `callId` | Идентификатор текущего вызова |
| `source` | Источник вызова: `tray` или `hotkey` |
| `pid` | PID дочернего процесса |
| `moduleVersion` | Версия плагина из манифеста |
| `apiVersion` | Версия API хоста, подтверждённая при рукопожатии |
| `uptimeMs` | Время жизни процесса до ответа |

Неизвестное действие возвращает машинный код `ACTION_NOT_FOUND`. После ответа
хост завершает процесс; повторный вызов запускает новый процесс, поэтому
зависший или завершённый процесс не мешает следующему действию. Плагин не
обращается к рабочему столу и не содержит Win32-кода.

## Сборка

```sh
make build-windows
```

## Проверка на Linux

Из корня репозитория:

```sh
make test
```

Тесты `crates/core/tests/control_module_ipc.rs` запускают реальный процесс
плагина, проверяют рукопожатие, ответ на `ping`, неизвестное действие и
повторные вызовы. Для точечного запуска:

```sh
make dev-run CMD="cargo test -p util-maker-core --test control_module_ipc"
```

Манифест: [`manifest.json`](manifest.json).
